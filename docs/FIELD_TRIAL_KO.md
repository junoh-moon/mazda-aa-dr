# 한 번의 실차 기회를 위한 통합 시험 준비

**설치 중단 — 2026-10-02:** 아래에 기록된 `v0.3.10-shadow.1`·`.2`
ZIP은 LDS 반복 종료 결함 때문에 사용 중단했습니다. 새 AA 문맥 풀 소스도
차량용 ZIP으로 발행하지 않았습니다. 아래 절차는 준비·과거 기록이며 현재
설치나 주행 지시가 아닙니다. [현재 상태](STATUS_KO.md)와
[수정 후보 검증](../validation/AA_CONTEXT_POOL_2026-10-02.md)을 확인하십시오.

**2026-10-02 실제 첫 시도는 자료 수집 여부를 판정할 수 없었습니다.**
v0.3.9-shadow.1을 설치한 뒤 차량 점화 OFF/ON과 주행이 있었고, 후속
v0.3.9-shadow.2 회수는 성공했지만 trace·collector JSONL 파일은
없었습니다. CMU Linux 새 부팅과 당시 guard 선택 여부는 미확인입니다.
[빈 기록 분석](../validation/FIELD_V039_EMPTY_CAPTURE_2026-10-02.md)을 먼저
읽으십시오. 아래 이동 절차는 새로운 현장 기회를 별도로 정한 경우에만
적용하며, 그 전에는 주차 중 부팅·collector 근거를 확인해야 합니다.

**2026-10-01에 사용자가 v1.0 전 실차 설치·시험 기회를 한 번 허용했습니다.**
아래 통합 절차는 해당 기회를 위한 SHADOW 시험판용입니다. 키보드의 Shift 입력
제약을 반영한 숫자 메뉴와 저장 공간·계산 진단을 포함합니다.
차량 USB 포트는 하나이고 허브를 사용할 수 없으므로 설치·회수 USB와 AA 연결을
주차 중에 번갈아 연결합니다. AA 연결 중 셸이나 상태 명령을 요구하지 않습니다.
마지막 공개 파일 기록은 [사용 중단한 v0.3.10-shadow.2 설치 ZIP](https://github.com/junoh-moon/mazda-aa-dr/releases/tag/v0.3.10-shadow.2)의
`mazda-aa-dr-v0.3.10-shadow.2.zip`입니다. 해당 소스는
`be96c6de6619d8e9053a327fd16e9df718384ca4`, ZIP의 SHA-256은
`76d6049db04631352ee7b37cb5f4f0294ad9b36e123dc8ad05b062a1a59d4148`입니다.
[최종 ZIP·발행 검증](../validation/RELEASE_V0310_SHADOW2_2026-10-02.md)과
[이전 회수 핫픽스](../validation/TRIAL_EXPORT_HOTFIX_2026-10-02.md)를 구분하십시오.
이전 시험의 메뉴3이 `/proc/mounts` 오류로 실패했다면 USB 파일을 교체하고
기존 한 줄 뒤 `3`만 사용하십시오. 이미 제거했어도 남은 로그를 회수합니다.
재설치·재주행은 필요하지 않습니다. 이 회수는 실제로 성공했으나 archive에
기동·센서 기록이 없었습니다. 사용자는 차량 점화 OFF/ON과 무선 AA 동글·S25를
이용한 주행을 확인했습니다. [빈 기록 조사](../validation/EMPTY_CAPTURE_2026-10-02.md)에

허용된 한 번의 시험은 이미 사용했으며, 아래 절차를 새 주행 요청으로 해석하지 않습니다.
**설치 `1 → 5 → 2 → 0`과 확대 회수는 공개 `v0.3.9-shadow.3`부터 가능하며, 아래 일곱

`startup_state`, `config_mode`, `runtime_disable_next_start`를 출력하지 않습니다. 두 버전의
파일과 판정표를 섞지 마십시오.
guard 진단·메뉴 `5` 재부팅·새 부팅 ID 대조·전체 설치 폴더 회수를 포함하며

성공을 판정하지 않습니다.
원본 AA 연결 등록의 서버 주소 GUID·client 고유 이름과 실제 raw 송신 연결의
일치를 기록합니다. 식별자가 없어도 원시 위치는 보존합니다. 이 연결 정보가
LDS의 물리 측정 시각이나 센서 자격을 대신하지는 않습니다.
GPS holdout 결과에 원본 위치의 호출·generation 식별자를 보존하여 회수 후
정확한 원본 행과 대조합니다. 연결 누락·중복은 별도 진단하며 기존 MODEL 비교를
지우거나 센서 자격으로 바꾸지 않습니다. 기준점·콜백 결합 수정과 원본 위치
아홉 필드 보존도 유지합니다. 실제 LDS는 서로 다른 callback에서 갱신된 필드를
함께 반환할 수 있으며 각 필드의 물리 생산 시각은 미검증입니다.
이번 판은 그 필드별 관측 할당 출처를 LDS 전용 제품에서 AA 기록까지
전달합니다. [원본 제품 실행](../validation/LDS_PRODUCT_RUNTIME_2026-10-02.md)의
응답 연결 성공도 물리 입력 자격이나 실제 ASSIST 적용을 뜻하지 않습니다.
v0.3.5의 첫 host 큐 막힘 원인은
미확정이며 이번 판의 별도 전체 검사 통과와 구분합니다.
[v1.0 완료 조건](V1_READINESS_KO.md)은 유지하며 live ASSIST는 계속 비활성입니다.

이전 v0.3.9-shadow.1의 host Python 421개와 C/C++, 고정 ARM 전체는 생략 없이 통과했습니다.
실제 DSO 8개 suite의 145개 사례와 순정 BusyBox 3개 검사, 공개 재다운로드의
해시·ZIP CRC·manifest·소스 고정을 대조하고 추가 도구를 제거했습니다.
선행 `f2ec7c2`에서 원본 라이브러리의 여덟 요청을 실행했습니다. 최종판의
다섯 제품 바이너리와 63개 빌드 입력이 이 선행 제품과 같음을 별도로
대조했으며, 최종 소스에서 원본 실행을 반복한 것은 아닙니다.
그 BusyBox fixture는 `/proc/mounts`를 일반 파일로 만들어 실제 회수 결함을
놓쳤습니다. 핫픽스는 링크 구조를 반영한 별도 결과를 위 문서에 기록합니다.
[v0.3.8](../validation/RELEASE_V038_2026-10-01.md)과
[v0.3.7](../validation/RELEASE_V037_2026-10-01.md) 검증은 각각의 이력으로 남깁니다.

허용된 실차 시험 기회는 한 번입니다. 가능한 구현·펌웨어 분석·오프라인
검증을 먼저 끝내고, 한 번의 준비된 기회에 기동 확인·원본 관측·센서 SHADOW·

나누는 것을 기본 절차로 삼지 않습니다.

압축 해제와 숫자 메뉴는 [USB 설치 안내](../packaging/USB_START_KO.md)를
따르십시오. 주차 중 기존에 작동하는 진단 셸에서 아래 한 줄과 숫자 `1`로
설치합니다. 실제 차량의 정상 기동·복구·센서와 폰 수용은 아직 검증하지 않았습니다.

## 방문 전에 우리가 완료할 것

1. 배포할 커밋을 고정하고 LDS 관측기·해시 도구를 포함한 여섯 ARM 바이너리·호스트/ARM 시험·패키징을 확인하십시오. 건너뛴 검사를 명시하고, 원본 펌웨어를 이용하는 설치 통합 시험의 생략을 완료로 처리하지 마십시오.
2. 이 통합 시험은 의도적으로 **SHADOW 기본값 묶음**으로 준비합니다. SHADOW 안에 순정 POSITION/send 관측도 있으므로 별도 OBSERVE 설치를 먼저 요구하지 않습니다. 아래 Shift 없는 숫자 메뉴의 `1`로 설치하십시오.
3. 현재 기록량은 AA 8MiB×3, collector 최대 1MiB×2다. 실제 센서 주기를 모르므로 몇 분 보관된다고 보장하지 않는다. 첫 기회는 짧고 정보가 다양한 경로로 구성하며, 장시간 켜 두거나 여러 번 재부팅하여 초기 로그를 덮어쓰지 않는다.
4. 회수 파일에서 확인할 질문과 각 근거를 아래 표로 고정한다. 추가 방문은 기존 자료로 답할 수 없는 구체적 질문이 있을 때만 요청한다.

개발용 일반 묶음 생성기의 기본값은 OBSERVE이고, 위 공개 ZIP은 SHADOW로
만들었습니다. 유지보수자는 다음처럼 별도 통합 후보를 만들 수 있습니다.
이 명령 자체는 검증이나 릴리즈 발행을 수행하지 않습니다.

```sh
sh packaging/make_bundle.sh --default-mode=SHADOW build/libmx5dr.so new-trial-bundle
```

`bundle-default-mode`는 OBSERVE/SHADOW만 허용한다. 설치기는 이를 shell 코드로 실행하지 않고 검증하며, 명시적인 `--mode` 옵션이 우선한다. ASSIST 자동 전환은 없다. 전체 manifest와 build-info의 기본 모드도 실제 묶음과 일치시켜야 한다.

## 별도로 정한 다음 시험의 설치·기동 확인

대상 차량은 **2019 MX-5 ND2 6MT**입니다. 아래는 다음 후보의 메뉴 `5`와
확대 회수까지 포함한 순서이며, 사용한 한 번의 시험을 자동으로 추가 승인하는
절차가 아닙니다. 발행된 고정 파일·해시를 확인하고 서로 다른 후보의 파일을
섞지 마십시오.

ACC, 엔진이 꺼진 ON, 실제 엔진이 가동 중인 ON을 구분하십시오.

| 전원 상태 | 엔진 | 시동 버튼 주황 표시등 | 이번 절차 |
| --- | --- | --- | --- |
| ACC | 꺼짐 | 켜짐 | 사용하지 않음 |
| ON, 엔진 꺼짐 | 꺼짐 | 켜짐 | 사용하지 않음 |
| ON, 실제 엔진 가동 | 가동 | 꺼짐 | 공회전을 유지 |

엔진이 꺼진 상태에서 페달을 밟지 않은 시동 버튼 조작은 OFF → ACC → ON 전환입니다.
[공식 전원 상태 설명](https://www.mazdausa.com/static/manuals/2019/mx5/contents/05010101.html)과
[공식 시동 설명](https://www.mazdausa.com/static/manuals/2019/mx5/contents/05010200.html)을
따르십시오. 엔진 가동 유지는 작업 중 전원 상태를 일정하게 두기 위한 이 프로젝트의
선택이며 Mazda의 패키지 승인이 아닙니다.

**배기가스가 쌓이지 않는 환기되는 장소에 주차하고, 주차브레이크를 채워
6MT 기어를 중립 N에 두십시오.** 브레이크와 클러치를 끝까지 밟고 시동 버튼을
눌러 엔진을 켜십시오. 시동이 완전히 걸릴 때까지 페달을 밟고, 타코미터가
0보다 높은 실제 공회전을 확인하십시오. **설치·CMU 재부팅·기동 확인 동안
중립·주차브레이크·엔진 가동을 유지하십시오.**

USB를 연결하고 기존 MP3 셸 진입 방식으로 셸을 여십시오. 다음 한 줄로
메뉴를 열고 최초 설치에만 **`1`과 Enter**를 누르십시오. USB가 sdb1 등으로
잡히면 경로의 해당 글자만 바꾸십시오. Shift 없이 입력할 수 있습니다.

```sh
sh /tmp/mnt/sda1/trial
```

설치가 끝나면 같은 메뉴에서 **`5`와 Enter**를 누르십시오. USB의 재부팅 요청
기록을 저장·동기화하고 필요한 USB 읽기 전용 복원을 마친 뒤 순정
`/sbin/reboot`를 옵션 없이 한 번 요청합니다. 요청 성공은 재부팅 완료 판정이
아닙니다. **시동 버튼을 누르지 말고 엔진과 USB 연결을 그대로 유지하십시오.**
차량 점화 OFF/ON으로 이 CMU 재부팅을 대신하지 마십시오.

CMU 화면이 돌아오면 같은 USB의 MP3로 셸을 다시 열어 같은 한 줄을 입력하고,
**`v0.3.10-shadow.2` 시험판에서는 이동 전에 계속 주차 중 메뉴 `2`로 다음 일곱 근거를 확인하십시오.**

- `reboot_check=new_boot_observed`: 요청 기록과 현재 부팅 ID가 다릅니다.
- `startup_state=guard_committed_after_new_boot`: 무장과 guard 표식 확정이 서로 다른
  Linux 부팅에 있었습니다.
- `one_boot=consumed_this_boot`: 현재 부팅에서 일회성 예약을 소비했습니다.
- `config_mode=SHADOW`: 현재 설정 파일이 SHADOW로 해석됩니다.
- `runtime_disable_next_start=absent`: 다음 AA 런타임 시작 차단 표식이 없습니다.
- `retained_bytes`가 0보다 큽니다.
- `collector_poll_recent=observed`: 현재 collector의 최근 poll이 기록됐습니다.

양성 `startup_state`는 `guard_config_binding=matched`도 요구하여 guard v3가
소비한 설정 해시와 현재 설정 파일이 같을 때만 출력합니다. 이 표식은 SM의
시험 경로 수신이나 AA 런타임 기동까지 증명하지 않습니다. 새 부팅의 guard
확정은 v3 형식의 표식에서만 인정합니다. 이전 v2 표식은 회수하되 새
시험의 성공 근거로 바꾸지 않습니다.
이 일곱 근거는 VBS tap 로딩·원시 센서 수신이나 MODEL 계산 성공을 증명하지
않습니다. 주차 중 AA 연결과 기존 터치 동작을 확인하고, 실제 기록은 회수 후
별도로 판정하십시오.

`2`는 기록을 시작하거나 설정을 바꾸지 않습니다. AA가 없어도 collector는
기동할 수 있으며, 이 단계에서 AA 후크·모든 센서 수신이나 `status_exit=0`을
요구하지 않습니다. 정차·AA 분리 때문에 전체 상태 종료 코드가 1이어도 위
개별 근거를 읽으십시오. 화면 복귀 직후 `startup_state=new_linux_boot_arm_unconsumed`이거나
collector poll만 아직 없으면 주차 상태에서 60초 기다린 뒤 `2`를 한 번 더
확인하십시오. 그래도 하나라도 없으면 이동하지 말고 `3`으로 가능한 자료를
회수하십시오. 메뉴 종료 후 같은 한 줄로 다시 들어가 `4`로 예약을 해제하고
원인을 분석하며, 임의로 설치·재부팅을 반복하지 마십시오.

확인되면 **`0`으로 메뉴를 종료하고 USB를 뺀 뒤 무선 AA 동글을 연결하십시오.**
기존 AA·터치를 주차 중 확인하고, 이 전환 중 시동을 껐다 켜거나 CMU를 다시
재부팅하지 마십시오. AA와 진단 USB를 동시에 사용하려고 하지 마십시오.
이 단계는 실제 센서·MODEL 결과나 폰의 ASSIST 수용 성공 판정이 아닙니다.

다음 상태 설명은 주차 중 `2`를 선택하거나 `3`으로 회수할 때 출력되는
**조회 시점의 현재 부팅 진단**입니다. 메뉴 종료는 `0`입니다. `2`는
모드·가드·프로세스를 바꾸지 않습니다. 현재 부팅 ID와 최근
5초의 runtime health, 8초의 collector poll, 30초의 수락된 원시 수신을
확인한다. MODEL 진단은 최근 2초만 표시한다. `observed`는 그 기간에
기록이 존재한다는 뜻이지 센서가 항법에 쓸 만큼 신선하다거나 운행이
승인됐다는 뜻이 아니다. 특히 후진 수신 여부와 후진 의미/유효 수명
검증은 별개다. 오래된 부팅의 로그나 boot가 덮어써진 자료는 현재
동작으로 인정하지 않는다. 조용한 기록 실패는 다음 health 시간 창이
지나기 전까지 감지하지 못할 수 있다.

종료 코드 0은 저장 공간과 **수락되어 기록된** 원시 수집의 최소 근거만 뜻합니다.
거부된 datagram만 세 종류 모였으면 수집 성공이 아니며, 센서별 거부
진단과 사유를 확인하고 원문을 보존합니다. 추가 출력의
`oem_position_recent`, `computation_active`, `model_diagnostic_recent`와
`model_solution`은 별도 진단이며, 수집 성공이나 ASSIST 자격으로 합치지
않습니다. `events_queued_total`에는 위치 입력도 포함되고 이전 MODEL
경계의 누적값이 남을 수 있으므로 실제 계산 완료 횟수가 아닙니다.
`calculation_attempt_recent`의 `drain_calls_total`은 worker가 MODEL의
`drain()`을 호출한 누적 횟수입니다. 빈 큐를 검사한 호출도 포함하므로 센서
처리 횟수나 유효 위치 생성 횟수가 아닙니다. `intervals_total`은 별도로
완료된 모델 적분 구간의 누적값입니다. `last_pipeline_reset_this_boot`는
현재 부팅에서 마지막으로 기록한 주 MODEL 초기화 사유·입력 경로를
표시합니다. `raw`의 `input_ns`는 수신 시각, `position`은 관측 시각,
`drain`은 처리 watermark이며 생산자 측정 시각으로 읽으면 안 됩니다.
초기화가 기록되면 앞선 MODEL 해는 현재 해로 표시되지 않습니다.
계산이나 위치 관측이 `unavailable`이어도 이미 수집한 원시 자료를
보존하고, 주차 상태에서 원인을 확인합니다. 상태 명령의 성공만으로
전체 주행 시험을 완료했다고 판단하지 않습니다.

`model_solution=not_observed`이면 현재 유효 MODEL 결과를 확인하지
못한 것입니다. AA 분리나 재부팅 뒤의 이 표시는 이전 시험에서 계산이 한 번도
실행되지 않았다는 뜻이 아닙니다. 함께 표시된 `pipeline`, `result`, `gps_anchor_gate`와 위치·센서
거부 사유를 확인하십시오. 정차 중 이동 기준점을 기다릴 수 있으므로 기동 확인과
유효 계산 결과를 구분합니다. 새 진단은 이전 릴리즈 ZIP에 소급 적용되지 않습니다.
최근 입력의 `pipeline=OK`와 과거 실패를 구분하십시오. 개별 사유·작업 종류와
원시 순번은 `shadow_pipeline_reset`에 남으며 PC 분석은 해당 실패를 숨기지 않습니다.

`retained_runtime_last_boot`는 보존된 trace의 마지막 boot 표식에 연결된 위치·
motion batch 행 수를 별도로 표시합니다. 같은 부팅의 runtime 재시작은 앞선 행을
지우지 않지만 다른 부팅·잘못된 boot 표식은 분리합니다. boot 표식이 회전으로
사라진 행의 부팅은 추정하지 않습니다. `retained_model_diagnostic_records`,
`model_valid_records`, `drain_attempt_records`는 각각 MODEL 진단 행,
`model_valid=true`인 행, 누적 `drain_calls_total`이 양수인 보존 행의 수입니다.
실제 drain 호출 수나 이번 행의 새 계산·적분 횟수를 뜻하지 않으며 정확도·완전성·
시험 성공을 판정하지 않습니다. `capture_end_record`도 해당 부팅의 행 존재만
표시하며 현재 부팅의 종료 확인을 대신하지 않습니다. 원문 전체는 회수 후 분석합니다.

메뉴 `2`는 수집 시작 명령이 아닙니다. 가드가 선택된 부팅에서는
**계산과 기록이 자동으로 실행되도록 설계**됐으며, 실제 시작은 위 주차 중
기동 근거로 확인하십시오.
운전 중에는 CMU를 조작하거나 USB를 바꾸지 마십시오. 가능한 범위에서 다음을 한 짧은 동선에 포함합니다.

- 하늘이 보이는 곳에서 잠시 정차: 자이로 영점 후보와 정차 센서 기록.
- 평소의 짧은 전진·후진 주차 동작: 6MT 후진 신호가 실제로 어떻게 오는지 확인.
- GPS가 보이는 이동·완만한 회전·정차: 휠 보정과 GPS 제외 비교를 자동 수집. GPS 제외 비교는 실제 터널 없이도 실행된다.
- 동선에 자연스럽게 포함된다면 짧은 지하 진입과 지상 복귀: 실제 mode=0/재획득 기록. 첫 자료를 얻기 위해 장터널을 별도로 갈 필요는 없다.

폰/앱 버전, 유·무선 연결 방식, 순정 SD 유무를 방문 전에 메모한다. 앱 화면 기록을 남긴다면 주차 중에 미리 준비하거나 동승자가 담당한다. SHADOW는 생성한 위치를 앱에 보내지 않으므로, 그 화면으로 **자체 ASSIST 수용**을 입증할 수는 없다.

**도착 후 주차한 다음 AA를 분리하고 같은 설치 USB를 연결하십시오.**
기존에 작동하는 방법으로 셸에 돌아온 뒤 위 한 줄로 메뉴를 열고 바로 **`3`과 Enter**로
종료·회수하십시오. 종료는 계산·관측 수집만 닫습니다. 기존 AA/touch/OEM 센서
콜백은 그대로 전달됩니다.
현재 메뉴를 실행한 USB로 자동 저장하며, 다른 USB를 임의로 선택하지 않습니다.
USB의 `trial-result.txt`에 종료 전 진단과 각 단계의 종료 코드를 저장합니다.
결과 파일과 archive·`.sha256`, `startup-result.txt`, `reboot-request.txt` 등
USB 결과를 함께 회수하십시오. 결과 텍스트는 다음 실행에 교체될 수 있으므로
PC에 먼저 보관하며 차량 저장소에는 추가하지 않습니다.

다음 후보의 archive는 `/data_persist/mx5-aa-dr` 전체를 포함합니다. 원시 로그뿐
아니라 guard 표식·설정·백업·설치 파일과 실제 autostart·두 SM 설정, 선택된
시험 설정 사본도 남깁니다. `/proc`·프로세스 정보·명령 출력·재부팅 요청 기록은
용량을 제한해 현재 회수 부팅의 진단으로 보관합니다. 이전 주행 당시의 상태와
혼동하지 마십시오. 진단 누락·잘림은 `diagnostic_partial=1`로 남기며 보존 원시
자료의 회수를 막지 않습니다. tar 실패의 `.partial`은 완성본이 아니므로 USB의
진단 폴더·체크섬과 함께 보존하십시오. 원본 파일과 차량 정보가 포함되므로
비공개로 보관하고 분석하십시오.

가능하면 같은 부팅에서 회수하십시오. 셸을 다시 열기 위해 정상 재부팅이
필요하면 재부팅 후 같은 USB에서 `3`을 실행하십시오. 다시 설치하거나 arm하지
마십시오. 현재 부팅에서 guard 소비 표식이 확인된 경우에만 다음 부팅의
기본 설정 복귀를 예상할 수 있습니다. 표식이 없으면 예약이 남아 있을 수
있습니다. 회수는 현재 부팅에
한정하지 않고 보존된 파일 전체를 복사합니다. 재부팅 전 마지막 행의 저장이나
이미 회전으로 없어진 자료까지 복원하는 기능은 아닙니다.

결과 파일의 `status_scope=current_boot`, `finish_scope=current_boot`와
`export_scope=all_retained_boots`를 구분하십시오. 재부팅 뒤의 현재 상태 및
종료 확인은 실패할 수 있어 메뉴 전체도 0이 아닌 종료 코드를 반환할 수 있습니다.
이전 완료 표식을 현재 부팅의 성공으로 인정하지 않습니다. 이때 `export_exit=0`이면
확보 가능한 자료의 회수는 성공한 것이며, `status_exit`·`finish_exit`를 이전 시험
전체의 실패로 해석하지 마십시오. 반대로 회수 성공만으로 기록의 완전성이나
시험 성공을 인정하지도 않습니다. archive의 `.sha256`을 확인하고 원문을 분석합니다.

종료 helper는 협조 요청 후 최대 15초 동안 현재 부팅의 runtime 완료 표식과 collector PID 표식의 제거를 확인합니다. collector의 정상 종료 기록까지 판정하는 명령은 아니며, 회수 후 PC 분석에서 `collector_stop`과 오류도 확인합니다. 실패해도 회수를 시도하고 `finish_exit`와 `export_exit`를 별도로 기록합니다. 실패를 성공으로 간주하거나 프로세스를 강제로 죽이지 않습니다. `capture_end`·마지막 health·현재 trace 파일의 fsync가 끝나기 전에 정상 runtime 완료 표식을 내지 않습니다. 과거 회전 파일 전체의 전원 단절 내구성을 보장하는 표식은 아닙니다. 완료 후 같은 부팅에서 수집을 다시 시작하지 않습니다.

로그를 확보한 뒤 기본 설정 복귀를 확인할 때도 **다시 arm하지 마십시오.**
주차 중 메뉴 `4`로 제거하십시오. 메뉴가 끝나면 같은 한 줄로 다시 들어가
`5`로 새 CMU Linux 부팅을 요청하고, 화면 복귀 후 다시 연 메뉴 `2`에서
부팅 ID 변경·`config_mode=OFF`·`guard_arm=absent`를 확인하십시오.
메뉴 `3`으로 같은 부팅의 수집을 끝낸 것만으로 이미
실행 중인 프로세스가 기본 설정으로 돌아왔다고 판단하지 않습니다. 제거가
실패했거나 arm 잔존을 확인할 수 없으면 복귀 확인을 완료했다고 기록하지
마십시오.
USB를 분리하고 AA를 연결해 기존 AA·터치를 주차 중 확인합니다. 차량 점화
OFF/ON을 새 부팅 근거로 대신하지 않으며, 별도 방문이나 재주행을 요구하지 않습니다.
완료 표식만으로 물리 복구·정확도·앱 수용이 검증되는 것은 아닙니다.

## 여전히 남는 한계

VBS가 먼저 시작하면 AA 수신기가 열리기 전 원본은 저장되지 않는다. 송신자는 OEM 경로를 막지 않도록 비차단으로 동작하며 잃은 값을 새 값처럼 재송신하지 않는다. 최초 수신 순번이 1보다 커도 이를 부팅 전체의 무손실 수집이라고 해석하지 않는다.

기록 한도가 지나면 오래된 파일이 회전한다. 이번 변경은 무제한 저장이나 일정 시간의 보관을 보장하지 않는다. 저장 오류가 나면 raw도 더 보존할 수 없다. 종료 시점의 제한된 drain 이후 들어오는 값도 시험 범위 밖이다.

## 저장 공간과 회수

설치는 새 바이너리, 남은 최대 로그 할당, 8MiB 여유분, 64KiB 쓰기 여유와
1MiB의 도구·설정·백업 임시 공간을 계산합니다. 이미 보관된 고정 로그는
재사용분으로 빼며 부족하면 기동 설정·백업을 만들기 전에 이유를 표시합니다.
제거에는 이 용량 검사를 적용하지 않습니다.

AA와 collector는 각 기록 전 남은 공간을 읽고 8MiB 여유분과 쓰기 여유를
유지할 수 없으면 해당 기록기를 중단합니다. `trace.storage.json`과
`collector.storage.json`은 각각 1KiB 미만의 마지막 중단 진단입니다.
기존 로그를 지워서 계속 쓰거나 같은 기록기가 자동 재개하지 않습니다.
새 프로세스가 수집을 재개해도 이전 중단 증거를 지우지 않습니다.
상태 도구는 현재 부팅의 과거 중단과 새 작업자의 활성 상태를 구분하고,
PC 분석은 중단 진단이 포함된 자료를 완전한 수집으로 판정하지 않습니다.

8MiB는 이 프로그램의 보수적인 기록 정책이며 OEM의 필수 여유량을 실측한
값은 아닙니다. 다른 프로세스의 동시 쓰기나 파일시스템 고장까지 막는 할당량
제한이 아닙니다. 중단 진단도 저장 자체가 실패하면 남기지 못할 수 있습니다.

센서·위치 로그는 총 26MiB 상한에서 회전하며 설치 파일·설정 백업·작은 진단은
별도입니다. 확대 archive와 진단 임시 파일은 실제 USB에 만들며, 차량 내부에
추가 누적하지 않습니다. PC에서 `.sha256`을 확인하십시오.
`export_logs.sh`는 해석된 `/data_persist` 내부 경로를 거부하여 차량 내부에
회수 archive를 반복 누적하는 실수를 막습니다. 회수·제거 후 원본 로그와
설정 백업은 남습니다. 공간 부족을 해결하려고 차량 전체 로그나 다른 패치
파일을 지우지 마십시오.

`finish_capture.sh`가 실패해도 남은 자료를 버리거나 성공으로 간주하지 않습니다.
숫자 메뉴의 `3`은 실패 출력도 보존하고 확보 가능한 파일부터 회수합니다.
가능하면 다음 부팅 전에 회수하되, 단일 USB 포트에서 셸 복귀를 위해 재부팅이
필요하면 위 절차대로 이전 부팅의 보존 파일을 회수하십시오. 현재 기회에서
불필요한 재설치·재무장을 반복하지 마십시오.

ASSIST에는 아직 생산자 시각/품질의 근거, 보정 검증, 정확한 요청 연계와 AA timestamp, 폰/앱 수용 확인이 필요하다. 실차 기회가 적다는 이유로 이를 가정해 활성화하지 않는다. 동시에 그 확인을 매번 별도 방문으로 나누는 것을 기본 계획으로 삼지도 않는다.

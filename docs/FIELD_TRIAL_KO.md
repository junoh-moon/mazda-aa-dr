# 한 번의 실차 기회를 위한 통합 시험 준비

**2026-10-01에 사용자가 v1.0 전 실차 설치·시험 기회를 한 번 허용했습니다.**
아래 통합 절차를 갱신하여 해당 기회에 필요한 후보를 준비합니다. 현재 공개된
ZIP에 이번 보완이 포함되어 있다고 간주하지 마십시오. 저장 공간 부족 대응과
실제 계산 진행 확인, 새 고정 커밋의 전체 검증·묶음 준비는 아직 진행 중입니다.
[v1.0 완료 조건](V1_READINESS_KO.md)은 유지하며 live ASSIST는 계속 비활성입니다.

허용된 실차 시험 기회는 한 번입니다. 가능한 구현·펌웨어 분석·오프라인
검증을 먼저 끝내고, 한 번의 준비된 기회에 기동 확인·원본 관측·센서 SHADOW·
로그 회수·다음 부팅 복귀 확인을 묶습니다. OBSERVE와 SHADOW를 별도 방문으로
나누는 것을 기본 절차로 삼지 않습니다.

현재 공개 묶음은 [v0.3.1-shadow.1](https://github.com/junoh-moon/mazda-aa-dr/releases/tag/v0.3.1-shadow.1)입니다.
고정 커밋·ZIP 해시·실행 범위는 [릴리즈 검증 기록](../validation/RELEASE_2026-09-30.md),
압축 해제와 `sh install.sh` 절차는 [USB 설치 안내](../packaging/USB_START_KO.md)를
따르십시오. 이 문서는 해당 SHADOW 시험 후보의 통합 절차입니다. 실제 차량의
정상 기동·복구·센서와 폰 수용은 아직 검증하지 않았습니다.

## 이번 변경이 막는 낭비

| 이전 문제 | 변경 |
| --- | --- |
| AA 후크/항법 초기화 실패 시 원본 센서 수신도 시작되지 않음 | SHADOW 원본 수집을 항법 계산의 성공과 분리 |
| AA 관측 큐에서 한 번 실패하면 이후 raw 수집도 중단 | 계산은 차단하고, 기록기가 정상인 동안 raw 진단 수집은 계속 |
| 늦거나 순번이 끊긴 입력을 일반 오류로 버려 원인/원본을 잃음 | 인증·디코딩된 거부 입력만 별도 `motion_rejected`로 보존. 항법 입력으로 쓰지 않음 |
| 수집이 시작되지 않은 사실을 귀가 후에 발견 | 주차 상태에서 현재 부팅의 로그·세 센서·health·collector를 확인 |
| 실행 중 로그 회수로 마지막 줄/파일 교체 문제가 생김 | 협조적 수집 종료와 저장 확인 후 회수. OEM 프로세스를 종료하지 않음 |

오류가 난 로그를 정상으로 바꾸는 기능은 아니다. 원본이 남아도 감사 오류·누락·거부가 있으면 PC 분석은 계속 불충분으로 판정한다. 특히 PR #16 재생기는 손상 구간 뒤의 기록을 자동으로 정상 세션으로 잘라 사용하지 않는다. 남긴 원본은 먼저 원인과 실제 센서 계약을 분석하는 자료다.

## 방문 전에 우리가 완료할 것

1. 배포할 커밋을 고정하고 해시 도구를 포함한 다섯 ARM 바이너리·호스트/ARM 시험·패키징을 확인하십시오. 건너뛴 검사를 명시하고, 원본 펌웨어를 이용하는 설치 통합 시험의 생략을 완료로 처리하지 마십시오.
2. 이 통합 시험은 의도적으로 **SHADOW 기본값 묶음**으로 준비한다. SHADOW 안에 순정 POSITION/send 관측도 있으므로 별도 OBSERVE 설치를 먼저 요구하지 않는다. 사용자 설치 명령은 `sh ./install.sh` 하나다.
3. 현재 기록량은 AA 8MiB×3, collector 최대 1MiB×2다. 실제 센서 주기를 모르므로 몇 분 보관된다고 보장하지 않는다. 첫 기회는 짧고 정보가 다양한 경로로 구성하며, 장시간 켜 두거나 여러 번 재부팅하여 초기 로그를 덮어쓰지 않는다.
4. 회수 파일에서 확인할 질문과 각 근거를 아래 표로 고정한다. 추가 방문은 기존 자료로 답할 수 없는 구체적 질문이 있을 때만 요청한다.

개발용 일반 묶음 생성기의 기본값은 OBSERVE이고, 위 공개 ZIP은 SHADOW로
만들었습니다. 유지보수자는 다음처럼 별도 통합 후보를 만들 수 있습니다.
이 명령 자체는 검증이나 릴리즈 발행을 수행하지 않습니다.

```sh
sh packaging/make_bundle.sh --default-mode=SHADOW build/libmx5dr.so new-trial-bundle
```

`bundle-default-mode`는 OBSERVE/SHADOW만 허용한다. 설치기는 이를 shell 코드로 실행하지 않고 검증하며, 명시적인 `--mode` 옵션이 우선한다. ASSIST 자동 전환은 없다. 전체 manifest와 build-info의 기본 모드도 실제 묶음과 일치시켜야 한다.

## 한 번의 시험 기회

아래 절차는 위에 고정한 공개 ZIP에 적용합니다. 이전 후보 `a319166` ZIP에는
수집 종료·상태 helper가 없으므로 이 절차와 혼용하지 마십시오.

**설치와 초기 확인은 주차 중에 한다.** 압축을 푼 디렉터리에서 `sh ./install.sh`를 실행하고 정상적인 다음 기동으로 들어간다. 기존 AA·터치가 정상인지 확인한다. 정상 동작을 확인할 수 없으면 주행으로 진행하지 않고 현재 자료부터 보존한다.

AA를 연결한 뒤 주차 상태에서 다음 명령 한 번으로 현재 수집 근거를 본다.

```sh
sh /data_persist/mx5-aa-dr/tools/trial_status.sh
```

이 명령은 모드·가드·프로세스를 바꾸지 않는다. 현재 부팅 ID와 최근 30초의 health/원본 수신/collector를 확인한다. `observed`는 그 기간에 기록이 존재한다는 뜻이지 센서가 항법에 쓸 만큼 신선하다거나 운행이 승인됐다는 뜻이 아니다. 특히 후진 수신 여부와 후진 의미/유효 수명 검증은 별개다. 오래된 부팅의 로그나 boot가 덮어써진 자료는 현재 동작으로 인정하지 않는다.

2026-10-01 이후의 새 소스는 OEM 위치 수신, 계산 활성과 실제 MODEL 입력 처리도
확인합니다. `model_solution=not_observed`이면 아직 유효 MODEL 결과를 확인하지
못한 것입니다. 함께 표시된 `pipeline`, `result`, `gps_anchor_gate`와 위치·센서
거부 사유를 확인하십시오. 정차 중 이동 기준점을 기다릴 수 있으므로 기동 확인과
유효 계산 결과를 구분합니다. 이 개선은 기존 공개 ZIP에 소급 적용되지 않습니다.

이후 **계산과 기록은 자동으로 실행**한다. 운전 중 CMU 조작은 없다. 가능한 범위에서 다음을 한 짧은 동선에 포함한다.

- 하늘이 보이는 곳에서 잠시 정차: 자이로 영점 후보와 정차 센서 기록.
- 평소의 짧은 전진·후진 주차 동작: 6MT 후진 신호가 실제로 어떻게 오는지 확인.
- GPS가 보이는 이동·완만한 회전·정차: 휠 보정과 GPS 제외 비교를 자동 수집. GPS 제외 비교는 실제 터널 없이도 실행된다.
- 동선에 자연스럽게 포함된다면 짧은 지하 진입과 지상 복귀: 실제 mode=0/재획득 기록. 첫 자료를 얻기 위해 장터널을 별도로 갈 필요는 없다.

폰/앱 버전, 유·무선 연결 방식, 순정 SD 유무를 방문 전에 메모한다. 앱 화면 기록을 남긴다면 주차 중에 미리 준비하거나 동승자가 담당한다. SHADOW는 생성한 위치를 앱에 보내지 않으므로, 그 화면으로 **자체 ASSIST 수용**을 입증할 수는 없다.

**도착 후 주차 중에 수집을 끝내고 즉시 회수한다.** 종료는 계산·관측 수집만 닫는다. 기존 AA/touch/OEM 센서 콜백은 그대로 전달된다.

```sh
sh /data_persist/mx5-aa-dr/tools/finish_capture.sh
sh /data_persist/mx5-aa-dr/tools/export_logs.sh /actual/mounted/usb
```

첫 명령은 협조 요청 후 최대 15초 동안 현재 부팅의 runtime 완료 표식과 collector PID 표식의 제거를 확인한다. collector의 정상 종료 기록까지 판정하는 명령은 아니며, 회수 후 PC 분석에서 `collector_stop`과 오류도 확인한다. 실패하면 성공으로 간주하거나 프로세스를 강제로 죽이지 않는다. 남아 있는 파일을 회수하고 실패 출력도 함께 보관한다. `capture_end`·마지막 health·현재 trace 파일의 fsync가 끝나기 전에 정상 runtime 완료 표식을 내지 않는다. 과거 회전 파일 전체의 전원 단절 내구성을 보장하는 표식은 아니다. 완료 후 같은 부팅에서 수집을 다시 시작하지 않는다.

로그를 확보한 뒤 **다시 arm하지 않고**, 같은 방문 중 가능한 정상 전원 주기로 baseline 복귀와 기존 AA·터치를 확인한다. 여러 부팅은 정상적인 기동 경계를 시험하기 위한 것이며 별도 차량 방문이나 재주행을 요구하는 것은 아니다. 완료 표식은 회복·정확도·앱 수용 증거를 대신하지 않는다.

## 회수한 자료로 답할 질문

| 질문 | 사용할 자료 | 이것만으로 확정하지 못하는 것 |
| --- | --- | --- |
| AA와 VBS 관측이 시작됐나 | 현재 boot/health/capture_active, 실제 motion 종류 | 미수신 원인이 모든 경우에 특정되는 것은 아님 |
| 휠·yaw·후진 주기/단절은 어떤가 | accepted motion과 별도 거부 원본, 수신 시각·사유 | 물리 측정 시각·하드웨어 품질 |
| 계산이 멈춘 이유는 무엇인가 | pipeline/holdout/audit, source/sequence/stale 등 거부 사유 | 누락된 물리 메시지 내용 |
| 보정이 계산 차이를 줄이나 | 동일 raw 재생과 완료된 같은 GPS 참조 구간 비교 | 전체 주행 정확도, 실패 구간 성능, GPS의 참값 |
| OEM LOCATION과 앱 화면은 어떤가 | 순정 POSITION/send, 같은 세션의 폰 관찰 | 미송신한 자체 DR 결과의 앱 수용 |
| 시험이 다음 부팅에 빠졌나 | 가드 기록과 실제 다음 기동 관찰 | 같은 실행 중 SM 내부 재시도까지의 회복 |

## 여전히 남는 한계

VBS가 먼저 시작하면 AA 수신기가 열리기 전 원본은 저장되지 않는다. 송신자는 OEM 경로를 막지 않도록 비차단으로 동작하며 잃은 값을 새 값처럼 재송신하지 않는다. 최초 수신 순번이 1보다 커도 이를 부팅 전체의 무손실 수집이라고 해석하지 않는다.

기록 한도가 지나면 오래된 파일이 회전한다. 이번 변경은 무제한 저장이나 일정 시간의 보관을 보장하지 않는다. 저장 오류가 나면 raw도 더 보존할 수 없다. 종료 시점의 제한된 drain 이후 들어오는 값도 시험 범위 밖이다.

ASSIST에는 아직 생산자 시각/품질의 근거, 보정 검증, 정확한 요청 연계와 AA timestamp, 폰/앱 수용 확인이 필요하다. 실차 기회가 적다는 이유로 이를 가정해 활성화하지 않는다. 동시에 그 확인을 매번 별도 방문으로 나누는 것을 기본 계획으로 삼지도 않는다.

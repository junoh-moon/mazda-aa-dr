# MODEL GPS 기준점 검사와 휠 거리 보정

NA 74.00.324A의 센서 SHADOW에서 GPS 기준점과 휠 거리 환산을 보강한다. 이전에는 수치 범위와 큰 위치 점프만 검사해 기준점을 만들었고, 휠 속도의 고정 환산값을 그대로 적분했다. 이제 GPS와 차량 입력이 명백히 어긋나면 기준점을 거부하고, 충분한 GPS 직진 구간에서 작은 거리 보정 후보를 계산한다.

이 문서는 해당 소스 변경의 계약이다. 배포된 `v0.2.0-observe.2`에는 포함되지 않는다. MODEL 계산이며 차량 보정 완료나 네이버 지도 수용을 뜻하지 않는다. 설치 기본값 OBSERVE, 원본 AA 송신, live ASSIST 차단은 유지한다.

## 좁힌 구현 범위

`Pipeline::init_model(..., auto_bias=true, gps_wheel=true)`로 기존 worker의 두 SHADOW 파이프라인에서 사용한다. 일반 API의 두 선택값은 기본 false이므로 고정 모델 비교를 유지한다. qualified 입력에는 적용하지 않는다.

작은 `GpsWheel` 객체가 기존 정렬 큐에서 입력을 받는다. 새 프로세스, 구독, 동적 할당, 영구 보정 파일이나 설정 체계를 추가하지 않는다. 맵매칭·일반 센서 융합 필터·장터널 한계 확장은 범위 밖이다. 기존 60초/1,500m DR 한계를 늘리지 않는다.

## GPS 기준점

아래 수치는 실차에서 확정한 허용오차가 아니라 MODEL 실험의 제한값이다.

| 검사 | 조건 |
| --- | --- |
| 기본 GPS | mode 1/2, 유효 좌표·UTC·heading, 이동 속도 1.8km/h 이상 |
| 휠·후진 신호 | 기준점 시각까지 수신한 값, age 최대 250ms 또는 코어 제한 중 작은 값 |
| 네 바퀴 일치 | 최대−최소 속도 ≤ max(0.3m/s, 평균 속도의 5%) |
| GPS와 휠 속도 | 차이 ≤ max(3m/s, GPS 속도의 30%); 휠에는 현재 적용 scale 사용 |
| 위치 쌍 | 1~2초 간격, 이동 거리 5m 이상; 빠른 callback은 쌍의 시작을 유지하되 큰 점프는 즉시 거부 |
| 이동 거리 | GPS 양 끝 속도의 평균×시간과의 차이 ≤ max(8m, 예상 거리의 40%) |
| 이동 방향 | 좌표 변화의 방향과 양 끝 GPS heading 차이 각각 35° 이하 |
| 시각 | UTC 역행·큰 점프·2초 초과 정체, callback 단절·역행 거부 |

GPS heading은 이동 방향이다. 후진일 때 몸체 방향으로 π를 더하는 기존 계약을 유지하며, 쌍 도중 후진 상태가 바뀌면 새 쌍을 요구한다. 휠 보정 학습은 전진에서만 한다.

명백한 거부는 기존 READY 기준점도 폐기하므로 이어지는 mode=0에서 재사용하지 않는다. 단순히 1초 쌍을 기다리는 정상 callback은 이전 정상 기준점을 유지한다. 실제 GPS 복귀 때는 기존 DR 위치와의 거리로 GPS를 거부하지 않는다. 따라서 DR 오차가 커졌다는 이유로 올바른 GPS 재획득이 차단되지 않는다.

## 휠 거리 보정

기존 raw→km/h 환산 후 네 바퀴 평균을 시간 순서대로 적분한다. scale은 GPS endpoint 이동 거리/보정 전 휠 적분 거리다. 이미 적용한 scale로 다시 학습해 보정이 중복되는 구조가 아니다.

학습은 전진, 속도 2m/s 이상, 네 바퀴 일치, 연속된 휠·yaw·후진 신호를 요구한다. 휠 가속도 1m/s² 초과, 절대 yaw 0.03rad/s 초과, GPS 방향 변화 5° 초과는 학습 근거를 끊는다. 각 보정 구간은 3초 이상·휠 거리 20m 이상이다. 구간 3개 이상이면서 GPS 거리 합계 100m 이상일 때 후보를 만든다.

각 구간 비율과 최종 후보는 0.95~1.05 범위다. 범위 밖의 값을 경계값으로 잘라 적용하지 않고 근거를 폐기한다. 충분한 데이터가 없으면 scale 1을 유지한다. GPS 잡음이나 센서 수신 형태 때문에 학습이 성립하지 않을 수 있다.

휠과 yaw의 수신 주기가 같을 필요는 없다. 공통 코어와 같이 이미 도착한 yaw 평균 구간으로 그 안의 짧은 구간을 계산한다. 평균 구간의 실제 수신 시각도 보정 근거에 유지하며, 그 시각보다 이른 GPS 기준점에는 후보를 적용하지 않는다. 이것은 기존 MODEL 평균 구간 가정이며 생산자 측정 시각을 확인했다는 뜻이 아니다.

후보를 완성한 시각보다 **뒤의 성공한 GPS 기준점에서만** 적용한다. 실제 GPS 단절이나 비교 구간이 시작되면 후보·학습 구간을 지우고 이미 적용한 scale을 고정한다. source/clock/audit fault는 적용값도 1로 되돌린다. 정상 비교 종료는 적용값·버전만 유지하고 새 위치·학습 근거로 다시 시작한다. 보정 후보의 수명은 30초다.

## GPS 비교와 로그

기존 [GPS 비교 SHADOW](SHADOW_CALIBRATION_KO.md)의 10초 RUNNING 동안 GPS 좌표·속도·방향을 예측이나 보정 학습에 전달하지 않는다. 이후 최소 30초 cooldown에는 GPS를 받아 다음 보정을 준비한다. 다음 비교의 시작은 cooldown 이후 시각의 **실제로 통과한 GPS 기준점**에서만 허용한다. 센서로 진행한 READY 위치를 새 GPS 기준점으로 잘못 표시하지 않는다.

- `shadow_calibration`: 기존 자이로 상태에 `gps_anchor_gate`, 휠 적용값·후보·버전·구간 수·근거 거리와 시각을 추가한다.
- `shadow`, `shadow_holdout`: 각 결과에 실제 사용한 `wheel_scale`, `wheel_scale_version`을 추가한다.
- PC 분석기: 이전 로그도 읽고, 새 필드가 있으면 쌍/그룹 누락·범위·근거와 비교 도중 보정값 변경을 검사한다. 새 명령은 없다.

자동 실행하며 운전 중 CMU 조작이 필요하지 않다. 위치 비교는 callback 수신 시각을 이용한 MODEL이고 GPS 자체도 참값이 아니다. 작은 GPS 차이나 후보 생성만으로 물리 보정·ASSIST 자격을 얻지 않는다.

검증은 [별도 기록](../validation/GPS_WHEEL_MODEL_2026-09-29.md)을 따른다. 다음 실차 증거는 callback 주기·상대 지연, 기준점 거부 사유, 보정 학습 성립 여부와 적용 전후 GPS 비교 차이다.

# 의사결정 기록

## D01 — 현재 판정과 과거 설계를 분리한다 (2026-09-28)

상세 설계 v1은 전체 목표와 근거를 담지만 구현 전의 가정도 포함한다. 0.1 구현과 후속 리뷰로 달라진 부분은 `STATUS_KO.md`와 `REVIEW_2026-09-28_KO.md`에 기록하고 과거 문서는 보존한다. 상위 문서에 남아 있는 GO가 현재 설치 허가로 읽히지 않도록 명시한다.

## D02 — OFF와 폴링 분리는 독립 수정한다 (2026-09-28)

두 문제는 수정 방향이 정해져 있고 복구 구조 선택을 기다릴 이유가 없다. 각각의 PR과 회귀 검증으로 진행한다. 다만 둘을 해결해도 외부 복구 경로가 미확보이면 실차 설치 보류를 유지한다.

## D03 — 내부 시작 표식만으로 완전 복구를 선언하지 않는다 (2026-09-28)

내부 센티널은 해당 코드가 실행된 뒤의 실패만 관찰한다. N분 후 삭제하는 방식은 보호 시간 이후의 크래시도 놓친다. 실제 로더·서비스 lifecycle 바깥의 보호 위치를 확인하고 보호 범위를 명시해야 한다.

## D04 — SCRUB은 비교 실험이며 DROP도 보장된 해결책이 아니다 (2026-09-28)

optional speed/bearing 제거와 유효 속도 0은 다르다. 오래된 좌표가 남는 문제는 실제로 존재하지만 앱이 멈추는지/개선되는지는 폰 관측이 필요하다. LOCATION 생략은 별도 send/return 계약 분석 뒤 평가한다.

## D05 — SMDB poll을 ASSIST 입력으로 승격하지 않는다 (0.1 구현에서 확정, 2026-09-28 재확인)

원래 시간·품질·평균 구간이 없으면 재조회 성공을 새로운 측정으로 간주할 수 없다. ASSIST 차단을 유지하고 native NNG 경로와 더 상위 생산자 경계를 조사한다. 이 계약을 확보하지 못하면 현재 SMDB 기반 경로를 종료한다.

## D06 — 공개 저장소를 코드·근거·리뷰의 기준으로 삼는다 (2026-09-28)

0.1 소스를 기준선으로 가져오고 수정 이력을 PR로 남긴다. 원본 펌웨어·지도·디스어셈블 덤프와 개인 로그는 공개하지 않는다. 지금은 소스와 연구 기록을 관리하며 설치 바이너리 릴리스를 게시하지 않는다. 라이선스는 아직 선택하지 않았다.

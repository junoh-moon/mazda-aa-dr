# SHADOW 정차 영점 보정과 GPS 비교

대상은 NA 74.00.324A의 MODEL SHADOW 경로다. 고정 영점 때문에 생기는 회전 오차를 줄이는 계산과, GPS가 보이는 구간에서 센서 DR을 별도로 비교하는 실행 기능을 추가한다. 실제 차량의 보정·정확도를 확인한 결과가 아니며, `v0.2.0-observe.2` 설치 ZIP에는 들어 있지 않다.

## 실행 구성

후속 [GPS 기준점·휠 거리 보정](GPS_WHEEL_MODEL_KO.md)은 두 MODEL 파이프라인의 기준점 검사를 보강하고, GPS-visible cooldown에서 휠 보정을 학습한다. RUNNING 중 GPS 제외 계약은 같다. 정상 비교 종료에는 적용 자이로 영점과 휠 scale을 함께 유지하며, 이후의 세부 조건은 해당 문서를 따른다.

기존 AA worker가 같은 원본 센서 복사본을 두 MODEL 파이프라인에 전달한다.

- **주 SHADOW:** 정차 중 영점 후보를 계산한다. 정상 GPS 기준점을 잡을 때 적용하고 실제 mode=0 구간을 계산한다.
- **GPS 비교 SHADOW:** 별도 상태와 기준점을 가진 동일한 파이프라인이다. 정상 GPS로 시작한 뒤 10초 동안 GPS를 계산에 넣지 않고 센서로 이동을 계산한다. 계속 들어오는 GPS와 위치·방향 차이만 기록한다.

두 기능은 SHADOW에서 자동 실행한다. 설치 기본 모드는 OBSERVE이며 이번 변경은 설치·기동 예약 절차를 바꾸지 않는다. 기존 SHADOW 설정을 쓰며 새 명령이나 운전 중 조작은 없다. 준비된 묶음의 주차 중 설정 절차는 [첫 시험](FIRST_TRIAL_KO.md)과 [센서 SHADOW](LIVE_SHADOW_2026-09-29_KO.md)를 따른다. 소스 PR을 설치 묶음이나 실차 승인으로 해석하지 않는다.

## 정차 영점 보정

`Pipeline::init_model(..., auto_bias=true)`일 때만 활성화한다. 일반 MODEL API의 기본값은 false여서 고정 영점과 비교할 수 있다. qualified 입력 경로에는 이 추정기를 적용하지 않는다.

| 조건 | 현재 MODEL 가정 |
| --- | --- |
| 정차 | 네 바퀴 각각 0..0.05 m/s. 평균 속도만으로 판정하지 않음 |
| 관측 기간 | 3초 이상, 실제 yaw 이벤트의 평균값 20개 이상 |
| 센서 연속성 | 휠·yaw 간격과 지연이 250ms 또는 코어 sample-age 제한 중 작은 값 이내 |
| 영점 범위 | 프로파일 명목 영점 ±64 count |
| 안정성 | 관측 범위 4 count 이하, 모집단 분산 1 count² 이하 |
| 후보 수명 | 마지막 보정 근거 시각부터 새 기준점까지 최대 30초 |
| 저장 | 해당 프로세스의 메모리에만 유지. 영구 보정 파일 없음 |

순정 산식을 유지하여 각 이벤트의 `raw_sum / count`를 **정수 나눗셈**으로 구한 뒤 영점 후보의 평균·분산을 계산한다. 하드웨어 내부 측정 시각이나 평균 구간을 새로 증명하지 않는다. 위 임계값도 실차에서 확정된 값이 아니다.

움직이면 진행 중인 정차 관측을 중단한다. 이미 완성된 후보는 다음 이동 GPS 기준점에서 쓸 수 있도록 제한된 수명 동안 보존한다. 잡음·비정상 값·센서 단절은 후보를 폐기한다. 파이프라인의 소스·시간·audit reset은 적용 영점과 항법 기준점을 함께 지운다. receipt/transport 시각 종류가 바뀌면 자동 보정 파이프라인은 기준점을 폐기한다.

후속 [세션 경계 수정](../validation/MODEL_SESSION_REVIEW_2026-09-30.md)은 관측한
AA 세션의 생성·파괴·상태 경계에서도 두 MODEL 파이프라인의 적용 영점·휠 보정과
대기 입력을 초기화한다. 이전 요청과 경계 이전 센서는 새 계산에 재사용하지
않으며 원본과 제외 사유를 기록한다. 일반 GPS→GAP 전환이나 정상 holdout
종료의 보정 유지와 구별한다. 이 경계는 폰 연결이나 물리 센서 자격을 증명하지 않는다.

후보는 **성공한 새 GPS seed에서만** 적용한다. DR이 진행되는 동안 정차를 새로 관측해도 현재 계산의 영점은 바꾸지 않는다. 미리 수신한 yaw 구간도 적분할 때 적용 영점으로 변환하므로, 큐에 들어갔던 시점의 옛 영점이 섞이지 않는다.

`candidate_ready`는 모델 후보가 있다는 뜻이며 물리 보정 완료를 뜻하지 않는다. `calibration_version`은 해당 reset 이후 적용 횟수이며 소스 전체에서 영구 증가하는 버전이 아니다.

## GPS를 계산에서 제외하는 비교 구간

기본값은 10초 계산, 종료 후 최소 30초 대기, GPS 관측 단절 허용 2초다. 시작에는 이동 중의 수치적으로 타당하고 연속적인 GPS 관측과 실제 센서 기준점이 필요하다. 정차 중 heading을 새 기준 방향으로 신뢰하지 않는다. 기준점에는 그 시각에 이미 수신했고 원래 lease와 age 제한 안에 있는 후진 신호를 요구한다. 오래된 전진 신호로 기준점을 만든 뒤 나중의 후진 신호가 이를 유효하게 보이게 하던 기존 결함도 수정했다.

비교 구간 시작 후 GPS의 좌표·속도·방향은 비교·관측 적합성 판정에만 쓰며 계산 파이프라인의 seed나 센서 입력으로 전달하지 않는다. 계산은 같은 DR 코어와 휠·yaw·후진 입력을 사용한다. 실제 mode=0, native mode=3, 불량 GPS, 센서 단절·재시작, 시간 역행, 큐 초과가 발생하면 해당 구간을 중단하고 새 기준점을 요구한다.

정상적으로 끝난 비교 구간의 다음 계산은 적용 영점·버전과 센서 소스/순번/시각 식별을 유지하되, 위치 기준점·큐·미완성 보정 후보를 새로 시작한다. 단절·오류·audit 중단은 영점도 지운다. 두 파이프라인은 기준점 적용 시점이 다를 수 있으므로 각 결과에 실제 사용한 영점을 기록한다.

GPS 참조는 고정 큐에서 대기한다. yaw 평균 구간이 나중에 도착하더라도 **예측 frontier가 GPS callback 수신 시각과 정확히 같을 때만** 비교한다. 뒤처진 위치를 최신 GPS와 바로 빼거나, 늦은 GPS를 과거 계산에 끼워 넣지 않는다. 이미 지나간 시각의 참조는 중단 사유가 된다. 실제 현재 수신 시각으로 예측의 유효기간도 검사한다.

이 정렬은 `receipt_model`이다. GPS와 차량 센서의 물리 측정 시각·지연이 일치한다는 주장이 아니다. 정상 GPS도 참값이 아니므로 출력은 **GPS 대비 차이**다. heading 차이는 양쪽 이동 방향이 존재할 때만 기록하고 정차에서는 생략한다. 차이가 작아도 폰/네이버 지도 수용이나 live ASSIST 자격을 증명하지 않는다.

참조 큐 32개, 출력 큐 64개로 제한하며 동적 할당·추가 프로세스·D-Bus·차량 송신을 넣지 않는다. 출력 큐 포화는 보이지 않는 샘플링 대신 ABORT로 드러낸다. 비교는 한 번에 하나의 구간만 실행한다. CPU 시간과 실차 수신 빈도는 아직 측정하지 않았다.

## 로그와 PC 판정

- `shadow_calibration`: 1초 주기로 상태, 적용 영점, 후보, 분산, 근거 시각·개수, 적용 버전을 기록한다.
- 기존 `shadow`: 각 위치에 적용된 `yaw_zero`, `calibration_version`을 추가한다.
- `shadow_holdout`: BEGIN / COMPARED / END / ABORT, 구간 ID, 기준점·참조·예측 시각, 비교 차이와 적용 영점을 기록한다. 준비 단계의 중단은 구간 ID 0이다.

모두 `domain=model`, `assist_ready=false`다. COMPARED가 아닌 이벤트에는 위치 차이 숫자를 넣지 않는다. 원본 `motion_batch`의 센서 필드와 순서는 유지한다.

기존 PC 명령으로 읽는다.

```sh
python3 tools/analyze_logs.py exported-logs.tar.gz --json
```

분석기는 잘못된 MODEL/ASSIST 표시, 비정상 숫자, 참조와 예측 시각 불일치, 누락된 BEGIN/종료, 역행 참조 및 구간 도중 보정값 변경을 확인한다. 비교 수·최소/최대/평균 GPS 차이를 요약하되 정확도 합격 판정을 만들지 않는다. ABORT나 잘린 구간은 불완전한 비교로 남긴다. 회전 로그의 보관 한계와 차량 위치 정보 취급은 기존과 같다.

## 검증과 다음 증거

2026-09-30부터 제품 worker는 관측된 AA 세션의 lifecycle revision이 바뀌면
보정 후보·적용값과 두 계산기의 대기 입력을 초기화합니다. holdout은
`session_reset`으로 중단하며 새 센서 입력과 GPS 기준점 쌍을 요구합니다.
관측 세션 부재·중복·전환·오류, 이전 revision의 요청, 요청 관측·시각 관계가
불명확한 위치는 계산에서 제외하고 원본 자료와 제외 사유는 계속 기록합니다.
`shadow_session`은 이 경계와 원시 입력의 수신 시각 하한을,
`shadow_position_rejected`는 위치 입력의 제외 사유를 나타냅니다.
일반 GPS→GAP 전환은 세션 reset이 아니므로 터널 MODEL 적분을 유지합니다.
이 제한은 qualification이 아닙니다. [새 검사 기록](../validation/MODEL_SESSION_2026-09-30.md)을
기존 합성 보정 검사와 구분하십시오.

고정 영점과 보정 영점의 직진·회전 비교, 가짜 정차·한 바퀴 움직임·잡음·단절 거부, 계산 중 영점 고정, GPS 재획득, 참조 GPS를 바꿔도 DR 예측이 같다는 격리 시험, 시각 정렬과 중단 경로를 검사한다. 실행 결과는 [검증 기록](../validation/SHADOW_CALIBRATION_2026-09-29.md)에 별도로 적는다.

실차에서 남은 것은 원본 센서 주기·지연·후진 신호 가용성, 실제 영점 변화와 보정 임계값, 위치 차이의 크기, CMU 계산 비용과 기존 AA/touch 공존이다. live ASSIST의 센서·provenance·복구·폰 수용 조건은 그대로 남는다. `allow_assist=false`와 MODEL 출력을 거부하는 bridge를 유지한다.

# 문제 정의와 거기서 파생하는 규칙 — 2026-10-05

원칙: **문제 해결이 1순위이고, 규칙은 문제를 풀기 위해 정의한다.** 규칙이 문제를 가로막으면 규칙의 근거를 다시 묻는다.
소유자가 2026-10-05에 1~3절의 문제·목표를 확인했고, 5절의 세부 규칙(분위수 등 수치 포함)은 코드와 자료를 조사해 구현 담당이 정하도록 위임했다.
세부 규칙이 근거와 함께 확정되어 `AGENTS.md`에 반영되기 전에는 `AGENTS.md`의 기존 규칙이 유효하다.

## 1. 문제

Mazda Connect(NA 74.00.324A)는 AA로 폰에 차량 위치(LOCATION)를 보낸다. GPS가 끊기면(터널, 지하주차장) 순정은 마지막 좌표에 정확도를 지운 값을 반복해 보내고,
네이버는 이를 무효로 보고 자체 외삽에만 맡긴다. 그 결과 사용자는 **터널에서 속도 변화가 반영되지 않고, 지하주차장에서 방위가 틀어지는** 것을 본다.
차는 이미 정확한 정보(휠 속도, yaw)를 갖고 있지만 폰에 전달되지 않는다.

## 2. 목표와 비목표

- **G1** 터널(GPS 단절) 안에서 네이버가 표시하는 속도가 실제 차 속도를 따른다.
- **G2** 지하주차장 안에서 방위(나침반)가 실제 차 진행 방향과 맞는다.
- 비목표: 주차장 내부의 절대 위치 정확도, 긴 터널의 위치 정확도, 순정 기능(터치, HUD, 연비 등)의 변경.

## 3. 성공 기준(관측 가능하게)

1. 단절 구간에서 네이버 표시 속도와 실제 휠 속도의 차가 작다(기준값은 시험 자료로 정한다; 순정은 마지막 속도에 고정).
2. 주차장에서 1분 단절 뒤 표시 방위 오차가 약 20° 이내(재생 추정: 앵커 3° + yaw 오차 10° 안팎).
3. 네이버가 "GPS 끊김"을 띄우지 않고, GPS 복귀 때 위치가 튀지 않으며 수 초 안에 정상으로 돌아온다.
4. 모든 판단(켬, 끔, 폴백, 사유)이 로그로 남아 사후에 설명된다.

## 4. 불변 조건(해를 끼치지 않기 위한 것, 문제에서 직접 나온다)

- H1 차를 해치지 않는다: CMU 리셋, AA·터치·HUD 장애가 없다. jciAAPA는 `reset_board=yes`라서 우리 코드의 어떤 크래시도 CMU 리셋이다.
- H2 의심이 있으면 **현재 상태(순정 송신)로 돌아간다.** 순정 송신이 기준선이므로 우리가 켜서 순정보다 나빠질 수 있는 경우에만 막으면 된다.
- H3 OEM 송신 계약(한 번 호출, 반환값, errno, 위치 외 필드)을 보존한다.
- H4 운전 중 CMU 조작이 없다. 시험은 한 번의 주행으로 끝나도록 설계한다.

## 5. 파생 규칙과 기존 규칙의 변화(승인 요청)

| 기존 규칙 | 문제에 비춰 본 근거 | 제안 |
| --- | --- | --- |
| 자격 있는 증거 + 관문이 전부 충족돼야 ASSIST | 관문은 "나쁜 위치를 보내지 않는다"를 위한 수단이다. 목적은 순정보다 나쁘지 않을 것 | **측정으로 정한 성공 기준**(재생, 시험 주행 자료)을 만족하고 H1~H4를 지키면 ASSIST 허용. 관문은 자료로 검증하는 항목으로 바꾼다 |
| 수신 시각은 생산 시각으로 올리지 않는다 | 지연 오차가 모델에 없을 때만 위험하다 | 수신 시각 증거를 쓰되 **지연 불확실성(측정한 값)을 오차에 포함**하고 MODEL 표지를 로그에 유지 |
| 정확도를 낮춰 보고하지 않는다 | 거짓 정확도를 막으려는 것이다. 최악 경우 선형 합은 실제보다 훨씬 비관적이라 쓸 창이 15초로 줄어든다(재생: 60초 후 실제 중앙값 15 m, p90 30 m) | **보정된 정확도**: 재생·시험 자료에서 검증한 분위수(예: p90) 이상으로 보고. 검증되지 않은 값을 낮춰 보고하는 것은 계속 금지 |
| 검증 안 된 센서 품질은 ASSIST 불가 | 같은 이유 | 성공 기준과 같은 방식으로 자료 검증 |
| 한 번에 한 가지 위험만 켠다 | H1에서 파생 | 유지: 위치 후킹 설치, `libpatch` 공존, ASSIST를 한 시험에서 처음 겹쳐 켜지 않는다 |

유지하는 규칙: OEM 계약 보존, 펌웨어 가드 약화 금지, 운전 중 조작 금지, 일회성 가드, 개인정보·OEM 바이너리 비공개, 독립 검토, 정직한 보고(시험하지 않은 것을 했다고 하지 않기).

## 6. 능력 단계(문제에서 우선순위가 나온다)

- **L1 속도**: 휠 속도만으로 가능하며 앵커가 필요 없다(배율 오차 약 1%). 속도가 폰에 닿으려면 정확도가 있는 정상 fix 형태여야 한다(DHU: 정확도 없는 이동 fix는 무시됨).
- **L2 방위**: GPS 앵커의 방향과 yaw 적분. 앵커 게이트(직선, 20 km/h 이상, GPS와 휠 속도 일치)와 후진 처리가 필요하다.
- **위치**: 비목표. 단절 직전 위치에서 DR로 전진시키되 정확도는 보정된 값으로 보고하고, 그 값이 한계(네이버 수용 40 m)를 넘어도 GPS 복귀까지 계속하며 보고 정확도는 40 m로 고정한다(2026-10-09 소유자 결정, 7절 2).

## 7. 남은 결정

1. (위임됨) 5절의 수치와 세부 규칙은 조사 결과와 근거를 `validation/`에 기록하고 확정한다.
2. (결정됨, 2026-10-09 소유자) 단절이 길어 보정된 정확도가 40 m를 넘을 때: 순정으로 돌아가지 않고 GPS 복귀까지 계속 DR 위치를 보낸다. 보고 정확도는 40 m로 고정하고 실제 예산은 기록에 남긴다. 근거와 한계는 [validation/TUNNEL_UNBOUNDED_2026-10-09.md](../validation/TUNNEL_UNBOUNDED_2026-10-09.md).

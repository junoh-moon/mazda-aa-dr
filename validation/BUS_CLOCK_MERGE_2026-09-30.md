## 직접 재현한 실패와 통합 내용

이전 `b4ea8f2` 소스에서 외부 회귀 두 개를 직접 실행하고 각각 exit 134를
확인했습니다. 수신 회귀는 이전 API에 맞춘 인자만 바꾸었고 실제 `recvmsg`
진입 뒤 datagram을 보냅니다. 이전 제품은 검사 시각을 미리 읽어 정상 입력을
FUTURE로 거부했습니다. 실제 received 시각은 `1633679675415467`, 이전
checked 시각은 `1633679674358964`였습니다. clock 값을 합성하지 않았습니다.

버스 회귀는 다른 연결이 전환 중일 때 정상 연결의 출처 표시가 누락되는 것을
검출했습니다. 통합 후 같은 두 회귀를 통과했으며, 버스 검사는 결정적인
전환 사례와 동시 표시 20,000회를 포함합니다. 이 수치는 외부 리뷰자의 별도
100,000회 실행과 합치지 않습니다.

- 수신 뒤 CLOCK_MONOTONIC을 읽고 syscall errno를 먼저 보존합니다.
  미래 입력 허용 범위를 늘리지 않으며 sequence 연속성 검사를 유지합니다.
- 버스 출처 표시는 안정된 슬롯을 먼저 잡고 상태·주소·수명을 재검사합니다.
  단조 CAS로 늦은 이전 표시가 새 수명을 덮지 않도록 합니다.
- 기존 MODEL/holdout의 세션·버스 초기화와 원시 입력 보존을 유지했습니다.
  외부 분석기의 수명 소유권·상태 이력·복합 시각 경계 검사를 합쳤습니다.
- worker 시험은 경계 전 READY/holdout BEGIN을 요구하고 free 진행 중,
  늦은 동일 연결 요청, 오래된 raw와 경계 전 GAP을 검사합니다. 비차단
  송신 재시도는 작성 fixture에만 적용하며 순번·시각을 바꾸지 않습니다.

외부 변경의 별도 원본 실행 42건과 독립 리뷰는
[외부 검토 기록](MODEL_BUS_REVIEW_2026-09-30.md)의 증거입니다. 아래는
통합 커밋으로 이 작업에서 새로 실행한 결과입니다.

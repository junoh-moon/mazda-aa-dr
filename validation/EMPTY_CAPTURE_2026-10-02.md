# 실차 회수 성공과 기록 부재 — 2026-10-02

## 확인한 결과

사용자가 v0.3.9-shadow.1 설치 후 재부팅하고 무선 Android Auto 동글과
Galaxy S25를 연결하여 지하·지상 구간을 주행했다고 확인했습니다.
이후 제거 메뉴를 사용했고, v0.3.9-shadow.2 USB로 회수를 다시 수행했습니다.
재부팅 누락이나 주행하지 않은 것을 원인으로 간주하지 않습니다.

회수 ZIP의 CRC, 내부 tar와 SHA-256 sidecar를 확인했습니다. USB의 기존
묶음 파일 36개는 공개 v0.3.9-shadow.2와 모두 같았습니다. 이는 회수 USB의
신원 확인이며, 이전 시험에서 설치된 코드의 실행 증거는 아닙니다.
개인 공유 주소, 사진, 원본 archive와 장치 식별자는 비공개로 보존했습니다.

| 관측 | 결과와 해석 |
| --- | --- |
| 메뉴3 회수 | `export_exit=0`; 4,096바이트 tar를 정상 생성했습니다. |
| 원시 기록 | `trace.*.jsonl`, `collector.*.jsonl`, storage 중단 기록 모두 없습니다. |
| 공개판 분석기 | 변경하지 않은 분석기로 실행하여 종료 2, `inconclusive`, 기록 수 0입니다. |
| 현재 상태·종료 | `status_exit=1`, `finish_exit=1`; 현재 부팅의 수집 완료 근거가 없습니다. |
| 현재 여유 공간 | 보고값은 522,866 KiB입니다. 시험 당시의 공간·마운트 상태는 알 수 없습니다. |
| `mode=OFF` | 앞선 제거 동작이 기록한 값일 수 있어 시험 모드의 증거가 아닙니다. |
| 빈 `collector.lock` | 설치기가 만들 수 있으므로 collector 실행 증거가 아닙니다. |
| stop 디렉터리 | 이번 종료 요청이 만들 수 있으므로 이전 실행 증거가 아닙니다. |

두 실행기는 센서 수신이나 모델 계산보다 먼저 기동 행을 기록하고 flush합니다.
따라서 단순 GPS 부재나 AA 연결 방식 차이만으로 양쪽 기동 파일의 부재가
설명되지는 않습니다. 자동 실행 선택 실패, 첫 기록 전 실행·초기화 실패,
실제 저장 위치 문제를 구분해야 합니다. 현재 자료만으로 원인을 확정하지 않습니다.

## 재부팅과 저장 경로

제공된 원본 펌웨어의 초기화 실행 파일을 정적으로 조사했습니다.
`/data_persist → /mnt/data_persist → /tmp/mnt/data_persist` 경로에서
마지막 디렉터리는 `/dev/mmcblk0p2`를 `relfs`로 마운트하는 대상입니다.
`/tmp` 자체의 93 MiB tmpfs와 구분됩니다. 경로에 `/tmp`가 있다는 사실만으로
기록이 임시 메모리에 저장됐다고 판단하지 않습니다.

프로젝트의 journal 회전은 설정된 개수 안에서 이전 파일을 보존하면서 새 파일을
만듭니다. 오래된 파일은 회전으로 밀려날 수 있지만 정상 기록 중에는 새 파일이 남습니다.
제거 메뉴는 로그를 삭제하지 않습니다. 정상 영구 저장장치에 기록한 파일을
재부팅 때 전부 비우는 코드도 없습니다. 반면 경로 존재·권한·여유 공간 검사만으로
해당 시점에 실제 영구 저장장치가 마운트됐음을 증명할 수는 없습니다.
마운트되지 않은 임시 디렉터리에 쓴 자료는 재부팅 때 사라지거나 이후 마운트로
가려질 수 있습니다. 이는 조사할 가능성이지 이번 차량에서 확인한 원인이 아닙니다.

## 진단 누락과 검증 범위

출하 회수 기능은 `logs`와 `mx5dr.conf`만 담았습니다. 이전 부팅의
`guard/last-boot`, `consumed`, 설치 파일 지문과 마운트 상태는 포함하지 않아
가드 선택 실패와 선택 후 실행 실패를 구분할 수 없습니다.
`one_boot=unconfirmed`는 이전 부팅의 표식이 있어도 표시됩니다.
이를 가드가 한 번도 실행되지 않았다는 증거로 해석하지 않습니다.

기존 순정 BusyBox 검사와 진단용 userspace VM은 가드를 직접 호출했습니다.
수정한 원본 autostart가 원본 셸 설정을 거쳐 가드를 부르는 전체 경로를 검증한
것은 아닙니다. 이 경로와 실제 마운트 구조를 별도로 검사합니다.
QEMU 사용자 모드의 파일시스템 syscall은 호스트 커널 동작이므로 원본 CMU
커널·저장장치의 동작을 대체하지 않습니다.

다음 필요한 차량 측 사실은 **남아 있는 기동 표식과 현재 파일시스템의 정체**입니다.
이를 위한 추가 회수는 주차 상태의 진단이며 재설치·재무장·추가 주행이 아닙니다.
현재 시점의 상태를 얻더라도 이미 없어진 시험 부팅의 사건을 복원할 수 있다는
보장은 없습니다. 먼저 가능한 원본 펌웨어·오프라인 검사를 완료합니다.

이 결과는 [이전 회수 핫픽스 검증](TRIAL_EXPORT_HOTFIX_2026-10-02.md)에
새로 추가된 실차 증거입니다. 과거 통과 수치를 수정하거나 현재의 성공으로
재사용하지 않습니다. 물리 센서 수집·관성항법 적용·폰 수용은 입증되지 않았으며
live ASSIST는 비활성입니다.

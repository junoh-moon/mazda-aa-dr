## 새로 빌드한 소스와 전체 시험

SSH로 `master`를 받은 별도 깨끗한 checkout을 위 커밋에 고정했습니다.
고정 GCC 4.9.1 ARM 도구체인(`61ec0343de84f6fc7c46840056df1d600d44be8a`)으로
새 디렉터리에 다섯 ARM 파일을 만들고, 그 빌드의 제품 DSO로 SHADOW 묶음과
ZIP을 생성했습니다. arm-build 입력·산출물과 ZIP build-info를 대조했습니다.
ELF32 little-endian ARM softfp, TEXTREL 없음, 동적 libstdc++ 의존성 없음과
필요한 GLIBC 2.4/의존성을 확인했습니다.

최종 묶음과 제공 펌웨어 fixture를 지정한 clean `make test`는 Python
**374개와 C/C++ 검사, 생략 0**으로 끝났습니다. 같은 최종 다섯 파일을 지정한
고정 ARM 전체 runner도 종료 0·생략 0이며 시작/끝 `ARM_TEST_INPUTS`의
`release_verified=true`와 파일·도구체인 해시가 일치합니다. 실제 배포 DSO의
작성 입력 시험은 position 8, request 14, raw wire 1, session 29, bus 31,
ASSIST 28, runtime-assist 9개를 포함합니다. ASSIST의 미결합 GPS·품질 전환·
동일 시각 오래된 기준점은 원본 전달 또는 `NOT_READY`로 끝났습니다.

## 원본 코드 VM과 설치 ZIP

최종 DSO를 startup preload한 별도 외부 caller를 컴파일했습니다. 원본
커널·rootfs를 넣은 격리 VM에서 실제 product `cold install=ok`를 확인하고
원본 LDS/AA API·journal을 실행했습니다. 정상 사례는 연계 위치 17건과
검사 9,947개, 제공자 부재 사례는 오류 연계 위치 10건과 검사 5,889개를
각각 `PIPE_RESULT=PASS`·caller 종료 0으로 기록했습니다. 그 27건의
raw 요청·응답 serial/reply_serial과 관측 순서를 최종 DSO journal에서
검사했습니다. 결합된 원본 요청 수명 사례도 `LIFE_RESULT=PASS`였습니다.
VM의 기존 진단 스크립트는 작성 request 14개 중 13개만 실행했습니다.
빠진 `session_transition`은 위의 고정 ARM DSO 시험에서 통과했습니다.
정상 사례 네 요청의 bus lifetime은 미확인으로 남았고 raw identity를
자격으로 승격하지 않았습니다.

게스트는 정상 결과 뒤 poweroff를 요청했지만 QEMU runner는 **240초 제한**에
도달했습니다. runner 종료 코드 124/기록된 QEMU 종료 0은 성공 근거가
아닙니다. 위의 개별 marker, 원본/제품 해시, journal의 정상 종료·소유권·
송신 바이트·손실 0을 별도 검증한 범위만 통과로 판단했습니다. VM에는
물리 CMU 장치·차량 센서·휴대폰이 없으며 위치 seed는 합성 자료입니다.

최종 ZIP을 풀어 순정 ARM BusyBox 1.19.2/libc에서 직접 `sh install.sh`,
손상 묶음 거부, 두 DSO loader, 일회 부팅 가드, 기존 터치 설정 보존,
collector UID/종료, 숫자 메뉴의 상태·종료·USB 회수·제거·재설치를
통과했습니다. 마운트 상태와 센서·health 행은 작성한 fixture입니다.
압축 CRC, 외부 SHA-256, 내부 `SHA256SUMS`, build-info의 소스 커밋·모드와
다섯 파일 해시를 확인했습니다. 공개 후 두 첨부 파일을 새 디렉터리에
받아 ZIP byte 동일성·CRC·외부/내부 해시를 다시 확인했습니다.

## 남은 조건

실제 센서별 단위·측정 시각·품질과 LDS producer→snapshot→응답 자격
공급부는 미구현입니다. 물리 저장소의 remount·복구, 실제 차량 기동·센서,
터널 위치 정확도, Galaxy S25/동글/지도 앱 수용도 미검증입니다.
송신 선택과 OEM send 사이의 세대 변경 경합은 별도 검증이 필요합니다.
한 번의 준비된 실차 기회는 [통합 시험 절차](../docs/FIELD_TRIAL_KO.md)를
따르며, 그 결과가 없으면 ASSIST를 켜거나 v1.0으로 표시하지 않습니다.

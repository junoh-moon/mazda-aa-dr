# MODEL 버스 경계 처리 — 2026-09-30

NA 74.00.324A 전용입니다. `feat/session-observation`의 `c595407`에서
작업했으며 같은 브랜치를 유지합니다. 차량·폰·동글과 독립 에이전트는
사용하지 않았습니다. ASSIST는 비활성이고 공개 설치 ZIP은 변경하지 않습니다.

## 문제와 변경

기존 제품의 실제 journal/MODEL worker에 작성한 세션·버스 API와 위치·센서
입력을 연결했습니다. AA 세션을 유지한 채 버스를 끊어도 이전 입력으로 유효한
MODEL 결과가 14회 남았고 holdout의 버스 초기화는 0회였습니다. 수정 전
실패(exit 134)와 원시 로그를 보존했습니다.

- 고정된 LDS notify를 사용하는 실제 submit에서 연결의 로컬 수명을 표시합니다.
  HMI/다른 연결을 서비스 종류나 최근 응답만으로 추정하지 않습니다. 새 접속
  수명은 새 LDS submit이 관측돼야 계산 입력의 연결로 인정합니다.
- 해당 연결이 없거나 여러 개이면, 또는 관측 중/오류이면 계산 입력을 막습니다.
  관측 revision이 변하면 MODEL과 GPS holdout의 기준점·학습 보정·대기 입력을
  초기화합니다. revision은 다른 버스의 lifecycle도 포함하므로 보수적으로
  추가 초기화할 수 있습니다. GPS→GAP 자체는 이 경계를 만들지 않습니다.
- 요청 발행과 응답의 연결을 모두 현재 연결과 비교하고 경계 전에 발행한
  요청을 거부합니다. 원시 위치 기록은 보존합니다. 기존 세션 경계와 버스
  경계 중 늦은 시각을 센서 입력의 하한으로 사용하며 오래된 receipt/양수
  transport 입력과 제외 사유도 저장합니다. 물리 생산 시각의 증명은 아닙니다.
- `shadow_bus`, 버스 epoch/revision, `bus_reset`과 입력 제외 사유를 기록합니다.
  분석기는 경계·계산 결과의 일치와 시각을 검사하고 과거 로그를 계속 읽습니다.
  초기화나 입력 부재는 inconclusive이며 qualified 성공을 만들지 않습니다.
- OEM 인자·반환·errno와 원본 전달, 기존 해시/ABI·설치 슬롯을 유지합니다.
  새 관측 함수는 고정 배열과 lock-free 원자 연산만 사용합니다.

## 직접 검사

`make test`의 host Python 309개와 C/C++ 검사를 통과했습니다. 생략은 없습니다.
MODEL worker의 버스 단절·재접속·같은 주소 재사용·close callback·단절 signal·
복수 연결·진행 중 해제 7개 회귀는 이전 MODEL 출력 0회와 새 기준점 뒤 재개를
확인합니다. AA 세션 6개 회귀도 유지합니다. 버스 표시/해제와 두 동시 reader의
경쟁 검사를 추가해 별도로 통과했습니다.

고정 GCC 4.9.1로 빌드한 제품과 exact ARM 전체 검사를 통과했습니다. 생략은
없습니다. 제품 DSO의 position 8·request 14·session 29·bus 17개 검사를
통과했고, 원본 공유 runtime에서도 같은 제품의 session 29·bus 17개를
통과했습니다. 전역 생성자 이전 초기화와 원본 errno/예외/취소 전달을 포함합니다.

학습 보정 회귀에서 두 계산기의 yaw 영점 2067·wheel scale 1.03 적용을 먼저
확인했습니다. 버스 경계 뒤에는 명목 영점 2047·scale 1과 버전 0으로 돌아가며
대기 holdout을 제거했습니다. 작성한 새 기준점 이후의 재개도 확인했습니다.

동시 빌드/검사 중 호스트 bus_inflight와 ARM recreate 작성 fixture가 입력
send 실패(exit 134)로 중단됐습니다. 통과로 세지 않으며 실패 로그를 보존합니다.
후속 host 전체 및 VM 종료 뒤 순차 ARM 전체 검사에서는 재현되지 않았습니다.
정확한 원인은 미분리이며 성공 검사로 앞선 실패 이력을 지우지 않습니다.

원본 커널 VM에서 기존 세션 파괴·재생성 시나리오와 AA 세션을 그대로 둔
버스 해제 시나리오를 실행했습니다. 실제 LDS 응답은 각각 5·9·3건이고,
사용된 연결은 object 2/lifetime 2였습니다. 버스 해제 전후 AA lifetime/revision은
1/1로 유지됐지만 `shadow_bus`는 `no_live_connection`으로 바뀌고 계산을
초기화했습니다. 단절 구간의 합성 raw 78건을 계속 저장했습니다. 각 실행의
전체 raw 540·519·309건은 연속 순번이며 journal/request/bus fault는 0입니다.
원본 세션 전환을 넘은 지연 응답도 각각 1건, 새 세션의 지연 LOCATION 1건을
확인했고 원본 전달 바이트가 일치했습니다. 별도 원본 상태 callback 2주기와
실제 daemon 종료에 따른 단절 signal 검사도 통과했습니다.

모든 원본 GPS 응답은 mode/UTC/좌표 0이며 MODEL 유효 출력은 0입니다.
버스 해제 시 holdout은 앞선 mode 0으로 이미 COOLDOWN에 있어 기존 reset은
중복 ABORT 행을 내지 않습니다. 최초 비공개 판정기는 이 행을 잘못 요구해
실패했습니다. 실패를 보존하고, 코드의 기존 계약에 맞게 선행 real_gap ABORT,
실제 버스 경계와 이후 계산 epoch를 대조했습니다. OEM의 학습 보정 초기화를
검증한 것으로 세지 않으며 그 양성 검사는 작성한 host/ARM 입력의 범위입니다.
분석기는 세 로그에서 inconclusive 22·35·17건, violation 0건을 반환했습니다.
205초 실행 종료 코드는 helper 124/QEMU 0이고 timed_out=true입니다. 이 코드를
성공으로 삼지 않고 종료 후 불변 console의 완료 표식과 전용 판정기로 검사했습니다.

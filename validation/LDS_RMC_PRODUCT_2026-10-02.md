# RMC 상태 보존 제품의 전체·원본 검사 — 2026-10-02

고정 소스는 `5eec1faf5b642f3ea86357841b97ffe29d646686`입니다.
[상태 보존 구현](LDS_RMC_METADATA_2026-10-02.md)을 새 여섯 ARM 제품으로
빌드하고 전체 host/ARM 및 원본 reader→현재 AA 사본 전달을 검사했습니다.
대상은 NA 74.00.324A이며 과거 d66 제품의 결과와 구분합니다.

## 빌드와 전체 회귀

GCC 4.9.1의 고정 도구체인으로 깨끗한 별도 사본에서 빌드했습니다.
추적 소스 441개, 빌드 입력 81개, 여섯 제품·묶음·도구체인·원본 fixture·
패키지 목록의 전후 동일성을 확인했습니다. 새 도구 설치는 없습니다.

| 검사 | 이번 실행 결과 |
|---|---|
| 여섯 ARM 제품·SHADOW 묶음 | 각각 직접 종료 0 |
| 전체 `make test` | Python 605개와 C/C++, 종료 0, 534.307초 |
| 전체 ARM | Python 131개와 C/C++, 종료 0, 463.060초 |
| 위 ARM에 포함된 실제 AA DSO | 13개 suite·206사례 통과 |
| 위 ARM에 포함된 원본 LDS 설치기 | 96사례 통과 |

host/ARM의 생략은 각각 0입니다. DSO·설치기 수는 전체 ARM에 포함된
하위 결과이며 별도 전체 재실행으로 합산하지 않습니다.

최초 빌드 launcher는 성공한 컴파일 뒤 정적 해시 helper에 `nm -D`를
사용한 판독 오류로 종료 1이었습니다. 최초 실패를 보존하고 정적 파일에는
일반 심볼 조회를 사용하여 **저장된 동일 제품만 재판독**했습니다. 수정 판독은
종료 0이며 제품을 다시 빌드하거나 첫 launcher를 성공으로 덮어쓰지 않았습니다.

실제 ARM ELF의 LDS TLS는 80바이트, AA TLS는 196바이트이며 정렬은 4입니다.
LDS는 이전 76바이트에서 status word만큼 늘었고 pending 입력은 28바이트입니다.
별도 ARM compile-only object에서 Owned 256바이트·정렬 8, Snapshot 176바이트를
확인했습니다. 실제 차량 스레드의 스택 여유를 측정한 결과는 아닙니다.

| 제품 | SHA-256 |
|---|---|
| AA | `9e0d5b47e36daf8f01399190e5f60c98ff7b382654246b58206bdf24eb8300e5` |
| LDS | `35b43715089541a9988734cbf2db7fba8161f5cf0f156dc90f7069716e14a158` |

나머지 네 제품도 새로 빌드했으며 d66 제품과 바이트가 같습니다. 실제
ELF·공통 layout v3·새 사례의 host/ARM/DSO 등록은 별도 검토자가 대조했습니다.

## 원본 reader에서의 상태 전달

이전 [8입력 실행](LDS_RMC_INHERITANCE_2026-10-02.md)의 C++ 입력과 여덟
문장을 그대로 사용했습니다. 새 pin에 맞춰 작성한 호출기를 컴파일한 뒤,
기존 격리 IPC 환경에서 원본 reader·부분 AA 기동과 실제 두 제품을 한 번
실행했습니다. 별도의 compile-only 원본 실행이나 GDB 연결은 없습니다.

첫 launcher는 **종료 0, 19.103초**, client/server는 각각 0입니다. 위치·송신
9쌍, 원시 필드 81개, sideband 8개를 대조했습니다. 초기 관측 준비 중
연결 불가 3건과 현재 callback의 연결 성공 6건을 구분합니다. 아홉 송신의
원본 48바이트는 유지됐습니다. 원본 송신 반환은 기록했으며 별도의 명령어
계수나 caller 반환 뒤 errno 측정까지 수행한 것은 아닙니다.

| 관측 단계 | 캐시 쓰기 | MODE | HEADING의 RMC 상태 |
|---|---:|---:|---|
| A 기준 | 3 | 1 | a |
| 같은 GGA | 4 | 1 | a |
| V | 5 | 0 | v |
| 같은 GGA | 6 | 2 | v |
| 같은 GSA | 7 | 0 | v |
| 같은 GGA | 8 | 1 | v |

마지막 아홉 숫자가 A 기준과 같아져도 UTC·방위각·속도는 V 쓰기 5에서
상속됐고, HEADING에 묶인 `v`가 현재 POSITION·SEND·sideband까지 남았습니다.
각 단계는 실제 요청 식별자와 원본 응답, 같은 locked 사본으로 연결했습니다.
최종 MODE나 숫자 동등성을 통과 조건으로 강제하지 않았습니다.

실험 판정기의 작성 회귀 42개와 별도 검토 대조 7개를 실행했습니다.
첫 구현 전 실패 17개와 후속 독립 검토의 잘못된 승인 3개를 보존했습니다.
후자의 원인은 관측 prefix 시간 역행, 같은 쓰기의 baseline 상태 충돌,
최종 비교기의 알려진 상태와 HEADING 출처 분리였습니다. 최소 수정 후
42개·7개 모두 통과했고, 다른 최종 MODE의 정상 대조도 유지했습니다.
이 수는 제품 검사나 원본 실행 수에 포함하지 않습니다.

별도 검토자는 runner·판정기를 import하지 않고 monitor·원시 journal·입력
framing과 여섯 prefix를 직접 대조했습니다. 저장 원문 판독의 첫 실행은
종료 0이며 위 9쌍·81개 값·상태와 출처 상속을 확인했습니다. 별도 작성
대조 12개와 준비 중 오류 기록도 보존했으며 제품을 재실행하지 않았습니다.

동결 입력 21개, 실행 입력 177개와 추적 소스 441개의 전후 불변성을 확인했습니다.
새 실행의 원본 파일은 불변이며 소유 프로세스·IPC·채널·별칭을
정리했습니다. 이번 출력 107개 항목만 소유자를 복원하고 바이트·모드·mtime·
inode·링크 불변을 확인했습니다. 보조 AA 서비스와 monitor는 소유자가
종료했으므로 전체 OEM의 정상 종료를 확인했다고 표시하지 않습니다.

## 남은 범위

원본에서 직접 대조한 lexical 상태는 이 이력의 A/V입니다. empty·other·
unknown, 중첩·예전 read 복원 등의 작성 회귀를 모두 물리 수신기 시험으로
일반화하지 않습니다. A는 물리 품질·생산자 측정 시각이나 ASSIST 자격이 아닙니다.

전체 SM/AAPA 기동, 실차 자동 기동·복구, 물리 센서, 휴대폰·지도 앱 수용과
간헐적 epoch 요청 정체 원인은 여전히 미검증 또는 미해결입니다. live 자격
공급부와 ASSIST 활성화는 미구현이며 v1.0 완료로 표시하지 않습니다.
이 기록만으로 새 공개 ZIP이 발행되거나 차량 시험이 승인되는 것은 아닙니다.

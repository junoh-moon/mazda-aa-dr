# 오프라인 VARIANT 평가 — 휠차 vs 0x078 터널 heading (기록 전용) — 2026-10-31

**성격: 탐색, 오프라인, MODEL 전용, 송신 없음.** live 사용 전에 반드시 선행해야 하는
기록 전용·사전등록형 비교다. GPS 손실 구간 중 OSM 체인에 유일 매칭된 터널에서, 각 heading
방식의 체인 접선(GPS 없는 truth) 대비 RMS를 잰다. 각 변형은 진입 정렬 h0 하나만 적합하고,
0x078 oracle만 최적 상수 영점 z도 적합(live로는 불가능한 하한). 스크립트: 비공개
`private-data/yaw-analysis-20261010/variant_eval.py`. 입력 trip2/3/4. 좌표 없음.

## 변형

- `wheel` = h0 + ∫ slope·d01 dt (앞쌍, ε=0, 무보정)
- `wheel_eps` = h0 + ∫ slope·(d01 − ε·v) dt (고정 ε=0.05%, 전역 보정 1개)
- `yaw@2047` = h0 + ∫ −K·(raw−2047) dt (0x078, 기기 공칭 영점; live에서 현실적인 값)
- `yaw_oracle` = h0 + ∫ −K·(raw−z) dt (0x078 최적 상수 영점; live 불가능한 하한)

## 결과

깨끗한 매칭 터널(trip4 @2221.8, 접선 변화 14°, 주행 1576 m)의 접선 대비 RMS:

| 변형 | RMS(deg) |
| --- | ---: |
| wheel (무보정) | 8.64 |
| **wheel_eps (고정 ε)** | **2.59** |
| yaw@2047 (현실 0x078) | 8.11 |
| yaw_oracle (0x078 하한) | 2.17 |

곡선 터널(@2123.6, 접선 60°)은 모든 변형이 크고 oracle이 88°로 발산 → `r_oracle<10°` 게이트로
집계 제외(#4와 같은 marginal 매칭).

## 판정

- **고정 ε 하나를 넣은 휠 방법(2.59°)이 0x078의 하한(oracle 2.17°)에 1° 이내로 근접**하고,
  live에서 현실적인 0x078(@2047 8.11°)보다 크게 낫다. 이유: 0x078은 터널 안에서 자기 영점을
  알 수 없어 oracle에 못 가지만(작은 상수 영점 × 긴 적분 = 큰 오차, [[YAW_ZERO_STEPS_2026-10-31]]),
  휠+ε는 영점 적분이 없어 그 하한에 영점 지식 없이 도달한다.
- **무보정 wheel(8.64°)은 0x078@2047(8.11°)과 비슷 — ε 보정이 승부처다.** 그 ε를 GPS 없이
  얻는 경로가 지도 구속 ε([[YAW_WHEEL_DIFF_MAP_2026-10-31]]).
- **표본은 깨끗한 터널 1개뿐.** 고무적이나 결론은 아니다. live 자격에는 깨끗한 긴 터널 여러 개에서
  (1) ε 안정, (2) wheel_eps가 yaw@2047을 일관되게 능가, (3) 사전등록 안전 규칙(악화 0건, 포화·
  역주행·매칭 실패 시 fail-closed) 통과가 필요하다.

## live 사용에 대한 입장

지금 live 송신은 권하지 않는다(증거 1개 터널, ε 안정 미확정, 접선·GPS 참값 아님, AGENTS.md의
"미검증 실험 기본 OFF"·"사전등록 안전 규칙 없이는 제품 변경 없음", 소유자의 기본값-전용 운용).
올바른 첫 "사용"은 이 VARIANT 평가를 받는 주행마다 자동으로 돌려(로깅 변경 불필요: 휠·yaw 이미
기록) 증거를 쌓는 것. 조건 충족 후에만 SHADOW→BETA로 좁게 승격한다.

GPS는 정확도 참값이 아니다. 이 기록은 설계 변경·실차 승인이 아니다.

# 원본 커널 VM의 USB 전원 GPIO 되읽기 — 2026-10-01

기준 master는 `55bdd8feb44ec6a721f05883aef8fd62be0906e8`입니다.
외부 `feat/session-observation`의 `e2c31c5` 기록은 원본 USB 관리자가 두
전원 GPIO에 `1`을 쓰는 데 성공해도 후속 읽기는 `0`이며, LDS가 수신기 선택
대기를 반복한다고 보고했습니다. 외부 실행의 비공개 r11 이미지·원본 로그는
이 작업 공간에 없으므로 그 동적 전이를 root가 재실행했다고 세지 않습니다.

root는 이 현상을 분리하려고 동일 SHA-256
`57fe0cda7c1f994a6ca6b3cce7d9cf247f3b5607ebf1ddc12f02598662d5e240`
원본 커널과 보존된 rootfs를 격리 QEMU `sabrelite`에 부팅했습니다. 원본 서비스나
제품 preload 대신 비공개 GPIO 진단 PID 1만 실행했습니다. 네트워크·호스트
장치·공유 디렉터리는 연결하지 않았고, 커널은 변경하지 않았습니다. CMU 진입의
machine ID 레지스터만 기존 하네스 방식으로 설정했습니다. QEMU는 Debian
7.2.22입니다.

두 실행 모두 진단 완료 표식에 도달했습니다. 첫 실행은 쓰기 직후 sysfs 0을
재현했습니다. 둘째 실행은 출력 방향·active-low와 같은 순간의 GPIO 레지스터를
추가로 읽었습니다. 두 이름은 원본 SoC GPIO 은행에 속하며 JCI 가상 GPIO
모듈의 핀이 아닙니다.

| 핀 | 방향 / active-low | `1` 쓰기 | 쓰기 뒤 DR / GDIR / PSR 비트 | sysfs 되읽기 |
| --- | --- | --- | --- | --- |
| `DO_OTG_PWR` | out / 0 | 성공 | 1 / 1 / 0 | 0 |
| `DO_HOST1_PWR` | out / 0 | 성공 | 1 / 1 / 0 | 0 |

쓰기 **전** DR은 읽지 않았으므로 이 시험만으로 쓰기가 latch를 0→1로 바꿨다고
말하지 않습니다. 쓰기 뒤 출력 latch가 1인데 sysfs가 0을 돌려준 사실은 직접
확인했습니다. [QEMU v7.2.22 원본 GPIO 구현](https://gitlab.com/qemu-project/qemu/-/raw/v7.2.22/hw/gpio/imx_gpio.c)은
PSR 읽기에서 출력 방향 비트를 가리고, DR 읽기는 출력 방향에서 latch 값을
선택합니다. 관측 결과는 이 모델과 일치합니다. 배포 QEMU의 해당 함수 바이트와
원본 커널 `gpio_get` 바이트까지 대조한 것은 아니므로 읽기 경로의 유일한
내부 원인으로 단정하지 않습니다. 실제 i.MX6 패드의 되읽기 결과도 여기서
결정할 수 없습니다.

root는 정확한 원본 `svcjcilds.so`의 함수 경계를 별도로 읽었습니다. LDS가
참조하는 전원 경로는 `DO_OTG_PWR` 하나이며, USB 관리자는 두 핀을 모두
참조합니다. LDS의 대기 경로는 OTG sysfs의 첫 글자가 `1`인지 검사하고,
아니면 대기 횟수를 되돌리고 재시도 이벤트를 등록합니다. 이는 정적 실행
조건의 확인이지 이번 두 VM에서 원본 LDS 함수가 실행됐다는 주장이 아닙니다.
두 GPIO가 출력이고 위의 0 되읽기가 유지되는 이 VM 조건에서는 해당
legacy 선택 경로가 통과할 수 없습니다. 외부 r11의 전체 중단을 이 조건
하나만으로 설명하거나, 빈 USB 목록·SYSTEM thermal 전환·이후 직렬 경로를
해결했다고 보지 않습니다.

Claude Code에 외부 기록과 직접 계측값을 두 차례 읽기 전용으로 검토시켰습니다.
Claude는 LDS가 OTG만 참조한다는 점과 DR/GDIR/PSR 대조 필요성을 지적했고,
두 번째 검토에서는 이 VM의 되읽기 차단을 독립적으로 해석했습니다. 그 세션은
권한 제한으로 원본 역어셈블과 VM 실행을 직접 수행하지 못했습니다. 따라서
동적·정적 직접 실행 근거는 위 root 실행에 한정합니다.

다음 오프라인 단계는 동일 원본 SM·SYSTEM·USB·LDS 구성에서 실제 DR을
계측하며, **진단용으로만** 출력 latch의 되읽기를 LDS에 반영하는 비교 실행을
설계하는 것입니다. 이는 에뮬레이터 하드웨어 가정을 바꾼 실험으로 명시해야
하며, 원본의 무수정 성공이나 물리 수신기 자격으로 세면 안 됩니다. 이어서
원본 LDS의 직렬 open/read, NMEA 파서, 유효·무효·복귀 GetPosition을 각각
확인해야 합니다. 외부 r11 전용 fixture가 이 작업 공간에 없어 아직 이 실행을
재구성하지 않았습니다. 생산 코드·설치기·ASSIST·공개 ZIP은 변경하지 않았고,
제품 코드 변경이 없어 `make test`와 ARM 제품 검사는 이번 기록에서 반복하지
않았습니다. 차량·폰 검증은 없습니다.

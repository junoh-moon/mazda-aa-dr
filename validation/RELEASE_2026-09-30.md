## 실제 OEM 실행의 범위

최종 ZIP에서 별도 비공개 initramfs를 만들고 순정 Linux 3.0.35와 원본 OEM
라이브러리·서비스를 격리된 QEMU 7.2.22 Sabrelite에서 실행했습니다. CMU
machine ID는 커널 진입의 r1만 조정했고 커널 바이트를 수정하지 않았습니다.
네트워크·호스트 장치·공유 디렉터리를 VM에 연결하지 않았습니다.

진단 PID 1과 standalone OEM service launcher를 사용했습니다. 정상 전체
OEM init 기동의 완료로 보지 않습니다. 실제 AA 후크 install=ok, health 53개,
SHADOW 행 411개와 collector의 별도 UID·종료를 확인했습니다. VBS에서 API,
VIM, CAN 원본 파일 검사와 비차단 datagram socket 생성이 관찰됐습니다.
원본 AddClient 반환값과 첫 센서 callback은 직접 확인하지 않았습니다.

센서 이벤트는 0개, MODEL 위치는 모두 무효이고 위치 poll도 실패했습니다.
160초 제한 종료는 관찰 종료이며 PASS 조건이 아닙니다. 물리 센서·CAN peer,
실제 폰·무선 AA·네이버 지도, watchdog 재부팅·전원 차단 복구는 미검증입니다.
이전 SM retry 실험은 [별도 기록](SM_RETRY_2026-09-29.md)을 따릅니다.

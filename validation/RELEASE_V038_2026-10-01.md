최종 ZIP은 순정 ARM BusyBox/libc 환경에서 설치·일회성 기동 보호·숫자 메뉴·

입력 로그는 작성한 조건이며 OEM 서비스나 차량을 실행한 검사가 아닙니다.

## 실패 재현과 최종 결과의 구분

구현 전에 실제 지연 큐→formatter에서 식별자 누락으로 exit 1, 최대 ID
formatter assertion으로 exit 134를 확인했습니다. 원본 연결 분석의 새 회귀도
수정 전 18개 검사·42개 assertion 실패로 시작했습니다. 일반 terminal의 불가능한
ID와 신규·과거 overflow의 잘못된 시간 분류도 각각 실패를 확인한 뒤 보완했습니다.

수정 전 소스의 실제 host worker 회귀는 기록의 새 키 누락으로 exit 134였고,
수정 후 같은 시나리오는 exit 0이었습니다. 회수 로그의 연결 결과는
`matched=1`, `no_reference=5`입니다. fixture의 설치 미실행, 작성한 bus 전환·
단절과 LOCATION 송신 표본 부재 때문에 전체 분석은 `inconclusive`/exit 2로
유지합니다. BEGIN 한 건의 연결을 GPS 비교 성공이나 차량 완주로 세지 않습니다.

추가 journal Python 시도 한 번은 오래된 workspace `build/test_journal`을
사용하여 123개 검사에서 실패 3건·오류 21건으로 끝났습니다. 직접 출력도
새 위치 출력 옵션 미지원, 6행 대신 5행·`wire` 누락, 이전 MODEL fixture 이름을
확인했습니다. 이 실패를 보존하며 위 **clean 고정 빌드의 최종 전체 통과**와
구분합니다. 실패를 숨기도록 검사·펌웨어 조건을 낮추지 않았습니다.

## 공개 파일 확인과 도구 정리

공개된 ZIP과 `.sha256` 두 첨부 파일을 다시 내려받았습니다. 시험한 후보와
바이트 단위 일치, SHA-256·CRC·전체 manifest·87개 소스 입력·다섯 산출물·
SHADOW 기본값을 대조했습니다. 원격 annotated tag는 위 소스로 해석되며,
GitHub 기록은 `isDraft=false`, `isPrerelease=true`입니다.

주 검증 컨테이너를 제거하면서 그 안의 추가·갱신 패키지 79행과 고정 도구체인
2,124개 파일, 원본 임시 추출본·clean checkout을 제거했습니다. 최종 ZIP
검사 전용 binfmt entry·host QEMU 복사본·helper도 제거했습니다. 최종 호스트
패키지 2,963개·이미지 11개·컨테이너 0개, binfmt 목록과 상세 설정이 작업
시작 시점과 같습니다. 기존 이미지·사용자 펌웨어 archive·검증 산출물은
보존했습니다. 호스트 패키지를 설치하거나 `sudo`를 실행하지 않았습니다.

호스트 baseline 사본과 실패한 worker-session 자료를 삭제하려던 작업은
자동 승인 검토가 거부했습니다. 보존 가치가 있는 실행·검증 증거의 영구 삭제
가능성이 있고, 추가 설치 도구 정리 승인이 그 삭제까지 명시적으로 포함하지
않는다는 사유였습니다. 삭제를 우회하거나 재시도하지 않고 증거를 보존했습니다.
이 자료는 추가 설치 도구가 아니므로 도구 제거 완료와 구분합니다.

비공개 근거는 `evidence/holdout-reference-20261001/`의 `release/`,
`release-check/`와 최종 정리 기록에 남겼습니다. 공개 문서·설치 ZIP에 OEM
바이너리·맵·역어셈블리·개인 경로나 실차 로그를 포함하지 않았습니다.

live qualified 입력 공급부, 개별 필드의 물리 생산 시각·센서 자격, 전체 차량
기동·복구·폰과 지도 앱의 보정 수용은 미구현 또는 미검증입니다. 로그 저장
상한과 여유 공간 정책은 유지하지만 보관 가능한 주행 시간은 실제 입력 주기
없이 보장하지 않습니다. 관측 ID 연결·MODEL 계산·합성 ASSIST 송신 검사를
실제 관성항법 적용 완료나 v1.0 완료로 표시하지 않습니다.

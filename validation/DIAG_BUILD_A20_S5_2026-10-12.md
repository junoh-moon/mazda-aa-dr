# A20/S5 터널 진단 BETA 후보 — 2026-10-12

> **진단 버전 2로 대체되었습니다(2026-10-12, [TUNNEL_REPORT_CAP_2026-10-12.md](TUNNEL_REPORT_CAP_2026-10-12.md)).** 다음 빌드부터 A20과 S5 군은 배정되지 않고, S5의 위성 수 재작성 코드는 어댑터에서 삭제되었습니다(type 21은 관측만 하고 원본 그대로 전달). 블록은 `{CONTROL, CAP, CAP}`이며 CONTROL은 상한 없음(40 m), CAP은 제품 상한 25 m입니다. 진단 표식이 없으면 모든 에피소드가 25 m 상한을 씁니다. 분석기는 이 기록의 beta.12 행(`CONTROL/A20/S5`, `cap_m` 20, `sat_in_use` 5)을 계속 읽습니다. 아래 내용은 beta.12 로그를 해석하기 위한 기록으로 남깁니다.

대상은 1세대 Mazda Connect **NA 74.00.324A**, `576302549cd8ee366e72b3f1e2b1bcaadfac7feb` 위의 진단 변경입니다. **v1.0.0-beta.12 후보 기록이며 실차 검증 결과가 아닙니다(발행 사실은 RELEASE 기록 참조).** 이 기록의 분석기·문서 작업은 별도의 스크래치 사본에서 수행했습니다. C++ 제품 빌드·ARM 검사·표식 부재 동일성 결과는 아래 TODO로 남깁니다. 자격 ASSIST는 계속 비활성입니다.

## 문제와 후보

실차에서는 터널에 따라 회색 GPS 아이콘과 속도 고정의 조합이 달랐습니다. 위치 대체 로그의 속도는 변했지만 폰 수용은 입증되지 않았습니다. [wire 조사](TUNNEL_WIRE_FIELDS_2026-10-11.md), [DHU 실험 11](DHU_NAVER_EXP11_RESULT_2026-10-11.md), [v4 반복](DHU_NAVER_EXP11_V4_RESULT_2026-10-11.md)을 근거로 다음을 분리하십시오.

| 후보 | 남은 설명 | 이번 조작과 구분 한계 |
| --- | --- | --- |
| S | GPS_SATELLITE 위성 수 0 또는 단절 첫 순정 메시지가 폰의 상태를 바꿉니다. | DHU의 `gps_satellite` 명령 미지원으로 미시험입니다. S5는 대체 LOCATION **뒤**의 위성 수만 바꿉니다. |
| A | 보고 정확도와 횡방향 위치 편차의 조합이 폰의 채택·회색 표시를 바꿉니다. | DHU에서 40 m 단독은 재현되지 않았고, 정확도 램프와 증가하는 횡오프셋의 조합은 세 번 회색 표시를 만들었습니다. A20은 좌표 계산을 유지한 채 보고 정확도만 낮춥니다. |
| W | 실차 무선 AA 동글 경로가 DHU 유선 경로와 다릅니다. | 이번 세 군 모두 같은 경로를 사용하므로 직접 분리하지 못합니다. |
| P | 폰 자체 GNSS의 실제 수신 상태·융합이 다릅니다. | 이번에는 폰 GNSS를 통제하거나 직접 관측하지 못합니다. |

DHU에서 **속도 고정은 재현되지 않았습니다.** A20 선택은 정확도 정책 개입을 작게 분리하기 위한 것이며 20 m가 실제 오차라는 주장이 아닙니다. S5의 5는 순정 mode 1의 고정 숫자와 같은 비교값이며 실측 위성 수가 아닙니다. wire timestamp는 평소에도 명시적 0이라는 선행 정적 근거가 있으므로 이 진단은 시각 전진을 추가하지 않습니다.

## type 21 구조에 대한 구현 전제

`src/adapter/adapter.h`의 구현자 주석은 정적 펌웨어 판독으로 다음을 확인했다고 기록합니다. **본 문서 작업자가 다시 판독하거나 OEM 코드를 실행한 결과가 아닙니다. 빌드 단계에서 재확인하십시오.** 다른 펌웨어로 일반화하지 마십시오.

| 필드 | 현재 코드의 전제 |
| --- | --- |
| sensor type / 전체 크기 | GPS_SATELLITE, type 21 / 정확히 864바이트입니다. |
| offset 0..3 | little-endian 32비트 `number_in_use`입니다. |
| offset 4..7 | `number_in_view` 존재 표지의 word입니다. 주석상 실제 소비자는 byte 4를 읽지만 재작성 조건은 word 전체가 0이어야 합니다. |
| 이후 | `number_in_view`와 위성 배열입니다. 진단은 offset 4부터 끝까지 그대로 복사합니다. |
| 순정 생성값 | mode 0에서는 864바이트를 0으로 만들고 위성 수 0, mode 1에서는 5를 설정한다는 정적 근거입니다. 실제 폰 구독·수신은 별도 확인 대상입니다. |

## 실험군과 눈가림

`<root>/diag`가 심볼릭 링크가 아닌 일반 파일이고 내용이 정확히 3바이트 `on\n`일 때만 진단을 요청합니다. worker 시작 때 한 번 읽으며 BETA 코어가 준비되어야 활성화합니다. 표식 부재·잘못된 종류·내용은 꺼짐입니다. USB 메뉴 9는 현재 상태와 숫자 재확인을 제공하고 실험군은 공개하지 않습니다. 변경 뒤 메뉴 5 재부팅과 메뉴 2 새 boot ID 확인이 필요합니다. 재설치·제거는 표식을 지웁니다.

| 군 | 배정 시 바뀌는 것 | 실제 적용 증거 |
| --- | --- | --- |
| CONTROL | beta.11의 LOCATION·위성 동작을 유지합니다. | `loc_replaced`, 보고 정확도 및 위성 전후값으로 기준 노출을 확인하십시오. |
| A20 | 기존 모든 정확도 규칙 뒤 보고 상한을 20 m로 낮춥니다. 정차 25 m 규칙과도 더 낮은 값이 우선합니다. 계산·honest 예산은 유지합니다. | `capped/pubs`는 **발행** 수치입니다. `send.diag.arm=A20`과 실제 outgoing LOCATION 정확도를 함께 보십시오. capped 발행만으로 capped 송신을 입증하지 마십시오. |
| S5 | 같은 POSITION 호출에서 하위 송신이 0을 반환한 BETA LOCATION 대체 뒤, 첫 적격 type 21의 `number_in_use`만 0→5로 바꿉니다. | `choice=5`, `diag.sat=applied`, `diag.in_use=[0,5]`, `presence=0` 및 `result`를 확인하십시오. `applied`는 하위 송신 선택이며 폰 수용이 아닙니다. |

부팅 ID와 3개 에피소드 블록 번호를 해시하여 여섯 순열 중 하나를 고릅니다. 부팅 내 매 3개 에피소드는 세 군을 한 번씩 포함하지만 실제 적용 수가 균형이라는 뜻은 아닙니다. `GPS_LOST` 진입에서 배정하고 `ENGAGED/WITHDRAWN` 동안 유지합니다. 그 밖의 상태에서 종료하며, 종료 후 **10초 미만**에 다시 끊기면 같은 인덱스·군으로 `continued`합니다. 매초 송신이나 이런 재연결을 독립 표본으로 세지 마십시오. 소유자는 군을 몰라도 되며, 주차 후 터널별 이름·방향·시각·가능하면 지속시간, 회색 및 속도 고정의 예/아니오/모름만 기록합니다.

## 로그와 분석 계약

- `diag_boot`: `active`, `reason`, `boot_id`, `arms`, `block`, `rejoin_ms`, `cap_m`, `sat_type`, `sat_length`, `sat_in_use`입니다.
- `diag_episode`: `event`는 `assigned/continued/ended`, 공통으로 `boot_id`, `episode`, `arm`, `reason`, `state`, `session_epoch`, `generation`을 남깁니다. 배정에는 `block/perm/cap_m/sat_in_use`, 계속에는 `gap_ms`, 종료에는 `open_ms`, `pubs/capped`, `honest_max_m`, `reported_min_m/reported_max_m`, `loc_replaced/loc_nonzero/loc_original_mode0`, `sat/sat_applied/sat_nonzero/sat_outcomes`, `first_sat`, 선택적으로 `withdrawn`이 있습니다. 종료 카운터는 이어진 에피소드의 **누적값**입니다.
- `send.diag`: LOCATION 대체는 `arm`, 위성 송신은 추가로 `sat`, `in_use` 전후 두 값, `presence`를 남깁니다. 짧은 payload의 숫자는 null입니다. 위성 행의 `arm=NONE`은 이 호출에 대체 LOCATION이 없었다는 기록일 수 있으므로 에피소드 배정 없음과 혼동하지 마십시오.

분석기는 부팅·기록 세션·에피소드별 배정, 종료된 open 시간, 누적 적용 수와 관측된 송신 수, honest 최대와 보고 정확도를 분리합니다. 첫 원본 mode-0 LOCATION, 위성 전후값·결과, 송신 속도 범위 변화와 표본상 속도 0 구간, 기존 GPS 복귀 비교도 연결합니다. `continued`의 종료 누적값을 더하지 않습니다. 과거 RAW-window 행은 flush 시점이 아닌 기록 시각으로 연결합니다. 종료 행·배정·원래 예산이 없으면 알 수 없음 또는 불완전으로 표시합니다. 순정 첫 행이 회수되지 않았다면 없었다고 단정하지 마십시오.

**축소된 보고 정확도를 honest 값으로 쓰지 마십시오.** 특히 A20의 GPS 복귀 비교는 `accuracy_honest_m`을 사용하며 없으면 honest 판정은 미상입니다. 에피소드 전체의 `honest_max_m`을 특정 GPS 복귀 시점의 예산으로 대체하지 마십시오. GPS 복귀 차이는 참값 오차가 아니고, 송신 속도 0 표본은 네 바퀴의 물리 정차 검증이 아닙니다. 진단 행이 없으면 JSON 키와 텍스트 절을 추가하지 않습니다.

## 표본 수와 남은 한계

군별 3~5개 터널은 탐색 수준입니다. 미리 정한 한 쌍 비교에서 **독립적인 불일치 짝 6개 모두가 같은 효과 방향**이면 양측 정확 부호검정은 `2 / 2^6 = 0.03125`입니다. 총 6개 터널이나 상관된 같은 주행의 6구간을 뜻하지 않으며, 군·지표 다중 비교 보정 전 수치입니다. 반복 통과·연속 에피소드의 부팅/폰 상태 이월, 길이·속도·정차·진행 방향 차이를 통제하지 못하면 독립성 가정이 성립하지 않습니다. 표본 수를 채우기 위한 추가 주행 승인은 아닙니다.

W(무선 동글)와 P(폰 GNSS)는 조작하지 않으므로 제외할 수 없습니다. 전화기/앱 버전과 표시 시각 대응, 실제 type 21 구독, 차량 센서 품질, preload 공존·전체 기동·복구, 첫 순정 메시지의 영향은 남습니다. 군 해시는 암호학적 비밀이 아니며 눈가림은 소유자 메뉴에 군을 표시하지 않는 절차입니다. 독립 심사나 합성 로그 통과는 실차·폰 검증을 대신하지 않습니다.

## 위험과 코드의 fail-closed 조건

**잘못된 type 21 재작성·버퍼 수명 가정은 AA 세션을 깨뜨리거나 CMU를 재시작시킬 수 있습니다.** 864바이트 정적 복사·원자적 점유가 실제 OEM의 포인터 보유 수명을 보장하는지 아직 이 작업에서 실행 검증하지 않았습니다. 하위 송신 호출 횟수는 정확히 한 번이고 원래 반환값·errno를 돌려주며, 호출자 wrapper/payload를 직접 고치지 않는다는 것이 코드 계약입니다.

`diag_satellite()`와 LOCATION 선택 코드를 기준으로 다음 거부 조건을 유지하십시오.

- 유효한 시작 표식·BETA 코어가 없으면 진단을 활성화하지 않습니다. S5 외의 CONTROL/A20에서는 위성 payload를 원본 전달합니다(`arm_control/arm_a20`).
- POSITION 문맥 없음, 재진입·중첩, 같은 호출의 성공한 S5 LOCATION 대체 없음, LOCATION 하위 송신 실패는 거부합니다(`no_context/nested/no_replacement/location_failed`). mode 0·LOST, BETA 출처, 준비된 snapshot, lease·나이·세대·source/session epoch, 세션 경계와 기존 hold/오류 검사도 먼저 통과해야 합니다.
- 같은 호출의 type 21 시도는 한 번만 허용합니다. 사용한 latch는 이후 거부 시에도 소진합니다(`exhausted`). 다른 storage·generation은 `context_mismatch`입니다.
- null payload 또는 864바이트가 아닌 길이는 `bad_length`, offset 4의 word가 0이 아니면 `bad_presence`, 원래 위성 수가 0이 아니면 `unexpected_value`입니다. 숫자를 읽을 8바이트도 없으면 기록값은 null입니다.
- 정적 복사 버퍼를 다른 호출이 점유하면 기다리지 않고 `busy`로 원본 전달합니다. 기존 adapter fault, BETA 이탈, 또는 이전 재작성 송신의 실패로 세운 sticky fault는 `disabled`입니다.
- 재작성한 하위 송신 결과가 0이 아니면 해당 **프로세스의 나머지 S5 재작성**을 막습니다. LOCATION의 기존 송신 실패 hold와 구분하십시오. 단순 거부는 원본 wrapper/payload를 그대로 전달하며 원본 송신 성공이 폰 수용이라는 뜻은 아닙니다.

모든 안전 규칙을 통과해도 동시성·실제 ABI·OEM가 반환 뒤 포인터를 보관하지 않는다는 전제의 검증은 별도입니다. firmware guard를 낮추거나 다른 owner의 슬롯을 덮어 검사를 통과시키지 마십시오.

## README paragraph to add

아래 문단은 `src/adapter/README.md`에 추가할 정확한 영문입니다. 해당 파일은 이 위임 작업에서 변경하지 않았습니다.

The diagnostic BETA build adds one explicit exception to the non-LOCATION forwarding contract, enabled only by the validated `<root>/diag` marker read at worker startup: in an S5 episode, the first GPS_SATELLITE attempt after a successful BETA LOCATION replacement in the same non-nested POSITION call may send type 21 (exactly 864 bytes) with `number_in_use` at bytes 0..3 changed from 0 to 5. The send storage and adapter generation must still match, the presence word at bytes 4..7 must be zero, and the bounded static copy must be available; all other bytes and the caller's wrapper/payload remain unchanged. Once an S5 latch reaches the rewrite checks, that attempt consumes it even if a check refuses; every refusal forwards the original. A nonzero result from a rewritten send disables further satellite rewrites for the process. The lower send is still called exactly once, with its return value and errno preserved; there is no dropped or extra send. CONTROL/A20 do not rewrite satellite payloads, and an absent or invalid marker keeps the beta.11 forwarding behavior. This is a diagnostic intervention, not a measured satellite count, qualified ASSIST, phone-acceptance evidence, or a vehicle-validated ABI contract; see `validation/DIAG_BUILD_A20_S5_2026-10-12.md`.

### 보충 2: 두 번째 독립 웹 조사(Fable)가 더한 가설과 근거 (beta.12 데이터 전)

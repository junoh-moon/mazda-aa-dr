# 원본 AA 호출의 계산 위치 선택 — 2026-10-01

NA 74.00.324A의 원본 LDS·BLM·AA 로컬 호출 경로에서 계산 위치가 실제
`aap_send_vehicle_data`의 인자로 선택되는지 시험했습니다. 별도 작성한
오프라인 실행 파일이 기존 core·bridge·adapter·설치/관측 코드를 연결합니다.
**제품 `runtime.cpp`와 제품 preload DSO는 실행하지 않습니다.** 실제 제품의
live ASSIST 연결이나 Galaxy S25·네이버 지도의 수용 완료로 세지 않습니다.

## 시험 경계

소스는 `5d9a863749f4630058edb3522635ad2c90640a44`에 고정했습니다.
후속 `86b046b`의 외부 GPIO 진단 통합은 문서 변경이며 실행 소스는 같습니다.
GCC 4.9.1·기존 원본 커널과 [두 핀의 실험용 GPIO 모델](LDS_GPIO_2026-09-30.md)을
사용합니다. 원본 파일 해시·ELF·진입 명령과 cold install 검사는 유지했습니다.
호스트 장치·네트워크·공유 디렉터리는 VM에 연결하지 않았습니다.

원본 LDS는 PTY에 공급한 NMEA를 파싱하고 유효→무효→재수신 응답을 만듭니다.
원본 BLM manager가 요청·callback·worker 큐·AA 송신을 실행합니다.
시험 core는 이 응답의 mode 전환을 보고 **별도 작성한 기준점과 정규화 입력**을
사용합니다. 기준점은 위도 35°·경도 135°·방위 0, 속도 10m/s·yaw 0.1rad/s의
곡선입니다. 원본 GPS의 시각·위치를 qualified 기준점으로 승격한 시험이 아닙니다.
VBS 센서부터 정규화까지의 제품 경로도 이번 실행 범위에 포함하지 않습니다.

작성한 호출기만 source/session epoch와 producer time·센서/보정 자격을
합성 조건으로 지정하고 `allow_assist=true`를 사용합니다. 제품 설정·출시 파일과
live 자격 조건은 변경하지 않았습니다. 입력, 시각, 출처가 실제 차량에서
검증됐다는 뜻이 아니며 호출기는 차량에 설치할 파일이 아닙니다.

자격 거부 조건은 계산·발행이 진행돼도 원본을 유지했습니다. LOCATION마다

각 양성 실행의 첫 mode-0 송신은 해당 generation의 후보가 없어 원본이었습니다.
MODEL 대조는 유효 MODEL 계산 결과라도 bridge가 qualified 결과로 변환하거나
발행하지 않음을 확인했습니다. 두 음성 조건의 26개 LOCATION은 모두 원본과
같았습니다. 같은 호출기의 세 실행에서 작업 6개씩의 시작·완료도 확인했습니다.

독립 검증기는 core의 적분 구현을 재사용하지 않고 WGS84 연속 운동식을
1ms 간격 RK4로 풀며, 평면 이동과 방위는 원호 해석식과 비교합니다.
완료한 네 실행의 최대 좌표 수치 차이는 `6.34e-8 m` 미만입니다. 이 값은
같은 합성 입력의 수치 일치이며 물리 위치 정확도 수치가 아닙니다.

최초 자격 거부 실행은 계산·송신 대조에 들어가기 전 `queue_task_completion`에서
실패했습니다. 당시 로그는 큐 작업의 미시작과 초기화 함수 안의 대기를 구분하지
못합니다. 원본 큐·초기화 함수를 살핀 뒤 작성 호출기에 작업 post/start/완료
관측과 실패 시 제한된 `/proc` 진단을 추가했습니다. 기존 10초 기한·원본 함수와
시험 동작은 유지했습니다. 후속 실행에서 재현되지 않았지만 **원인 미분리이며
수정 완료나 전체 기동 안정성으로 세지 않습니다.** 실패한 실행도 보존합니다.

## 송신 버퍼 수명 검토

같은 원본 `libaap_interface.so`에서 심볼·ARM PLT relocation·호출 인자를
대조했습니다. 원본 `aap_send_vehicle_data`는 입력 payload를 로컬 메시지로
복사하고, 하위 `comm_create_send_req`는 이를 할당한 메시지로 복사합니다.
IPC 함수는 다시 내부 전송 버퍼로 복사한 뒤 원본 SysV `msgsnd`를 호출합니다.
따라서 조사한 경로는 adapter의 임시 replacement 버퍼를 API 복귀 전에
복사합니다. 원본 반환값을 보존하는 기존 스택 버퍼 계약을 지지하는 정적 근거입니다.
덤프·주소 표와 OEM 바이너리는 비공개 증거에만 보존합니다.

하위 API 반환 0은 로컬 송신 경로의 결과입니다. 실제 AA 서비스의 정상 연결,
폰 위치 제공자나 지도 표시를 증명하지 않습니다. 원본 서비스는 USB 초기화
실패·미시작 세션의 요청 거절을 기록했고 종료 시 thread cancel 오류도 있었습니다.
호출기 종료 0을 전체 서비스 정상 동작으로 해석하지 않습니다. 원본 전체 차량 기동·센서의
생산 시각/물리 품질·요청별 provider/receiver/session 자격과 복구 조건은 남습니다.
이번 계산 선택 시험과 앞선 제품 MODEL 시험을 하나의 검증된 제품 ASSIST
경로처럼 합치지 않습니다. [v1.0 완료 조건](../docs/V1_READINESS_KO.md)은 유지합니다.

## 검사·증거·정리

QEMU 재빌드의 qtest 7개를 통과했습니다. 제품 소스는 변경하지 않았으므로
이번에는 전체 `make test`와 제품 ARM suite를 재실행하지 않았습니다.
같은 소스의 [직전 전체 검사](PIPELINE_MERGE_2026-10-01.md)와 이번 작성 실행
파일의 고정 ARM 빌드·원본 VM·독립 계산 검사를 구분합니다.

다섯 실행 모두 helper의 제한 종료 124·QEMU 종료 0과 guest 완료·공급기 종료
0을 확인한 뒤 로그 해시를 고정했습니다. 최초 자격 거부의 호출기 91은 실패로
남겼고, 나머지 네 실행은 호출기 0과 독립 검사 통과를 확인했습니다. 제한 시간
종료 자체를 PASS로 세지 않습니다.

비공개 경로는 `evidence/assist-runtime-20261001-5d9a863/`입니다.
종료된 실행의 자료 **56개·437,500,301바이트**를 복사 전후 해시로 대조해
보관했습니다. 최초 실패·작성 코드·독립 검증기·관측 원본을 비공개로 보존합니다.
추가 패키지 **104개**·갱신 **6개**, 도구체인·QEMU archive/소스/빌드와 전용
컨테이너·임시 폴더를 모두 제거했습니다. 호스트 패키지·이미지·컨테이너 목록은
작업 전과 같으며 기존 base 이미지는 보존했습니다. 호스트 설치나 `sudo` 실행은
없었습니다. 같은 작업 브랜치에서 fetch·pull을 반복했고 공개 ZIP은 바꾸지 않았습니다.

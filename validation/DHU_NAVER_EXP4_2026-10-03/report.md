# Android Auto DHU 실험 4: 위치 정확도 수용 경계

실험일: 2026-10-03 (Asia/Seoul). 다른 LLM이 재검토할 수 있도록 관찰과 추론을 구분합니다. 구조화 증거는 `evidence.json`입니다.

## 환경과 범위

- Galaxy S25 SM-S931N, Android 16; 네이버 지도 6.10.0.16; Android Auto 17.7.663654-release.
- macOS 15.8 arm64; DHU 2.0-mac-arm64, build 2022-03-30-438482292; ADB 37.0.1; command-line tools 23.0.
- 유효 시험은 모두 ADB 포워딩 TCP 5277을 사용했습니다. USB 액세서리(AOA) 연결은 초기 연결 문제 해결 때만 사용했습니다.
- 휴대전화의 앱 위치 권한은 변경하지 않았습니다. 실내 조건이며 이번 실험에서는 실제 GPS 수신 강도를 별도 측정하지 않았습니다.
- 실험 3에서 OSM으로 생성한 해운대해변로→미포항 경로(약 2.52km)를 재사용했습니다. 네이버의 초기 남은 거리는 2.4km였습니다. 처음 420m/840m를 각각 고정 정확도/램프 시험에 사용했습니다.
- 각 회차 전 DHU와 안내를 재시작하고, 정확도 5m·속도 0의 출발 좌표를 보낸 뒤 파란 화살표와 2.4km 안내를 직접 확인했습니다.
- 고정 정확도 시험: 14m/s, 1Hz, 30초. 0·10·20·30초 화면을 저장했습니다. 램프: 14m/s, 1Hz, 60초. 요청보다 촘촘한 1초 간격으로 화면을 저장했습니다.
- 각 촬영은 해당 초의 위치 명령 전송 후 약 0.2초에 요청했습니다. 화면 렌더링 지연이 있으므로 명령 시각·사진 시각·내부 위치 수용 시각을 동일시하지 마십시오. 명령 시각은 호스트 기준이며 센서 메시지 안의 타임스탬프는 측정하지 않았습니다.

## A. 고정 정확도

무작위 순서는 Python `random.Random(20261004)`로 A 목록을 먼저 섞고 이어 램프 목록을 섞어 정했습니다. 실제 순서는 아래 표와 같습니다.

|---|---|---|---|---|---|---|
| 1 | A70-r1 | 70m | REJECTED | 2.4→2.4→2.4→2.4km | 0 유지 | 0초 파랑, 10초부터 회색/위성-X |

각 정확도에서 두 번의 판정이 일치했습니다. 시험한 고정값 중 가장 큰 추종값은 **40m**, 가장 작은 거부값은 **50m**입니다. 따라서 이 실험이 직접 좁힌 전환 구간은 **40~50m**이며, 내부 임계값이 정확히 어느 실수 값인지 증명한 것은 아닙니다. 모든 값이 같은 결과가 아니므로 요청의 조건부 35m/90m 확장은 필요하지 않았습니다.

40m의 화면상 약 400m/30초는 약 13.3m/s로 주입 14m/s(420m)와 대체로 부합합니다. 화면 거리는 0.1km로 반올림되므로 이 차이를 정밀 위치 오차로 해석하지 마십시오. 거부 회차의 회색 표시 출현 구간은 (0,10]초입니다. 마지막 유효 준비 좌표와 본시험 사이의 시간은 회차마다 다르므로 이 표시 지연을 내부 수용 임계값으로 사용하지 않습니다.

## B. 증가하는 정확도

공식은 `A(t)=10+(끝값−10)×t/60`이며, t=0~60초에 각각 위치를 보냈습니다. 실제 순서는 다음 표입니다. 아래 정지 구간은 **화면의 거리 안내가 더 이상 갱신되지 않기 시작한 구간**입니다. 내부에서 마지막으로 수용한 위치 메시지의 시각은 아닙니다.

| 순서 | 회차 | 정확도 램프 | 거리 표시 정지 구간 | 그 구간에 주입한 정확도 | 첫 회색/위성-X 화면 | 그때 주입한 정확도 | 60초 화면 전진량 |
|---|---|---|---|---|---|---|---|
| 11 | R60-r1 | 10→60m | 48~49초 | 50.00~50.83m | 57초; 직전 56초는 파랑 | 57.50m | 약 600m, 2.4→1.8km |
| 12 | R100-r2 | 10→100m | 28~29초 | 52.00~53.50m | 37초; 직전 36초는 파랑 | 65.50m | 약 400m, 2.4→2.0km |
| 13 | R100-r1 | 10→100m | 28~29초 | 52.00~53.50m | 37초; 직전 36초는 파랑 | 65.50m | 약 400m, 2.4→2.0km |
| 14 | R60-r2 | 10→60m | 48~49초 | 50.00~50.83m | 57초; 직전 56초는 파랑 | 57.50m | 약 600m, 2.4→1.8km |

전부 처음에는 주입 좌표를 따라 이동했고, 이후 거리가 멈추고 GPS 손실 표시가 나타났습니다. 같은 램프의 두 반복에서 판정·정지 구간·첫 회색 화면 시점이 일치했습니다. 60초 전체 궤적을 따랐다면 주입 거리는 840m입니다. 표시 속도는 이동 중 50km/h로 바뀐 뒤, 위치가 멈추고 회색이 된 뒤에도 50km/h로 남았습니다. 속도 표시만으로 좌표 추종을 판정하면 안 됩니다.

### 정지 시점의 근거

- R100 두 회차: 가까운 안내 거리가 26·27·28초에 143→129→115m가 된 뒤, 29~60초에도 115m로 유지됐습니다. 28초 뒤 지도 애니메이션이 조금 더 움직이고 약 31초부터 비교 영역의 픽셀 변화가 0이 됐습니다.
- R60 두 회차: 카메라 안내 거리가 46·47·48초에 595→581→567m가 된 뒤 567m로 유지됐습니다. 48초에 가까운 안내 21m/다음 회전 925m가 보이고 이후 유지됐습니다. 미세한 지도 애니메이션은 약 52초까지 안정화되었습니다.
- R60의 가까운 안내와 다음 회전 거리 문구는 일부 프레임에서 서로 다른 갱신 지연을 보였습니다. 예를 들어 r2의 47초 화면은 가까운 안내 49m, 다음 회전 939m였습니다. 이 차이를 숨기거나 개별 센서 메시지와 일대일 대응시키지 않았습니다.
- 보조 코드로 지도 영역 픽셀 변화와 화살표 영역의 파란 픽셀 수를 측정해 전환 후보를 찾은 뒤, 전후 원본 화면을 직접 판독했습니다. 픽셀 통계는 내부 위치 수용 판정기가 아닙니다. 1초 간격 원본과 통계 모두 보존했습니다.

### 고정값과 램프의 비교

고정 정확도에서는 40m를 따르고 50m부터 거부했습니다. 램프의 화면상 추종 중단은 당시 입력 정확도 약 50~53.5m에서 보였습니다. 이는 **약 50m 부근에서 수용이 끊기고 처리·렌더링 지연 후 화면이 멈추는 설명과 부합**합니다. 다만 내부 센서 수용 시각을 관찰하지 않았으므로 램프의 내부 한계가 고정값과 정확히 같다는 사실까지 확정할 수는 없습니다. 40~50m 사이의 고정값은 시험하지 않았습니다.

회색 표시가 처음 나타날 때의 입력값은 57.5m와 65.5m로 서로 달랐습니다. 그러나 두 경우 모두 화면 거리 갱신이 멈춘 뒤 약 8~9초 후였습니다. **이 차이를 곧바로 정확도 상승 속도에 따라 수용 한계가 바뀐 증거로 해석하면 안 됩니다.** 이번 결과에서 가장 확실한 것은 고정값 40m의 추종, 50m의 거부, 그리고 추종 중단과 GPS 손실 표시 사이의 지연입니다.

## 예외, 오류, 재시작

- 초기에 ADB가 `unauthorized`였고, 휴대전화 재연결·USB debugging 토글·ADB 재연결/서버 재시작 뒤에도 승인 창이 나타나지 않았습니다. 공식 USB 액세서리 연결을 시험하여 DHU 연결에 성공했고 이후 ADB도 authorized로 바뀌었습니다. 승인 상태가 바뀐 직접 원인은 단정하지 않습니다.
- USB 액세서리 연결을 닫을 때 기존 ADB 포워딩이 사라져 첫 ADB 시작에 실패했습니다. 포워딩을 다시 만들고 연결을 복구했습니다. 이 준비 과정은 유효 14회 시험에 포함하지 않았습니다.
- 종료된 DHU 프로세스에 쓰기를 시도해 제어기에 `Broken pipe`가 났습니다. 살아 있는 프로세스인지 검사하도록 수정하고 제어기를 재시작했습니다. 본시험 전의 오류입니다.
- 모든 유효 시험 전 DHU를 재시작했습니다. R100-r1 준비에서는 자동 안내 재개가 실패했습니다. 최근 목적지에서 미포항을 다시 선택하고, 12개의 추가 정지 좌표를 보낸 뒤 파란 화살표·2.4km 경로를 확인하고 시작했습니다. 이때 초기 실제 위치 화면은 공유에서 제외했습니다.
- 경로 재탐색 알림이 나온 회차에서는 보이는 닫기 버튼을 눌렀습니다. 본시험 시점에는 경로와 위치가 확인됐습니다.
- 이전 실험의 예상 이름으로 준비 파일을 읽으려다 파일 없음이 발생했습니다. 이전 명령 시각 로그에서 정확한 준비 명령을 회수했습니다.
- SDK 23.0의 `sdkmanager`는 사용 중단 예정 경고를 출력하고 Android CLI를 자동 설치했습니다. 작업 폴더 밖의 자동 생성 파일도 설치 목록과 정리 대상에 추가했습니다.
- 보조 이미지 분석에서 Pillow `getdata` 사용 중단 예정 경고가 한 번 발생하여 새 API로 변경했습니다. 입력 명령이나 원본 사진에는 영향이 없습니다.
- 초기 USB 액세서리 준비 로그에 `Ping timeout` 경고가 2회 있었습니다. 유효 ADB 시험에는 `Audio stream already playing` 오디오 경고가 있었으며, 위치 명령 오류는 발견하지 못했습니다. 오디오 경고를 위치 수용의 증거로 사용하지 않습니다.
- DHU 출력 원문과 제어기 시작·종료·오류·입력 시각은 `logs/`와 `commands-timed.jsonl`에 보존했습니다. 개인 경로와 장치 식별자는 치환했습니다.

## 자료와 한계

`evidence.json`은 14개 회차의 정확한 명령, 정확도/좌표 궤적, 관찰, 사진 참조, 환경, 실행 순서를 담습니다. 고정 시험 사진은 10초 간격, 램프 사진은 1초 간격이며 준비 사진을 포함해 총 298장입니다. `methods/`는 실행 당시 보조 코드이며, SDK와 원래 작업 폴더 구성이 없는 상태에서 바로 실행되는 독립 앱은 아닙니다.

실제 Mazda 차량·무선 동글·차량 타임스탬프·NAN 전송 표현은 이번 범위에 없으며 확인하지 않았습니다. 정확한 내부 필터 구현, 수신 메시지별 수용 여부, 처리 지연의 분해도 확인하지 않았습니다. 이번 결과는 명시한 버전의 네이버 지도+Android Auto+DHU 조합에 대한 화면 관찰입니다.

## 정리

네이버 안내·DHU·ADB를 종료하고 임시 작업 폴더 약 494MB와 작업 폴더 밖 자동 생성 파일 177개를 삭제했습니다. 휴대전화 임시 UI 파일도 삭제했습니다. 휴대전화 서버 중지·USB debugging 해제의 사용자 확인 상태와 개별 삭제 내역은 `cleanup.json` 및 `install-cleanup.md`에 기록했습니다.

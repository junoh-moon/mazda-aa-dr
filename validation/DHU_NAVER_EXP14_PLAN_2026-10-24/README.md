## 판정 표(회차마다 evidence.json에 미리 정한 라벨만)

A계열:
- `G-FOLLOW` — G0에서 `ARR-FOLLOW`이고 G37·G84·G171에서 화살표/지도가 델타만큼 다르게 보임 → **앱이 방위 필드를 표시에 쓴다**; 각 델타의
  화면 오차(±°)를 기록. 소유자 수용 판단의 근거는 "최대 델타에서 화면이 얼마나 틀려 보이는가"입니다.
- `G-POSONLY` — G0·G37·G84·G171의 화살표가 모두 같음(진행 방향/경로 접선) → 앱이 방위를 표시에 쓰지 않음 → **이월 방위의 화면 손실은
  이 앱 버전에서 0**으로 관찰(단, 다른 앱·버전에 일반화 금지).
- `G-MIXED` — 일부 델타만 다름(경계·문턱 시사) / `G-UNREADABLE` — 사진으로 판정 불가.

B계열:
- `J-VISIBLE` — J15에서 `JMP-SEEN`(측정된 15.0 m 점프가 화면에 보임). J37·J113의 크기 의존(더 큰 점프가 더 크게 보이는지)을 함께 기록.
- `J-HIDDEN` — J113에서도 `JMP-NONE` → 화면 표시가 점프를 감추거나 앱이 재적합으로 흡수.
- `J-REROUTE` — 어느 회차든 `REROUTE` 발생(J0 대조와 비교해 점프 때문에 생겼는지).
- `J-UNREADABLE` — 사진으로 판정 불가.

## 한계

- **스트림은 제품 산출의 유도가 아니라 모델입니다.** A는 창이 열린 동안의 상한(40 s 지속)을 보내고, 실제 창 지속·끝 조건은 제품이 정합니다.
  B의 점프는 측정값을 선상으로 모델링했으며 실제 점프는 횡·종 방향 성분이 섞입니다.
- DHU는 제품 코드·센서 수신·GPS 상태판정·체인 매칭을 실행하지 않습니다. 이 시험은 **앱 화면 반응만** 봅니다.
- 네이버 지도 버전·기기·해상도에 종속됩니다. 같은 폰·같은 앱 버전에서만 비교합니다.

# AA POSITION 문맥 풀과 관측 손실 처리 — 2026-10-02

## 판정

고정 소스 `943c054a826b074985421668ebe607c8edf4cdbf`는 AA
`libmx5dr.so`의 스레드별 큰 POSITION 문맥 배열을 64개 전역 슬롯으로
옮겼습니다. 고정 GCC 4.9.1로 만든 실제 AA DSO의 SHA-256은
`c9ec09d9574740a25bad8a00206d8b7591049e93ad26a740ce460c9cea236497`이고,
ELF `PT_TLS`는 196바이트·정렬 4바이트입니다. 이전 AA DSO의
7,284바이트 정적 TLS와 구분합니다. 문맥 풀은 BSS 58,368바이트를
사용합니다. LDS DSO는 기존 수정 제품
`2353666d85e301f54341b21e70cf740877f5dcf818d560263a00081db290b01a`이며
`PT_TLS` 48바이트입니다.

각 스레드의 중첩 한도는 8입니다. 슬롯 64개가 모두 사용 중이거나
중첩 한도를 넘으면 기존 원본 SEND를 한 번만 호출하고 반환값·`errno`를
보존합니다. 가능한 첫 실패 POSITION의 호출·세대와 원시 입력을
`CONTEXT_UNAVAILABLE`로 남기고, 이후 계산·요청 연결과 변형 송신을
철회합니다. 더 깊은 중첩에서는 식별자 없이 불완전 관측으로 남으며
정상 연결로 승격하지 않습니다. callback의 예외·지연 취소도 슬롯을
반납하고 관측 fault를 세웁니다. 비동기 취소·`longjmp`나 원본 OEM
프레임의 실제 예외 unwind 가능성까지 증명한 결과는 아닙니다.

## 실행 근거

- Linux 호스트의 `make test`는 종료 0입니다. Python 590개 중 551개가
  통과했고 원본 펌웨어 identity fixture가 없는 호스트 컨테이너에서
  39개가 생략됐습니다. C/C++ 실행은 통과했습니다. 생략된 동일 39개는
  원본 fixture가 있는 격리 컨테이너에서 따로 실행해 **39개 통과,
  생략 0개**를 확인했습니다. 두 실행의 수를 단일 전체 실행으로
  합산하지 않습니다.
- 고정 ARM 전체 runner는 종료 0이고 Python 118개, 원본 LDS 설치기
  71개, 실제 AA 제품 DSO 10개 suite·159개 사례를 통과했습니다.
  시작·종료 `ARM_TEST_INPUTS`는 위 AA를 포함한 여섯 산출물의 같은
  SHA-256과 `release_verified=true`를 기록했습니다. 해당 runner에는
  실패·생략이 없었습니다.
- 작성한 65개 동시 스레드의 슬롯 포화·재사용, 8/9단계 중첩,
  16 KiB 작성 ARM 스레드의 중첩·예외·취소·부족 경계를 검사했습니다.
  실제 제품 DSO를 preload한 사례와 소스 링크 사례를 구분해 실행했습니다.
  이것은 원본 AAPA 스레드의 스택 크기나 잔여 여유 측정이 아닙니다.
- 원본 rootfs의 ARM BusyBox 셸·libc를 사용하는 격리 chroot에서
  로컬 SHADOW 묶음의 `sh install.sh`, 숫자 메뉴 `1 → 5 → 2`,
  같은 부팅 재시도 거부, 일회성 guard 선택, 회수·제거와 원본 파일
  바이트·소유권·mode 보존을 검사했습니다. 재부팅·마운트·collector
  근거 중 일부는 작성한 witness입니다. 원본 PID 1·AA·VBS 전체
  서비스, 실제 CMU 재부팅이나 USB 교체를 실행한 결과는 아닙니다.

분석기는 문맥 없는 POSITION/SEND, 추가 LOCATION, 관측 drop·fault와
`capture_incomplete`가 있으면 LDS 연결을 철회하고 원시 행을 유지합니다.
`capture.done`은 닫히고 배출된 큐와 그때까지 본 fault의 기록을
확인하는 표식입니다. 그 후에 시작하거나 진행 중이던 OEM callback까지
종료했다는 보증은 아닙니다. fault가 발생한 worker 턴의 임시 MODEL
상태는 다음 drain·출력 전에 초기화하도록 검사했지만, 이 동시성 경계도
전체 OEM 실행으로 검증한 것은 아닙니다.

Codex 독립 검토 네 건 이상과 Claude의 읽기 전용 적대적 검토를
수행했습니다. 검토가 찾아낸 중단 시 fault 누락, 문맥 부족 행의
분석기 거짓 위반·거짓 연결, 마지막 fault 기록 누락을 수정한 뒤
전체 검사를 다시 실행했습니다. 최종 Claude 검토는 새 중·고위험
결함을 제시하지 않았고, 원본 unwind·스택·callback 완료 범위의
미검증을 명시했습니다. 검토자는 제품 소스를 수정하지 않았습니다.
원본 펌웨어와 비공개 로그·프롬프트 원문은 이 공개 기록에 포함하지
않았습니다.

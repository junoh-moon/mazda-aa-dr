# Android Auto DHU 시험 5 — E1·E5 우선, E2·E3·E6 후속

실험일: 2026-10-05 (Asia/Seoul). 요청한 다섯 조건을 각각 1회 완료했습니다. 관찰·해석·확인하지 못한 항목을 구분합니다.

## 결과 요약

| 회차 | 핵심 결과 | 판단 범위 |
|---|---|---|
| E1, 방위 335° | 61장 모두 파랑; 10분간 정속 50·정지 0km/h 반복; 거리 2.4km 고정 | 표본에서 속도 추종·표시 유지 확인 |
| E5, 약 4km/h 대조 | 13장 모두 파랑; 표시 속도는 모두 0km/h | 저속 입력과 표시 속도의 차이 관찰 |
| E2, 방위 NAN | 61장 중 파랑 11·회색 50; 주기적인 짧은 회복과 재손실 | E1보다 나은 대안이라는 근거 없음 |
| E3, 첫 fix→이동 | 44m 앞 정지 fix는 화면 추종 미확인; 정상 이동에서는 2.4→1.5km | 첫 fix와 이동 복귀의 판정을 분리 |
| E6, 정확도 NAN→복귀 | NAN 구간도 파랑·0km/h·위치 고정; 정상 입력 후 이동 재개 | 손실 표시가 반드시 난다는 가정 미확인 |

**E1·E5만 보면 E1의 속도 덮어쓰기 형태가 위치 표시를 악화시킨 현상은 관찰하지 못했습니다. 그러나 E3 첫 fix의 화면 추종은 확인되지 않았고, E6의 손실 형식 가정도 충족되지 않았으므로 계획 전체를 통과했다고 판정하지 않습니다.** 속도 숫자가 변하거나 화살표가 파란색이라는 사실만으로 좌표 수용 여부를 판정해서는 안 됩니다.

총 1,570개 위치 입력, 본시험 사진 193장, 준비·안내 종료 사진 10장입니다. `evidence.json`과 `frames.csv`가 정형 결과이며 각 사진과 실제 호스트 전송 시각을 연결합니다.

## 범위와 방법

사용자 우선순위에 따라 E1 → E5 → E2 → E3 → E6를 각각 1회 수행했습니다. E1·E2는 600초, E5는 120초, E3는 140초, E6는 110초입니다. 원문 계획의 반복 권장 및 무작위 순서와 달리, 이번 실행은 사용자 우선순위에 따른 단일 회차입니다.

Galaxy S25, Android 16, NAVER Map 6.10.0.16, Android Auto 17.7.663654-release, macOS 15.8 arm64, Google DHU 2.0-mac-arm64 (2022-03-30-438482292), ADB 37.0.1-15733141을 사용합니다. USB ADB `forward tcp:5277 tcp:5277`로 연결하고 DHU에 공식 `location` 콘솔 입력을 보냅니다.

기준 출발 좌표는 제공된 시험용 경로의 35.1582787,129.1493314이며 실제 사용자 위치가 아닙니다. 각 회차 전 DHU와 길안내를 다시 시작하고 정확도 5m·속도 0·방위 110°의 준비 입력을 보낸 뒤 파란 화살표, 남은 거리 2.4km, 다음 주요 회전 1.6km를 화면으로 확인합니다.

E1·E2·E5는 좌표를 고정합니다. E1·E2 속도는 60초 주기로 0→14→0m/s를 반복합니다. 14m/s는 50.4km/h입니다. E5의 1.111m/s는 약 4km/h입니다. E3·E6는 제공된 경로상의 이동 입력을 사용합니다. 모든 원문 위치 명령과 sleep 값은 그대로 유지하고, 준비 단계를 화면 확인용으로 분리했으며 각 회차 마지막 사진을 추가했습니다.

## 관찰과 해석

### E1 — 완료

- 600개 위치 입력의 순서·값·sleep 명령이 실행 파일과 모두 일치했습니다. 끝 사진 요청까지 호스트 시간 603.238초였으며, 입력 간격 중앙값 1.00556초, 최대 1.01677초였습니다. 명목 600초와 실제 경과시간의 차이를 숨기지 않습니다.
- 0~600초의 61장 모두 파란 화살표였고 회색·위성-X를 관찰하지 못했습니다. 남은 거리 2.4km, 다음 주요 회전 1.6km, 가까운 안내 177m, 카메라 거리 271m가 유지됐습니다.
- 10회의 정속 구간 사진(각 주기의 20·30초)에서는 모두 50km/h, 정지 구간(40·50초)에서는 모두 0km/h였습니다. 10·70초 사진은 50km/h, 130·190·250·310·370·430·490·550초 사진은 45km/h였습니다. 후자는 직전 입력 12.6m/s≈45.36km/h와 부합하지만 내부 처리 지연을 직접 측정한 것은 아닙니다.
- 화면 화살표는 대체로 위를 향했고, 눈에 띄는 잘못된 방향 이동·좌표 전진은 보이지 않았습니다. 속도에 따라 지도 축척이 바뀌었으며 교통 색상도 갱신됐습니다. 이를 차량 위치 이동으로 해석하지 않습니다.
- 판정: **화면 표본 범위에서 속도 추종 및 파란 화살표 유지가 확인됨**. 10분 연속의 모든 프레임에서 끊김이 전혀 없었다는 증명은 아닙니다.

### E5 — 완료

120개 입력이 원문과 일치했으며 종료 사진까지 120.653초였습니다. 0~120초의 13장 모두 파란 화살표, 위성-X 없음, 남은 거리 2.4km였습니다. 가까운 안내는 준비부터 종료까지 178m, 카메라 거리는 271m였습니다. E1의 가까운 안내 177m와 1m 차이가 있으므로 회차 간 표시 초기값 차이로 기록합니다.

입력 1.111m/s≈4km/h에도 **13장의 표시 속도는 모두 0km/h**였습니다. 저속 표시 억제 등의 설명이 가능하지만 내부 원인과 임계값은 시험하지 않았습니다. E5에서 보인 이 현상을 E1의 고속 표시 오류나 좌표 손실로 해석하지 않습니다.

E1과 E5 모두 표본에서 파란 화살표와 고정 위치가 유지됐습니다. E1의 0↔50km/h 속도 표시 변화와 E5의 0km/h 표시는 달랐지만, E1이 E5보다 위치 유지 측면에서 나빠졌다는 현상은 관찰하지 못했습니다. 두 조건의 관찰 길이는 각각 600초와 120초로 다릅니다.

### E2 — 완료

600개 위치 입력이 원문과 모두 일치했고 종료 사진까지 603.367초였습니다. 61장 중 파란 화살표는 0·10초 및 70·130·190·250·310·370·430·490·550초의 **11장**, 나머지 **50장은 회색**이었습니다. 첫 회색 표본은 20초였고 직전 10초는 파란색이므로 최초 전환 구간은 (10,20]초 표본 구간으로만 좁힙니다. 30초부터 여러 사진에서 위성-X도 보였습니다. 위성 아이콘은 회색 상태에서도 일부 사진에 없으므로 아이콘 부재를 정상 판정으로 사용하지 않습니다.

각 60초 주기의 가속 끝부분 표본에서는 파란색으로 잠시 돌아왔다가 다음 정속 표본에서 회색이 됐습니다. 표시 속도는 모든 주기에서 10초 45km/h, 20·30초 50km/h, 40·50초 0km/h였고 색상도 회색 상태를 반영했습니다. 남은 거리 2.4km와 가까운 안내 177m는 유지됐습니다.

E1과 비교해 **방위 NAN 조건에서는 GPS 손실 표시가 반복되는 명백한 화면 차이**가 있습니다. 이번 결과는 방위 제거가 더 낫다는 가설을 지지하지 않습니다. 다만 방위 필드 하나가 내부의 어떤 경로에서 처리되는지, 가속 구간의 일시 회복 이유는 밝히지 못했습니다. 단일 회차에서 속도 변화와 색상 변화를 함께 관찰한 결과이며 내부 원인을 단정하지 않습니다.

### E3 — 완료

140개 입력이 일치했고 종료 사진까지 141.558초였습니다. 35장 모두 파란 화살표였으며 시험 사진에서 위성-X를 관찰하지 못했습니다.

- 0~59초 고정 좌표 단계: E1과 같은 속도 표시 반복, 남은 거리 2.4km.
- 60~79초 첫 fix 단계: 44m 앞 좌표·정확도 3m·속도 0·방위 NAN을 반복했습니다. 60~78초의 2초 간격 사진에서는 가까운 안내 177m·카메라 271m·남은 거리 2.4km가 그대로였습니다. **44m 위치 변경의 화면 추종은 확인하지 못했습니다.** 파란 화살표가 유지된 사실만으로 새 좌표가 수용됐다고 간주하지 않습니다.
- 80~139초 정상 이동 단계: 정확도 5m·속도 14m/s·경로 방위를 전송했습니다. 80초 사진은 아직 0km/h와 기존 거리였고, 85초에는 50km/h·남은 거리 2.3km로 바뀌었습니다. 이후 경로를 따라 전진했고 140초 종료 사진은 1.5km였습니다. 마지막 입력은 경로 시작에서 884m 지점으로, 표시 거리 감소 약 0.9km와 대체로 부합합니다. 화면 거리는 반올림됩니다.

판정은 **정상 이동 추종 확인 / 첫 정지 fix의 44m 이동 확인 실패**로 나눕니다. 원문 E3 전체 조건을 완전히 충족했다고 판정하지 않습니다. E3 첫 fix에서도 방위 NAN이었지만 E2와 달리 회색이 되지 않았으므로, NAN이라는 문자열만으로 모든 손실 현상을 설명해서는 안 됩니다. 두 단계는 속도·좌표 변화·이전 상태가 다릅니다.

### E6 — 완료

110개 입력이 일치했고 종료 사진까지 110.655초였습니다. 23장 모두 파란 화살표였으며 위성-X를 관찰하지 못했습니다.

- 0~19초 정확도 10→38m의 이동 단계에서 정상 전진하고 속도 50km/h를 표시했습니다. 0초 사진만 초기 지연으로 0km/h였습니다.
- 20~79초에는 마지막 좌표·정확도 NAN·속도 2.2m/s·방위 80.4°를 반복했습니다. 20초 사진은 아직 50km/h였지만 25초부터 75초까지는 **0km/h·남은 거리 2.1km·가까운 안내 199m·파란 화살표**였습니다. 입력 속도는 약 7.92km/h입니다. 20초 가까운 안내 213m에서 25초 199m로 한 번 더 갱신된 뒤 유지됐습니다.
- 80초부터 정확도 5m·14m/s의 이동 입력으로 복귀했습니다. 80초 사진은 이전 정지 화면, 85초 사진부터는 50km/h와 지도 전진이 보였습니다. 종료 사진은 남은 거리 1.7km였습니다. 복귀 후 눈에 띄는 경로 이탈 점프는 표본에서 관찰되지 않았습니다.

판정: **고정 상태와 정상 이동 복귀는 관찰했지만, 이 조합이 화면상 GPS 손실 형식이라는 가정은 확인되지 않았습니다.** 정확도 NAN만으로 반드시 회색·위성-X가 나온다고 일반화할 수 없습니다. 이 결과를 실제 Mazda mode 0 wire format의 검증으로 해석하지 마십시오.

## 판정의 한계

- 10초 간격(E3·E6 전환 구간은 2~5초)의 화면 표본입니다. 표본 사이에 짧은 손실 표시가 전혀 없었다는 연속 관찰 증거는 아닙니다.
- 입력 후 약 0.2초에 촬영을 요청하며, 명령 전달·앱 처리·렌더링 지연이 있습니다. 사진 번호와 개별 메시지 수용 시각을 동일시하지 않습니다.
- [Google 공식 문서](https://developer.android.com/training/cars/testing/dhu#sensors)는 `location`의 선택적 매개변수를 생략할 때 `NAN`을 사용하도록 설명합니다. 이번에는 그 문법으로 명령을 보내고 화면 반응을 관찰합니다. Android Auto wire format, hasBearing/hasAccuracy 필드, 위치 수신 시각은 패킷 분석으로 확인하지 않습니다.
- 고정 방위 입력이 존재하더라도 화면 화살표는 지도 회전·도로 정합의 영향을 받습니다. 화면이 위를 향한다는 사실만으로 내부 방위 값이 335°인지 또는 무시됐는지 단정하지 않습니다.
- 단일 회차 결과이며 실제 휴대전화 GNSS 수신 강도는 측정하지 않았습니다. 이전 실험의 실내 조건을 이번 측정값으로 간주하지 않습니다.
- Mazda 차량·차량 timestamp 0·휠 신호·무선 동글은 시험하지 않습니다. 저장 좌표를 반복한 원인은 이 시험의 입력 조건이며 실제 차량 동작의 독립 검증이 아닙니다.
- 전체 제품 출하, 차량 적용 또는 ASSIST 활성화를 승인하는 시험이 아닙니다.

## 연결 준비의 예외

무선 ADB 페어링을 두 번 시도했으나 상태 응답 오류가 발생했습니다. 서비스는 mDNS로 검색됐지만 TCP 연결이 거절됐습니다. 사용자는 공용 Wi-Fi 환경이라고 설명하고 일시 정지를 요청했습니다. 기기 간 통신 차단은 추정이며 확인하지 않았습니다.

이후 사용자가 USB로 연결하고 다섯 조건으로 범위를 확대했습니다. 처음 ADB 상태는 unauthorized였으며 공식 USB 액세서리 연결 시도와 사용자 Allow 승인 이후 device 상태가 확인됐습니다. 액세서리 연결을 닫는 전환 중 환경 조회 한 번이 `error: closed`로 실패했으며 재연결 후 정상 조회했습니다. 유효 회차는 USB ADB 포워딩으로 실행합니다.

## 추가 준비·분석 예외

- E5 준비에서 원문 자동 재개 탭이 길안내를 시작하지 않아 목적지를 다시 선택했습니다. E2 준비에서 최근 목적지 목록 선택 후 390km 안내가 나와 본시험을 시작하지 않고 중단·재선택했습니다. 변경된 목록과 미포항 미리보기를 직접 확인한 뒤 기준 2.4km를 재확인했습니다. 유효 시험에 잘못된 준비 경로를 포함하지 않았습니다.
- 본시험 중 지도 조작이나 추가 위치 입력을 끼워 넣지 않았습니다. 각 시험은 제공된 명령 파일과 정확히 일치하는 전송 구간으로 검증했습니다. 준비 단계와 본시험 이후 입력 중단 구간은 판정 대상에서 제외했습니다.
- 초기 E1 DHU 시작에 macOS IMK 포트 오류 로그가 한 번 있었고 E2 등에서 오디오 재생 중복 경고가 있었습니다. 원본 로그를 보존했으며 이 경고를 위치 실패의 증거로 해석하지 않았습니다. 위치 명령 문법 오류나 본시험 컨트롤러 오류는 발견하지 못했습니다.
- 보고서 준비 코드에서 누락된 Python import 1회, 아직 생성되지 않은 미래 사진을 묶으려던 분석 호출 1회, 셸에서 따옴표 없는 GitHub API 경로 해석 오류 1회가 있었으며 수정했습니다. 입력 제어 프로세스 및 본시험에는 영향을 주지 않았습니다.
- 원문 경로의 도형은 이전 실험의 OpenStreetMap 기반 `geometry/non-tunnel-path.json`을 함께 보존했습니다. © OpenStreetMap contributors.

안내·DHU·제어기·ADB 종료와 TCP 5277 포워딩 제거를 수행했습니다. 임시 작업 폴더 163,922,535바이트와 생성된 ADB 키 2개·임시 로그 1개를 삭제했습니다. 휴대전화 설정 확인 여부는 `cleanup.json`, 설치·정리 기록은 `install-cleanup.md`에 기록합니다. 휴대전화의 실제 GNSS 위치 복원 시점은 별도로 측정하지 않았습니다.

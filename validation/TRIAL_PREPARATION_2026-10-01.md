# 한 번의 실차 시험 준비 — 2026-10-01

사용자가 v1.0 전 한 번의 실차 설치·시험을 허용했습니다. 이전 펌웨어 파일만
사용하는 제한을 해당 통합 시험에 한해 갱신했습니다. 실제 관성항법 위치를
적용하는 v1.0 목표는 유지하며 제품 ASSIST는 아직 비활성·미완료입니다.
실차 실행이나 새 설치 ZIP의 검증 완료를 기록하는 문서가 아닙니다.

## 상태 확인의 계산 진행 누락

기준 `ce125189e064baa0c3e74514ddcb15e721e91826`의 상태 도구는 최근 원시 센서와
health가 있으면 `shadow_boot.active=false`, `computation_active=false`이고
계산 기록이 전혀 없어도 종료 코드 0을 반환했습니다. 합성 로그로 직접 재현했습니다.

새 도구는 원시 수신, OEM 위치 수신, 계산 활성, 실제 MODEL 입력 처리와 현재
MODEL 결과를 별도로 보고합니다. 계산기 heartbeat만으로 입력 처리를 인정하지
않으며 최신 결과가 무효하면 과거 유효 결과를 대신 표시하지 않습니다.
정차 중 기준점·움직임 대기는 이유와 `model_solution=not_observed`로 표시하고,
주차 중 기동 확인에 이동 중의 유효 해를 요구하지 않습니다. 계산 대기·거부가
원시 수집을 중단하는 기능을 추가한 것은 아닙니다.

해석된 거부 원시 입력도 수신 증거로 표시하지만 센서의 물리적 유효성·신선도로
취급하지 않습니다. 최근 위치·입력 거부 사유와 GPS 기준점 상태를 표시합니다.
기동 확인의 성공은 주행 실험이나 항법 검증의 완료가 아닙니다.

검증: 새 회귀 7개가 수정 전 실패했고, 수정 후 상태 검사 19개를 임시 Debian
bookworm 컨테이너에서 생략 없이 통과했습니다. 실제 호스트 collector의 journal
형식 검사도 포함합니다. 호스트 자체에서는 D-Bus 개발 파일 부재로 해당 한 개를
생략했으며, 이 생략을 컨테이너의 실행으로 보완했습니다. OEM BusyBox 실행과
전체 host/ARM·새 설치 묶음 검증은 후속 단계입니다.

## 저장 공간 대응

두 journal은 각 기록 전에 `statvfs`의 비특권 사용 가능 공간을 검사합니다.
8MiB 여유분, 64KiB 쓰기 여유와 다음 기록을 수용하지 못하면 기존 파일을
회전·삭제하지 않고 해당 writer를 멈춥니다. 이 값은 프로그램 정책이며 OEM
요구량 실측이나 다른 프로세스에 대한 할당량 제한이 아닙니다.

각 stream의 고정 `*.storage.json`에는 부팅 ID, PID, 단조 시각, 원인,
남은 바이트·여유 정책과 시스템 오류가 들어갑니다. 파일은 1KiB 미만이고
저장 자체가 실패하면 이 진단도 남기지 못할 수 있습니다. 새 worker가
수집을 재개해도 과거 실패를 지우지 않습니다. 상태 도구는 이전 부팅과
현재 부팅의 실패, 재시작한 작업자의 활성 상태를 구분합니다. PC 분석은
디렉터리와 tar 안의 이 기록을 읽고 수집을 불충분으로 판정합니다.

설치·재무장은 남은 최대 로그 할당, 신규 바이너리, 위 여유분과 1MiB의
도구·설정·백업 공간을 먼저 확인합니다. 이미 저장된 고정 로그는 재사용분으로
빼며, 부족하면 설치의 기동 설정·백업 변경 전 중단합니다. 제거에는 이
검사를 적용하지 않습니다. 내보내기는 경로를 해석한 후 내부 persistent
디렉터리를 거부합니다. USB 회수와 제거는 원본 로그·설정 백업을 보존합니다.

검증을 구분하면 다음과 같습니다.

- 최초 두 logger의 기동 시 부족·도중 부족·조회 오류·잘못된 공간 정보
  8조건이 수정 전 실패했습니다. 수정 후 양쪽 10조건과 기존 journal 검사가
  통과했습니다. 정상 공간 대조도 포함합니다.
- 실제 16MiB tmpfs에 다른 데이터 6MiB를 기록했습니다. 공간 조회를 대체하지
  않고 두 writer를 각각 실행했으며, 모두 사용 가능 공간 10,485,760바이트에서
  8,445,952바이트를 남기고 멈췄습니다. 차량 flash의 고장·내구성 검사는 아닙니다.
- 설치·회수 회귀 4개, PC 분석기의 추가 회귀 2개가 수정 전 실패했고 수정 후
  해당 검사군을 통과했습니다. 중단 뒤 최근 health만으로 정상 수집을 표시하는
  진단과 재시작 시 실패 증거를 지우는 초기 구현도 회귀로 재현·수정했습니다.
  최종 상태 검사 22개를 생략 없이 통과했습니다.
- 초기 통합본은 host Python 345개와 C/C++, 고정 GCC 4.9.1의 ARM 전체 runner를
  통과했습니다. 생략은 없었습니다. 최초 host 실행 두 번의 Git 소유권 오류와
  최초 ARM의 32비트 비교 경고/빌드 실패는 따로 보존했습니다. 격리 컨테이너의
  정확한 저장소 경로만 신뢰하도록 설정하고 비교식을 32비트 범위에 맞췄습니다.
- 그 통합본의 원본 ARM BusyBox 1.19.2·libc로 설치, loader, one-boot guard,
  collector UID/종료, 상태·종료 helper, 회수, 제거·재설치를 실행했습니다.
  mount 상태와 센서/health 행은 작성한 fixture이고 OEM 서비스·차량 실행은
  아닙니다. 재시작 증거 보존을 포함한 최종 고정 후보의 전체 검증은 후속입니다.

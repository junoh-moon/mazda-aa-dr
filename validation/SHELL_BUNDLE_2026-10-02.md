# 승인된 셸용 설치 묶음 — 2026-10-02

새 `--shell-only` 옵션은 이미 승인된 셸에 접근할 수 있는 사용자를 위한
설치 묶음을 생성합니다. 숫자 메뉴와 DR 설치·재부팅·기동 진단·회수·제거는
유지하며 셸 진입용 MP3/JS와 이전 진입 안내를 포함하지 않습니다.
[동봉 안내](../packaging/SHELL_START_KO.md)는 CMU 재부팅 뒤에도 승인된 셸에
다시 접속할 수 있어야 한다는 전제를 명시합니다.

`make_bundle.sh`와 `make_usb_zip.py`가 같은 옵션을 사용합니다. build-info의
`bundle_type=shell-only`, `entry_payloads_included=false`로 배포 종류를
구분하고, 사용하지 않는 이전 진입 파일은 이 묶음의 소스 입력에서 제외합니다.
나머지 실제 입력의 Git blob·해시 대조와 여섯 ARM 제품 검증은 유지합니다.
ZIP 검사는 진입 파일·이전 안내를 거부하고 여섯 제품과 각각의 체크섬,
숫자 메뉴·설치기·동봉 안내·build-info를 요구합니다.

## 집중 검증

작성한 여섯 dummy 제품으로 실제 bundle CLI를 실행했습니다. 구현 전에는
새 옵션을 거부하여 OBSERVE/SHADOW 두 대조가 실패했습니다. 구현 뒤 두
모드에서 기존 DR 파일 전체와 여섯 제품·체크섬, 안내문을 대조했습니다.

검토에서 ZIP 판독이 이전 안내와 일부 제품·체크섬 누락을 허용하는 두
공백을 찾아 12개 실패 대조로 보존했습니다. 정상 main 생성 경로의 여섯
제품 검사는 이미 존재했으며 이를 실제 배포 제품 누락으로 표현하지 않습니다.
최소 수정 뒤 다음 **6개 unittest 메서드가 종료 0, skip 0**으로 통과했습니다.

- 두 모드의 실제 bundle CLI와 DR 파일·제품·체크섬 보존
- 셸 전용 ZIP의 정상 생성·CRC·외부 체크섬
- 진입 디렉터리·옛 안내 이름 네 종류의 게시 전 거부
- 여섯 제품·여섯 체크섬을 각각 누락한 경우의 거부
- 셸 전용 metadata 부재의 거부
- 사용하지 않는 입력 제외와, Git 표시에서 숨긴 실제 안내 변경의 검출

실제 접근 페이로드를 실행하거나 새 ZIP에 넣는 검사는 수행하지 않았습니다.
작성 대조에는 이름만 같은 무해한 텍스트 파일을 사용했습니다. 이는 전체
host/ARM 재실행이나 차량 시험이 아닙니다.

`5eec1fa`의 [전체·원본 제품 검사](LDS_RMC_PRODUCT_2026-10-02.md)와 비교하여
컴파일 입력 81개가 바이트 그대로임을 확인했습니다. 이번 변경에는 제품
runtime, ASSIST 자격, 설치 가드나 저장 한도 수정이 없습니다.

이 기록 시점에는 새 pin의 실제 최종 ZIP·BusyBox 세 경로 검사와 공개
재다운로드 검증이 아직 남았습니다. 그 결과는 별도 발행 기록에 남깁니다.
실차 기동·물리 센서·폰 수용과 live ASSIST는 계속 미완료입니다.

# Shift 없는 USB 시험 절차 — 2026-10-01

사용자의 키보드가 Shift를 인식하지 않아 실차 명령 입력을 최소화합니다.
NA 74.00.324A의 SHADOW 시험 후보이며 실제 차량·폰 수용 검증은 아닙니다.
실제 관성항법 위치 적용이라는 v1.0 목표와 ASSIST 비활성 상태는 유지합니다.

## 동작

USB 최상위의 `trial`을 `sh /tmp/mnt/sda1/trial` 한 줄로 실행합니다.
USB가 sdb1 등으로 잡히면 해당 글자만 바꿉니다. 소문자·숫자·공백·슬래시만
입력합니다. `1` 설치, `2` 상태 확인, `3` 종료·USB 회수, `4` 제거,
`0` 종료를 숫자와 Enter로 선택합니다. 최초 설치, 다음 부팅의 주차 확인,
도착 후 주차 회수에서 같은 한 줄을 사용하며 운전 중 입력은 없습니다.

`1`은 기존 설치기의 펌웨어·전체 manifest·공간·일회 기동 검사를 그대로
실행합니다. 빈 Enter, 잘못된 번호나 입력 종료는 설치를 실행하지 않습니다.
`2`는 모드·가드·수집 상태를 바꾸지 않고 기존 진단을 표시합니다.
`3`은 현재 상태를 기록하고 협조적 종료를 요청한 뒤 실행한 USB에 회수합니다.
종료 확인이 실패해도 확보 가능한 원본 회수를 시도하며, 실패 코드를 유지합니다.
다른 USB를 자동 선택하지 않으며 USB가 마운트되지 않은 디렉터리에 archive를
만들지 않습니다. 마운트 동작은 기존 helper를 사용하며 바꾼 읽기 전용 상태를
복원합니다. USB는 회수하는 동안 연결해 두어야 합니다.

USB의 `trial-result.txt`는 종료 전 상태, `status_exit`, `finish_exit`,
`export_exit`와 각 명령 출력을 보존합니다. 다음 회수 때 교체하는 작은 파일이며
CMU에 누적하지 않습니다. archive·체크섬과 함께 회수합니다. 회수 성공과
계산 성공을 합치지 않으며 저장 실패 시 화면에 오류가 남습니다.

## master 통합과 회귀

같은 `feat/session-observation` 브랜치를 유지했습니다. 메뉴 커밋 `20d1235`
이후 fetch에서 외부 master `260528c`를 발견하여 `b185b99`에 통합했습니다.
문제 raw를 먼저 저장한 뒤 MODEL 초기화 원인을 기록하고, 시각이 없는 초기화
표시와 잘못된 drain 카운터의 PC 분석 거부를 반영했습니다.
기존 저장 공간 정책·진단을 보존했으며 외부 검증 수치를 이번 실행과 합산하지
않습니다. 외부 master가 공간 정책을 채택하지 않았다는 판단은
[그 검토 시점의 기록](MODEL_RESET_REVIEW_2026-10-01.md)에 남아 있습니다.
8MiB는 여전히 프로그램 정책이며 OEM 필수 공간의 실측값이 아닙니다.

- 새 메뉴 회귀 10개가 구현 전 실패하고 구현 후 통과했습니다. 실제 helper와
  작성한 펌웨어 식별 fixture로 설치, 읽기 전용 진단, 성공/실패 회수, USB 부재,
  설치 거부와 제거·원본 보존을 검사했습니다. 묶음 내 메뉴 포함 회귀도 실패한
  뒤 기존 종료·묶음 8개와 함께 통과했습니다.
- 외부 회귀를 이전 `20d1235` 코드에 적용하여 raw/진단 기록 순서의 assertion
  실패와 잘못된 호출 카운터를 통과시키는 PC 분석 실패를 직접 재현했습니다.
  통합 후 journal, 상태 35개와 분석기 34개를 통과했습니다.

# LDS 진단값의 위치 출처 연결 검토 — 2026-10-01

이 문서는 외부 master `ad252cd`의 실행·검토 기록을 보존한 것입니다.
본문의 직접 실행·root는 그 기록의 작성자를 가리킵니다. 현재 작업의
직접 검증이나 최종 설치 후보의 시험 횟수로 합산하지 않습니다.

원본 `GetUbloxDiag`를 추가 조회하는 것만으로 각 `GetPosition` 응답에
수신기·센서 자격을 붙일 수 없다는 외부
[정적 분석](LDS_DIAGNOSTIC_PROVENANCE_2026-10-01.md)을 root가 입력과
공개 API 경계에서 직접 대조했습니다. 진단값 조회를 제품 live
`provenance()`의 성공 조건으로 구현하지 않았고 ASSIST는 비활성입니다.

제공 NA 74.00.324A rootfs의 원본 `libjcilds-dbus.so` SHA-256은
`86fa094608e0c342ea759e522611d4c2d069006e2bb8909767f8835c164f18ce`,
`libjcilds-ublox.so`는
`aa1d4f5023c5f12093884e3b8a10bda07b234e4a36a793e333af010b522dbae5`로
외부 조사 기록과 일치했습니다. D-Bus introspection의 출력 형식을
직접 파싱했을 때 `GetPosition`은 아홉 필드
`(i,t,d,d,i,d,d,d,d)`, `GetUbloxDiag`는 15개 필드였습니다. 두 메서드
어느 쪽에도 특정 위치 응답과 진단 응답을 묶는 생산 측정 ID·snapshot
ID가 없습니다. UTC와 좌표가 같아도 두 독립 조회가 하나의 측정이라는
보장은 되지 않습니다.

원본 ELF의 심볼에서도 `currentPositionMutex`와
`diagnosticsDataMutex`가 서로 다른 객체임을 확인했습니다. 각각의
정확한 갱신·복사 순서와 u-blox 생산자 분기 분석은 외부 기록의 근거이며,
root가 이번에 명령어 실행이나 경쟁 상태를 재현한 결과는 아닙니다.
따라서 이 직접 검사만으로도 사후 진단 polling을 **요청별 위치 출처
자격의 증거로 승격할 수 없음**은 분명합니다. 향후 자격을 구현하려면
원본 생산→위치 snapshot→실제 요청·응답 경계에 동일 측정의 식별자와
무효화 규칙을 연결해야 합니다. 연결을 구현하더라도 실제 차량의
수신기·센서 품질·생산 시각·폰 수용은 별도 검증 항목입니다.

이번 단위는 원본 파일 해시, D-Bus 선언과 ELF 심볼만 읽었으며 제품
소스·USB·실차를 변경하거나 원본 서비스를 새로 실행하지 않았습니다.
제품 회귀 `make test`와 ARM suite는 문서만 변경하므로 다시 실행하지
않았습니다. 원본 파일·주소 지도·명령어 덤프는 게시하지 않습니다.

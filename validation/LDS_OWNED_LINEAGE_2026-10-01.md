# LDS 필드별 쓰기 출처 보존 — 2026-10-01

부분 갱신에서 유지하는 필드의 출처를 **해당 콜백이 실제로 읽었던 사본**에서
계승하도록 구현했습니다. 원본 LDS에서 읽기와 쓰기 사이 다른 갱신이 들어오면

출처가 어긋납니다. 새 코어를 원본 실행의 비공개 관측 서버에 연결하여 이 경우를
재현하고, 원본 응답과 제품 request token까지 대조했습니다.

구현 커밋은 `a0c6f5b0153b9ac4dd5b9fdbf03860822f656e99`입니다.
`src/sensors/lds_lineage.h/.cpp`와 host·ARM 검사 연결을 추가했습니다.
**제품 LDS preload·자동 기동·프로세스 간 공급부에는 아직 연결하지 않았습니다.**
공개 v0.3.8-shadow.1 설치 ZIP은 그대로이며 live ASSIST는 비활성입니다.

## 구현 계약

`Ledger`는 위치의 아홉 필드마다 마지막으로 관측한 할당의 쓰기 번호와 관측
시각을 보존합니다. 원본 캐시와 같은 mutex 안에서 읽기 사본을 만들고, 실제
캐시 쓰기가 완료될 때 그 사본과 검증된 할당 마스크를 전달합니다. 응답을
복사할 때의 출처도 별도 소유 사본이므로 이후 캐시 쓰기에 따라 바뀌지 않습니다.

- 같은 값을 다시 할당해도 새로운 쓰기입니다. 조회만 하면 번호가 늘지 않습니다.
- 중간 쓰기가 있어도 미할당 필드는 실제 읽기 사본의 출처를 유지합니다.
- 읽기 사본 누락·다른 소유자·다른 수명·미래 번호·지원하지 않는 마스크는
  미확인 출처로 기록합니다. 이후 부분 갱신으로 확인된 필드만 회복합니다.
- 새 관측 수명은 출처를 비우며 `(관측 수명, 쓰기 번호)` 쌍을 재사용하지
  않습니다. 새 수명의 쓰기 번호는 다시 0에서 시작합니다. 쓰기 번호가
  소진되면 출처를 미확인으로 남깁니다. 관측 실패로 OEM 호출을 막지 않습니다.
- 코어는 고정 크기이며 잠금·대기·동적 할당·I/O·콜백을 수행하지 않습니다.
  모든 접근의 원본 mutex 직렬화와 실제 읽기/쓰기 경계 결합은 호출자 계약입니다.

번호는 **관측한 할당의 identity**입니다. 물리 생산 순번·수신기 identity·측정
시각이 아닙니다. 관측 시각이 같거나 뒤로 가도 이를 물리 신선도 판정으로
사용하지 않습니다. RMC의 mode 할당처럼 이전 parser 상태에도 의존하는 값을
단일 문장의 새로운 측정으로 표시하지 않습니다. 사본의 구조 검사는 임의로
변조한 metadata를 인증하는 기능이 아니며, 객체 주소 재사용 때도 수명을
재사용하지 않을 책임은 호출자에게 있습니다.

## 먼저 실패시키고 원본 응답까지 확인한 경우

코어의 초기 명시적 미구현 상태는 할당한 위도의 출처가 계속 미확인인 검사에서
exit 1로 실패했습니다. 별도 원본 실행 기준선도 값과 요청 연결은 성공했지만
필드 출처 metadata가 없어서 독립 검증기가 실패했습니다.

가장 중요한 원본 경합은 다음 순서입니다. 대기는 원본 mutex가 실제로
해제된 뒤 작성한 pthread에서 수행했으며 5초 제한을 뒀습니다.

1. 고도 12가 들어 있는 쓰기 3의 사본을 RMC가 읽습니다.
2. 그 RMC를 기다리게 한 동안 GGA가 고도 24를 쓰기 4로 저장합니다.
3. RMC가 재개되어 자신의 이전 사본을 쓰기 5로 저장합니다.
4. 실제 서비스와 제품 클라이언트가 다시 고도 12를 받습니다.

새 코어는 쓰기 5에서 고도 출처를 **쓰기 3**으로 보존했습니다. 같은 원본 값과
경합을 유지하면서 metadata만 최신 전역 상태에서 계승하도록 만든 비공개
대조 구현은 쓰기 4로 잘못 귀속시켰고, 독립 검증기가 이를 실패로 잡았습니다.
입력 번호와 완료된 쓰기 번호도 분리했습니다. 이 작성 스케줄은 실제 차량
driver가 병렬 RMC/GGA를 실행한다는 주장이 아닙니다.

## 독립 연결 검사와 회귀

실제 원본 객체의 path→method→reply→raw reply 연결과 bus identity,
client unique name+request serial, server unique name+response serial+reply
serial로 원본 service snapshot을 제품 token에 연결했습니다. 필드별 출처는
그 snapshot과 실제 읽기·쓰기 번호로 대조했습니다. 위치 값·UTC·관측 시각·
실험 label은 연결 키가 아니며 값은 identity 연결 후 비교합니다. monitor의
텍스트 출력 정밀도를 위치의 bit 단위 증거로 사용하지 않습니다.

독립 검증기는 자체 회귀의 실패를 먼저 확인한 뒤 최종 **16개 검사**를
통과했습니다. 고정한 최종 SHA-256은
`f1c21953866a29a5520a7e3891a54e073ad1867d05f3ce554691c3c4ab979981`입니다.
보존된 원본 실행을 이 버전으로 모두 다시 분석했으며, 원본 바이너리를
다시 실행한 결과로 세지 않습니다. 독립 코드 검토에서도 선언한 원본 mutex·
변경하지 않은 읽기 사본 계약 안에서 중요한 결함을 찾지 못했습니다.

코어는 host, 고정 ARM sysroot, 같은 ARM 실행 파일의 순정 공유 runtime에서

## 남은 제품 연결

현재 서버의 수동 origin scope와 초기화는 진단 fixture입니다. 실제 제품은
LDS cold load, 원본 callback 등록과 table 초기화, 직접 cache 초기화의 수명을
자동으로 관측하고 실제 응답 출처를 AA 프로세스에 전달해야 합니다. 원본
`Initialize`는 공통 updater를 거치지 않고 cache를 지우므로 updater 관측만으로
제품 수명을 완성할 수 없습니다. driver의 callback table 초기화와 cache
초기화도 같은 사건으로 취급하지 않습니다.

실제 등록의 반환·부작용·이전 callback 소유권과 preload 공존, 중간 설치 실패,
OFF·일회성 부팅 보호·제거 경로를 보존하는 연결은 **미구현**입니다. 현재
비공개 관측기의 I/O·대기 지점·슬롯별 설치를 제품 구현으로 사용할 수 없습니다.
지원하지 않는 실제 writer는 미확인 출처로 남겨야 하며, 물리 측정 시각·센서
품질·receiver/session 자격과 폰/지도 앱 수용은 이 assignment 기록으로
대체하지 않습니다. 실제 관성항법 위치를 AA에 적용하는 v1.0 목표는 미완료입니다.

원본 바이너리·덤프·개인 경로·raw 로그는 게시하지 않습니다. 작성 소스와 실행
명령·종료값·전후 해시·실패 대조는 비공개 `evidence/lds-owned-lineage-20261001/`에
보존합니다. 이전 도구 정리 때 승인 거부로 보존한 증거 디렉터리도 삭제하지 않았습니다.

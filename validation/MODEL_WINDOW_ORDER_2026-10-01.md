# 기준점 준비 중 요레이트 구간 순서 수정 — 2026-10-01

MODEL이 GPS 기준점을 준비하는 동안, 아직 닫히지 않은 요레이트 평균 구간보다
휠 입력을 먼저 소비하여 정상 요레이트를 `LATE`로 거부하던 결함을 수정했습니다.
원본 센서 시각·250ms 유효 기간을 바꾸지 않고 다음 평균 구간이 닫힐 때까지
입력을 보존합니다. NA 74.00.324A의 SHADOW 계산 수정이며 live ASSIST 연결이나
물리 센서·차량·폰 검증 완료가 아닙니다.

## 재현과 변경

수정 전 소스 `6ef818a456aea2d6862f4e6cac185dc3103a91b3`에서 기준점이 없으면
`advance()`가 적분 없이 성공합니다. 100ms까지 닫힌 yaw 구간 뒤에 wheel 120ms를
소비하면 내부 소비 시각도 120ms가 됩니다. 다음 yaw가 220ms에 도착할 때
평균 구간은 100→220ms로, 250ms 제한 안인데도 구간 시작 100ms가 소비 시각보다
과거여서 계산기가 초기화됩니다. 입력 자체의 역순이나 오래된 측정이 아닙니다.

기준점이 없는 MODEL도 마지막으로 닫힌 yaw 경계를 넘는 입력을 대기시킵니다.
기존 GPS 모드 변경·재기준점 경로는 대기 중인 위치 관측을 처리할 수 있도록
유지합니다. 실제 yaw 단절은 기존 나이 제한으로 거부하며, 대기만으로 MODEL
유효 결과를 만들거나 QUALIFIED 입력으로 승격하지 않습니다.

- 수신 시각 MODEL과 transport 시각 MODEL 각각에서 120ms wheel 뒤의 220ms yaw가
  수정 전 실패하고 수정 후 수락됩니다. 260ms 실제 yaw 간격은 계속 거부합니다.
  마지막 yaw 뒤 250ms와 251ms의 대기 경계도 확인합니다.
- 실제 worker·소켓·journal 경로에서 wheel 20ms, reverse 100ms, yaw 160ms 입력과
  버스 주소 재사용을 실행합니다. 같은 최종 회귀를 이전 pipeline에 연결하면
  입력 공급 중 reset assertion에서 실패합니다. 수정 후 raw 499건을 모두 기록·
  수락하고, 새 기준점 뒤 유효 계산을 재개합니다.
- 기존 cadence 회귀는 입력마다 drain하는 잘못된 스케줄에서 `LATE`를 기대했습니다.
  이번 수정으로 그 오류가 사라져 첫 전체 검사가 해당 assertion에서 실패했습니다.
  모든 스케줄에서 준비 입력이 보존되는지 검사하고, 입력마다 실행하는 과다 호출과
  20ms 입력의 최소 간격만 사용하는 스케줄의 지연은 실제 drain 시각으로 판별합니다.
  현재 worker의 50ms deadline은 1.5초 동안 기존과 같은 31회 호출을 유지합니다.

초기 수정은 GPS 재기준점 회귀를 실패시켜 위치 처리 경로를 보존하도록 보완했습니다.
초기 worker assertion도 입력 공급 종료 이후의 정상 `MISSING_SENSOR`까지 거부하여
실패했습니다. 최종 회귀는 입력 공급 중의 초기화를 거부하고, 7.5초 공급 종료 뒤
유효 기간 만료는 허용합니다. 두 초기 실패와 최종 회귀의 수정 전 실패를 모두
비공개 evidence에 보존했습니다.

## 과거 부하 실패와의 관계

[이전 시험 준비](TRIAL_PREPARATION_2026-10-01.md)의 동시 host/ARM 실행에서는
host가 마지막 GPS 쌍 사이에 초기화되어 재기준점을 만들지 못했고, ARM은 raw
수신 후 검사까지 252.879197ms가 지나 250ms 제한을 넘었습니다. 당시 주 계산기의
첫 초기화 원인 정보가 충분하지 않아 이번 결함이 과거 실패의 유일한 원인이었다고
단정하지 않습니다. 이 수정은 정해진 입력 순서에서 결함을 별도로 재현한 결과입니다.

이전 pipeline을 사용하는 단독 대조와 동일 CPU에 부하 프로세스 두 개를 붙인
`bus_reuse`·`bus_closed` 검사는 통과했습니다. 후자는 해당 worker의 syscall도
추적했습니다. 이 제한된 부하 실험으로 과거 최초 지연은 재현되지 않았으며,
스케줄링·실제 차량 부하의 안정성이 입증된 것은 아닙니다.

최종 ZIP의 `source_modified=false`와 전체 파일 manifest·CRC·해시를 확인했습니다.
커밋 뒤 동일 코드를 다시 컴파일하거나 전체 검사를 다시 실행했다고 표시하지 않습니다.

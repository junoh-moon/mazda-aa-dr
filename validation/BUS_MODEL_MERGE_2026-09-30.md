## 수정 전 실패와 통합 내용

외부 변경을 제품에 통합하기 전에 기존 `2548312` 소스에 외부 작성
`signal_reuse` 회귀를 연결해 실행했습니다. 원본 신호 분류를 기다리는 동안 이전 객체를 해제하고
같은 주소에 새 연결을 만들면, 뒤늦은 단절 관측이 새 연결을 끊긴 것으로
바꾸어 assertion에서 종료했습니다(SIGABRT). 해당 실패를 보존했습니다.

외부 수정은 원본 분류 호출 전에 관측 슬롯을 보존하고, 반환 뒤에는 같은
슬롯만 갱신합니다. 해제된 슬롯을 되살리거나 주소의 새 소유자를 다시 찾지
않습니다. OEM 인자·반환·errno 전달은 그대로 유지합니다. 이 작성 경쟁은
OEM이 동시 free/dispatch를 지원한다는 증거가 아닙니다.

- 기존 LDS 발행 연결 표시와 MODEL/holdout의 버스 경계 초기화를 보존했습니다.
- 외부의 버스 수명 소유자·용량·개수·동일 요청의 수명 역행 검사를 합쳤습니다.
  지연 기록, 시각을 모르는 기록과 새 부팅의 처리도 유지합니다.
- 송신 후보의 12개 버스 경계 회귀, 주소 재사용 회귀와 16개 설치 슬롯의
  원본 값 재검사를 가져왔습니다. 기존 연결 표시·동시 reader 검사는 유지합니다.
- 버스 검사 대상의 누락된 헤더 의존성을 보완했습니다.

## 통합 제품의 원본 LDS 실행

원본 커널 VM에서 세션 파괴·재생성과 AA 세션을 유지한 버스 해제를 실행했습니다.
이는 진단 init과 작성 caller를 사용하는 실행이며 정상 전체 기동 검사가 아닙니다.
205초 관찰이 끝난 뒤 확정된 console 해시와 완료 표식으로 판정했습니다.
helper 124·QEMU 0·timed_out=true 자체를 성공으로 취급하지 않았습니다.

| --- | ---: | ---: | --- |
| 세션 파괴 | 5 | 522 | 지연 응답 1건을 계산에서 제외, 이후 송신 없음 |
| 세션 재생성 | 6 | 540 | 이전 세션 응답 1건 제외, 새 세션의 원본 LOCATION 1건 전달 |

버스 해제 전후 AA lifetime/revision은 1/1로 같았지만 LDS 연결은
`no_live_connection`으로 바뀌고 MODEL을 초기화했습니다. 제외한 센서 입력
3건도 원시 기록과 대조했습니다. journal/request loss와 관측 fault는 0이며,
원본 송신 바이트를 유지했습니다. 별도 원본 상태 callback 두 주기와 실제
daemon 종료도 검사했습니다. daemon 종료 시 원본 close callback은 0회였지만
단절 signal을 관측해 generation이 30에서 32로 증가했습니다.

모든 실제 GPS 응답은 mode/UTC/좌표가 0이고 MODEL 유효 출력도 0입니다.
작성한 직접 GPS seed는 `request_unobserved`로 제외됩니다. holdout은 원본
mode 0으로 이미 중단된 상태이며, 이 실행을 OEM 입력의 학습 보정 초기화나
유효 GPS→단절→복귀의 양성 검사로 세지 않습니다. 일반 분석기는 세 조건에서
inconclusive 20·27·21건, violation 0건을 반환했습니다.

# Project guidance for automated contributors

Read `docs/STATUS_KO.md`, `docs/REVIEW_2026-09-28_KO.md`, and the relevant source before proposing a change. Those current status documents supersede historical design and installation GO statements.

For release work, read `docs/RELEASING_KO.md`. **Release ZIPs must be self-contained:** include the `mp3/`, `js/` shell-entry files and `USB_ENTRY_NOTICE.md` (build without `--shell-only`) so the user can install from the ZIP alone; shell-only ZIPs are only for an explicit owner request. Review/Ready/LGTM, merge and release publication are separate requested actions; do not infer one from another. A request that already authorizes publication does not require duplicate approval. Pin the commit and verify the published installation ZIP; source merging alone is not deployment.

State S means the car stood since the write only as far as the product observed it and only if the departure mark landed (a 110-byte write without fsync under the idle rule and the 5 s rate): a drive without any product start, a non-BETA mode, a boot whose worker did not reach the token swap (stop requested, locale failure, no worker thread), a turntable or mechanical parking system, or a power cut soon after the mark leaves a stale S (a second worker start in the same boot refuses the previous boot's record: not_prev_boot), and the next boot then sends a heading wrong by that drive's rotation (up to 180 deg) until an end condition, also where the stock bearing would have been right. The window may open after the car moved since boot (a garage exit) unless a yaw-chain break happened after the first wheel motion while not standing. Reverse latch: a valid latch saying forward is used; a latch that is not valid (no 0x118 change since the session/bus admission, a message before the admission excluded, or any pipeline reset or latch clear) counts as forward only while no 0x118 information was lost (G3Motion::reverse_unsure zero: no excluded value other than forward, no cleared valid latch, no rejected or reset-discarded REVERSE message, no motion input gap that clears the latch) and only after 20 m of wheel distance since the first wheel motion after the session/bus admission; otherwise the window waits, and an open window ends on a reverse latch or on a latch that became not valid after lost information. Uncounted reverse-information losses: a source-epoch change without a preceding rejection and 0x118 messages before the worker attached. Residual: a car in reverse since before the worker received its first motion message that reverses more than 20 m gets a bearing 180 deg wrong until the first 0x118 change or an end condition. The overlaid send, its bytes (40, 44..47 only), wrapper, return value, errno and every other end condition are those of beta.15. Uncertainty of the garage chain: the stored uncertainty of every record a garage-on boot writes and the propagation of a carried flag-4 record use a 2 % rotation term and a 0.0023 rad/s time term (BETA: 10 %, 0.002 rad/s; the RMS of the 93 parked yaw zeros of the 2026-10-17 export around the integration zero is 0.00224 rad/s, rounded up to 0.0023 by the pre-registered rule; the union of all eight private exports gives 111 stops and 0.0022, and 0.0023 is kept as the larger value); the 60 deg limit applies only to flag-4 records; a carried record without flag 4 keeps the BETA terms and the 30 deg limit; with the marker a flag-4 record is rejected as a format error, as beta.16 decodes it. Store I/O: the parked S record needs 5 s of exact standstill and may be written without fsync while BETA replaces; while BETA replaces an S request needs 30 s since the previous S request (any S request, also a cancelled or failed one and the 60 s fsync rewrite), except the rule F taint rewrite and any S request while the record on disk is an S with heading (its departure mark did not land, so the new S replaces a record that would otherwise be carried stale; bounded by the 5 s request spacing: one S per stop while the mark keeps failing, a cancelled request is retried after 5 s, no fsync); the departure mark is written while the car moves or within the first 5 s of a stop (afterwards only the parked S record is requested), also while BETA replaces (then only with a journal writer lag <= 100 ms). These are the first store writes that run while BETA replaces and while the car moves: the 2026-10-11 H1 'parked write only' invariant no longer holds with the garage carry. The previous-product-boot token write (logs/g3-last-start, temp+rename without fsync) is a further exception to that invariant: it runs at every BETA worker start, with or without the markers, including a mid-drive worker restart in the same boot. No fsync is requested while BETA replaces and an in-flight fsync write is cancelled before its fsync/rename gate; an fsync already executing cannot be interrupted (unchanged residual). The pre-registered rule (a garage write without fsync with lat_ms > 500 or a journal-lag overlap makes the next build default the garage carry off) detects a problem only after a drive. Not vehicle-validated; with the 0.0023 rad/s term the digest model of the only real garage exit (E-Mart, 2026-10-17) closes the window at the exit (unc_grew; at 0.0022 rad/s it would stay below 60 deg for four overlaid sends of 198 m mode-2 fixes and end on trust), and the home spiral garage is expected not to benefit.

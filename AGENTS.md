# Project guidance for automated contributors

Read `docs/STATUS_KO.md`, `docs/REVIEW_2026-09-28_KO.md`, and the relevant source before proposing a change. Those current status documents supersede historical design and installation GO statements.

For release work, read `docs/RELEASING_KO.md`. Review/Ready/LGTM, merge and release publication are separate requested actions; do not infer one from another. A request that already authorizes publication does not require duplicate approval. Pin the commit and verify the published installation ZIP; source merging alone is not deployment.

- Target: first-generation Mazda Connect NA 74.00.324A. Do not generalize offsets, hashes or ABI to another firmware.
- Published v0.3.10-shadow.2 adds guarded startup and config-binding diagnostics to the six-binary LDS observation product. Its pinned ZIP was published and re-downloaded; see validation/RELEASE_V0310_SHADOW2_2026-10-02.md. It remains a trial candidate without vehicle startup, physical sensor timing/quality, or phone acceptance evidence.
- v0.3.9-shadow.2 fixed the vehicle-observed menu3 rejection of the normal /proc/mounts symlink; its successful vehicle archive contains no trace/collector journals. The user confirmed installation, an ignition OFF/ON cycle, wireless AA dongle + S25 and an underground/surface drive. Do not infer a completed CMU Linux reboot from that ignition cycle or infer historical OFF from the removed configuration. Later private diagnostics showed an armed guard but no consumed/last-boot marker or JSONL, so startup/storage failure remains unresolved. v0.3.9-shadow.3 adds an explicit parked reboot menu and expanded USB recovery, but has not run on the vehicle. See validation/EMPTY_CAPTURE_2026-10-02.md and validation/STARTUP_RECOVERY_2026-10-02.md. /tmp/mnt/data_persist is the original relfs mount target, not necessarily tmpfs. Do not reinstall/rearm or request another drive to retrieve remaining diagnostic evidence. The package remains a SHADOW trial candidate with ASSIST disabled. Vehicle startup/recovery, physical sensors, same-running-SM retries and phone acceptance remain unverified. Read docs/STATUS_KO.md, docs/FIELD_TRIAL_KO.md and docs/V1_READINESS_KO.md; preserve historical release evidence without upgrading its scope.
- Keep live ASSIST disabled until documented sensor, provenance, recovery and phone/app gates are satisfied. MODEL-domain SHADOW calculation consumes an existing VBS callback tap but is not vehicle-validated; receipt time and model assumptions must never become qualified ASSIST. Read docs/LIVE_SHADOW_2026-09-29_KO.md and validation/LIVE_SHADOW_2026-09-29.md.
- For stationary calibration/GPS holdout work, read `docs/SHADOW_CALIBRATION_KO.md`. Keep learned zeros MODEL-only, apply only at new anchors, and keep held-out GPS fields out of prediction. GPS differences are not ground-truth accuracy.
- Preserve OEM forwarding contracts, registers, errno, preload coexistence and installer token ownership. A proposed DROP mode needs an explicit different send/return contract.
- Keep observed receipt time separate from producer measurement time. Never promote a successful SMDB poll into a fresh/VALID sample.
- No driving-time CMU interaction. Observation must run automatically; configuration and collection occur while parked.
- The user's keyboard cannot enter Shift characters. Minimize typed commands: use the USB `trial` numeric menu and lowercase paths; do not require underscores, uppercase letters, wildcards or shell pipelines in the normal vehicle procedure.
- The vehicle has one usable USB port and the infotainment does not recognize a hub for simultaneous wired AA and shell access. Prepare/install while parked, switch to AA for automatic capture, then park and switch back to shell/USB for export. Menu 2 does not change CMU trial state or start capture; it saves a status report to USB. After the empty vehicle trial, use it before moving to verify a new CMU Linux boot, guard selection and current collector evidence. Distinguish current disconnected/changed-boot status from retained trial evidence; do not require a live AA session during shell use.
- The user authorized one vehicle installation/test opportunity on 2026-10-01, superseding the earlier firmware-only restriction for that attempt. It was used by the v0.3.9-shadow.1 installation/drive and follow-up export, which contained no startup or sensor journals. Do not treat that historical authorization as permission for another visit or phone/dongle bench test. Continue feasible implementation and firmware/offline verification first. A separately arranged combined trial would check parked startup/recovery, automatic OEM observation, raw sensor/SHADOW calculation and GPS holdout capture. Verify storage headroom and distinguish input capture, calculation attempts, usable results and explicit failure reasons; installation success alone is insufficient. Preserve raw inputs when calculation is disabled, keep faulty sessions inconclusive, and do not weaken live ASSIST qualification or claim v1.0 complete. Any additional vehicle request must identify an unanswered question that existing evidence cannot resolve.
- Do not publish OEM binaries/maps, disassembly dumps, credentials, personal share links or unredacted vehicle logs. Do not weaken firmware guards to make tests pass.
- Changes belong in focused commits/PRs with problem, changed behavior, test evidence and remaining limitations. Report skipped tests explicitly.
- Use `make test` for host checks when dependencies are available. Exact-ARM checks use the pinned toolchain; see `docs/toolchain.md`. QEMU/synthetic success is not vehicle validation.
- Preserve the imported baseline provenance. Do not edit historical test counts into new test results. New verification belongs in a dated record.
- Do not claim Claude or a physical vehicle was used without actual execution evidence. Independent agent review is useful but does not replace target tests.

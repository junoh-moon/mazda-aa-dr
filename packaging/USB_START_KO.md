# USB 설치·CMU 재부팅·회수

대상은 **2019 MX-5 ND2 6MT, 1세대 Mazda Connect NA 74.00.324A**입니다.
메뉴 첫 줄이 `This USB installs mode BETA`이면 이 안내 대신 BETA 현장 절차
(저장소 `docs/FIELD_PROCEDURE_BETA_KO.md`)를 따르십시오. BETA는 SHADOW 기록에 더해
순정이 GPS 없음(mode 0)을 보내는 동안에만 위치를 바꿔 보내며, 자격 ASSIST는 계속 비활성입니다.
**BETA는 상시 실행 제품입니다(2026-10-06).** `1`로 한 번 설치하면 매 부팅 스스로 켜지고,
BETA 부팅 두 번이 연달아 CMU 리셋으로 끝나면 자동으로 순정만 실행합니다(`2`에 `PERSIST tripped`).
아래 표의 "다음 한 번의 부팅"은 SHADOW·OBSERVE 묶음에만 해당합니다.
**이 묶음은 SHADOW 시험 후보이며 live ASSIST는 비활성입니다.** 실제 차량의
기동·센서·물리 복구와 폰/지도 수용은 미검증입니다. 설치 파일은 해당
[릴리즈](https://github.com/junoh-moon/mazda-aa-dr/releases)에 발행된 ZIP과
체크섬으로 확인하십시오. 로컬 빌드나 이 문서만으로 차량 시험 승인을 뜻하지 않습니다.
이전 `v0.3.10-shadow.1`·`.2` ZIP은 LDS 반복 종료 때문에 사용 중단했습니다.
**아래는 메뉴 `5`가 포함된 이 설치 묶음의 절차입니다.** v0.3.9-shadow.2와
그 이전 묶음에는 메뉴 `5`, 새 부팅 대조, 설치 폴더 전체의 확대 회수가 없습니다.
새 시험이 정해졌을 때 사용할 안내이며 지금 새 차량 방문이나 주행을 요청하지 않습니다.
이미 사용한 첫 시험에서는 회수 archive에 trace·collector 기록이 없었습니다.
[분석 기록](https://github.com/junoh-moon/mazda-aa-dr/blob/1cb4f74c2733bd77538b934b783e076b583c1c11/validation/FIELD_V039_EMPTY_CAPTURE_2026-10-02.md)을 보존합니다.

차량 USB 포트는 하나이며 허브를 사용할 수 없습니다. 설치·회수용 USB와
무선 AA 동글을 주차 중에 번갈아 연결하십시오. AA 사용 중 셸은 요구하지 않습니다.

먼저 전원 상태를 구분하십시오. 엔진이 꺼진 상태에서 페달을 밟지 않고 시동 버튼을 누르면
OFF → ACC → ON 순서로 바뀌며, 이 조작만으로 엔진이 켜진 것은 아닙니다.

| 상태 | 엔진 | 시동 버튼의 주황 표시등 | 이 설치 절차 |
| --- | --- | --- | --- |
| ACC | 꺼짐 | 켜짐 | 사용하지 않음 |
| ON, 엔진 꺼짐 | 꺼짐 | 켜짐 | 사용하지 않음 |
| ON, 실제 엔진 가동 | 가동 | 꺼짐 | 타코미터가 0보다 높은지 확인하고 유지 |

ON과 표시등의 의미는 [Mazda 2019 MX-5 공식 설명서](https://www.mazdausa.com/static/manuals/2019/mx5/contents/05010101.html)를
따릅니다. 실제 엔진 가동을 유지하는 것은 작업 중 전원 상태를 일정하게 두기 위한
이 프로젝트의 절차이며, Mazda가 이 패키지를 승인했다는 뜻은 아닙니다.

1. ZIP을 푼 **내용물 전체**를 깨끗한 FAT32 USB 최상위에 복사하십시오.
   USB를 열었을 때 `trial`, `install.sh`, `mp3/`, `js/`가 바로 보여야 합니다.
2. 배기가스가 쌓이지 않는 환기되는 주차 장소에서 **주차브레이크를 채우고
   6MT 기어를 중립 N에 두십시오. 브레이크와 클러치를 끝까지 밟고 시동 버튼을
   눌러 엔진을 켜며, 시동이 완전히 걸릴 때까지 페달을 밟고 계십시오.** 타코미터가
   0보다 높은지 확인하고 **설치·CMU 재부팅·기동 확인까지 엔진 가동을 유지하십시오.**
   작업 중에는 중립·주차브레이크·공회전 상태를 유지하십시오.
   [공식 엔진 시동 설명](https://www.mazdausa.com/static/manuals/2019/mx5/contents/05010200.html)을 참고하십시오.
3. USB를 연결하고 기존에 사용한 방법으로 키보드 입력 가능한 셸을 여십시오.
   Entertainment → USB에서 포함된 곡을 재생하고 약 15초 기다리십시오.
   다른 USB가 먼저 연결되어 있으면 다음 곡도 재생하십시오.
4. 셸에서 다음 한 줄로 숫자 메뉴를 여십시오. 소문자·숫자·공백·슬래시만
   사용하므로 Shift가 필요하지 않습니다.

   ```sh
   sh /tmp/mnt/sda1/trial
   ```

   메뉴 `1`·`2`는 같은 메뉴로 돌아오고, `3`·`4`·`5`는 실행 뒤 메뉴가
   끝납니다. 다음 번호가 필요하면 같은 한 줄로 메뉴를 다시 여십시오.
   새로 검증·발행한 묶음의 설치기를 이미 직접 실행해 설치에 성공했다면
   `1`을 반복하지 말고 같은 메뉴의 `5`부터 진행하십시오. 직접 설치만으로
   CMU가 재부팅되지는 않습니다.

   USB가 `sdb1`, `sdc1`, `sdd1`로 잡히면 경로의 해당 글자만 바꾸십시오.
   별도 `sha256sum`, `chmod`, `chown`, `mount` 명령은 필요하지 않습니다.
5. **최초 설치인 경우에만 `1`과 Enter**를 누르십시오. 설치 오류로 메뉴가
   종료되면 `5`로 진행하지 말고 오류 출력을 보존하십시오.
   `Installation finished` 안내가 나오면 같은 메뉴에서 **`5`와 Enter**를
   누르십시오. USB에 `reboot-request.txt`를
   저장·동기화하고 필요한 USB 읽기 전용 복원을 마친 뒤 순정 `/sbin/reboot`를
   옵션 없이 요청합니다. **시동 버튼을 누르지 말고 엔진과 USB 연결을 유지하십시오.**
   차량 시동 OFF/ON으로 이 단계를 대신하지 마십시오.
6. CMU 화면이 돌아오면 같은 USB의 곡으로 셸을 다시 열고, 위 한 줄로
   메뉴에 들어가 **`2`와 Enter**를 누르십시오. 재부팅 요청의 성공이나
   화면 복귀만으로 새 부팅과 수집 시작이 확인된 것은 아닙니다.

이전 시험 자료의 회수만 필요하다면 설치·재부팅 단계 대신 **`3`과 Enter**를
사용하십시오. 이미 `4`로 제거했어도 남은 자료를 회수하며, 재설치·재무장·재주행은
필요하지 않습니다. 기존 USB 결과는 먼저 PC에 보관하십시오.
SHADOW는 위치 계산을 로그로만 기록하며 폰에 자체 위치를 전송하지 않습니다.

설치기는 기존 AA 터치·km/L 패치를 다시 설치하거나 제거하지 않도록 설계됐습니다.
이 묶음의 MP3/JS는 셸 진입에 사용하며, 기존 기능은 주차 중 실제로 확인하십시오.
설치 중에는 USB를 빼지 마십시오.

메뉴 `2`는 상세 출력 맨 아래에 짧은 `---- GO / NO-GO ----` 블록을 출력합니다. 아래 일곱 근거와 세 서비스(`AAPA`, `LDS`, `VBS`)의 preload 적재를 줄마다
`ok`, `NO`, `wait`로 요약하고 마지막 줄이 `GO`, `NO-GO`, `WAIT 60 s, then run 2 again` 중 하나입니다. 같은 블록이 `startup-result.txt` 끝에도
저장됩니다. 작은 화면에서는 이 블록으로 먼저 판단하고 상세 값은 저장된 파일에서 보십시오.

이 묶음으로 별도로 정한 시험을 진행할 때, 이동 전 `2`로 다음 일곱 근거를 각각 확인하십시오.

- `reboot_check=new_boot_observed`: USB 요청 기록과 현재 부팅 ID가 다릅니다.
- `startup_state=guard_committed_after_new_boot`: 무장한 Linux 부팅과 현재
  guard 표식 확정 부팅이 다릅니다.
- `one_boot=consumed_this_boot`: 이번 부팅에서 일회성 예약을 소비했습니다.
- `config_mode=SHADOW`: 현재 설정 파일의 mode가 SHADOW입니다.
- `runtime_disable_next_start=absent`: 런타임의 다음 시작 차단 표식이 없습니다.
- `retained_bytes`가 0보다 큽니다.
- `collector_poll_recent=observed`: 현재 collector의 최근 poll 기록이 있습니다.

`startup_state=guard_committed_after_new_boot`은 v3 형식의 guard 소비 표식에서만
출력되며 `guard_config_binding=matched`도 필요합니다. 이 값은 가드가 확정할
때 결합한 설정 파일의 해시가 현재 파일과 같다는 뜻입니다. 이 표식만으로
SM이 시험 경로를 받아 사용했거나 AA 런타임이 시작됐다고 증명하지 않습니다.
이전 v2 표식은
회수 자료로 보존하지만 새 시험 기동 근거가 아닙니다.
부팅 표식이 `invalid`이면 설치·재무장을 반복하지 마십시오. 손상 원본과 로그를
회수한 뒤 PC에서 원인을 조사해야 하며, 메뉴 `4`만으로 손상 표식이 복구되지는 않습니다.
AA 동글을 아직 연결하지 않아도 collector는 기동·기록할 수 있습니다.
정차 중 센서가 아직 없거나 AA가 분리돼 전체 상태의 `status_exit`가 1일 수
있으므로, 모든 센서나 `status_exit=0`을 이 단계의 조건으로 요구하지 않습니다.
화면 복귀 직후 `startup_state=new_linux_boot_arm_unconsumed`이거나 collector
poll만 아직 없으면 주차 상태에서 60초 기다린 뒤 `2`를 한 번 더 확인하십시오.
그래도 일곱 근거 중 하나라도 없으면 이동하지 말고 `3`으로 가능한 자료를 회수한 뒤
메뉴가 종료되면 같은 한 줄을 다시 입력하여 `4`로 예약을 해제하십시오.
가드 부팅 표식이 `invalid`라면 설치·재무장이나 수동 표식 수정을 시도하지 말고
같은 회수·제거 순서로 원본과 진단을 보존하십시오.
이 확인은 수집 시작 명령이 아닙니다.
근거가 확인되면 **`0`으로 메뉴를 종료한 뒤 USB를 빼고 무선 AA 동글을 연결하십시오.**
기존 AA·터치 동작을 주차 중 확인하고, 이 전환 중 시동을 껐다 켜거나 CMU를
다시 재부팅하지 마십시오. AA와 USB를 동시에 연결하려고 하지 마십시오.
이 근거는 guard 선택·설정·collector 일부 상태의 확인입니다. VBS tap 로딩이나
원시 센서 수신, 계산 성공, 주행 승인을 뜻하지 않습니다.

| 번호 | 동작 |
| --- | --- |
| 1 | 최초 설치, 다음 한 번의 부팅 예약(BETA: 매 부팅 실행 설치·차단 해제) |
| 2 | 현재 상태와 보존 기록 요약 확인, 모드 변경 없음. 이동 전 기동 확인에 사용 |
| 3 | 수집 종료 요청과 전체 설치 폴더·기동 진단을 현재 USB로 회수 |
| 4 | 제거(BETA 상시 실행 포함), 기존 수집 로그 보존 |
| 5 | USB에 요청 기록을 남기고 순정 명령으로 CMU 재부팅 요청 |
| 0 | 메뉴 종료 |

빈 Enter나 입력 종료로 자동 설치하지 않습니다. 시험 부팅 후 다시 `1`을
선택할 필요는 없습니다. 수집·계산은 자동으로 실행됩니다.

`2` 또는 회수 시 출력되는 최근 상태는 **조회하는 현재 부팅**의 진단입니다.
AA 분리나 재부팅 뒤의 `unavailable`은 이전 시험에서 한 번도 기록·계산하지
않았다는 뜻이 아닙니다. 수락된 원시 수신, OEM 위치, 계산 시도를 각각 표시합니다.
`calculation_attempt_recent`은 주 계산기의 실제 호출 근거이고,
`events_queued_total`은 대기열 등록 수입니다. 둘 다 유효 해의 개수가 아닙니다.
`model_solution=not_observed`이면 현재 유효 계산 결과가 확인되지 않은 상태입니다.
정차 중 기준점을 기다릴 수 있으므로 함께 표시된 `pipeline`과
`gps_anchor_gate`를 확인하십시오. 기동 확인 성공이 시험 완료를 뜻하지는 않습니다.
`last_pipeline_reset_this_boot`은 이후 입력이 정상이어도 보존한 최근 계산 초기화 사유입니다.
이 사유와 원시 입력은 회수한 로그에서 함께 분석합니다.
상태 명령의 성공은 원시 수집 근거를 뜻합니다. 계산·위치가 `unavailable`이면
그 사유도 보존하며, 거부된 입력은 수락된 수신과 별도로 표시합니다.
`retained_runtime_last_boot`와 `retained_model_diagnostic_records`는 마지막
보존 부팅에 연결된 기록 요약입니다. 행 수는 계산 호출 수·정확도·시험 성공을
뜻하지 않습니다. boot 표식이 회전으로 사라졌다면 부팅을 추정하지 않습니다.

설치기는 필요한 저장 공간을 먼저 확인합니다. 실행 중에도 공간이 부족해지면
기록을 중단하고 사유를 남기며, 기존 로그를 지워서 계속 수집하지 않습니다.
로그는 최대 128MiB(AA 40MiB×3, collector 4MiB×2)이며 설치 파일·설정 백업은 별도입니다. 8MiB 여유 정책은
다른 프로그램의 동시 쓰기나 파일시스템 고장까지 방지하는 보장은 아닙니다.

운전 중에는 명령을 입력하거나 USB를 바꾸지 마십시오. 도착 후 주차 상태에서
AA를 분리하고 같은 설치 USB를 연결하십시오. 곡을 재생하여 셸로 돌아온 뒤
위 한 줄로 메뉴를 열고 **바로 `3`과 Enter**로 종료·회수하십시오. `2`를 먼저
누를 필요는 없습니다. 실행한 USB에 자동 저장하므로 목적지 경로를 입력하지
않습니다. 저장 중에는 USB를 연결해 두십시오.

가능하면 같은 부팅에서 회수하십시오. 셸 복귀에 정상 재부팅이 필요하면
재부팅한 뒤 같은 USB에서 `3`을 실행하십시오. 다시 `1`을 누르거나 시험을
재무장하지 마십시오. 현재 부팅에서 `guard/consumed`가 확인된 경우에만
일회성 예약이 소비되었다고 판단하십시오. 그렇지 않으면 예약이 남아 있을 수
있으므로 주차 중 메뉴 `4`로 제거하십시오. 이전 부팅의 남아 있는 로그도 함께
회수합니다.
재부팅 전 마지막 행의 저장이나 회전으로 사라진 자료까지 보장하지는 않습니다.

종료 확인이 실패해도 남은 파일의 회수를 시도합니다. USB의 `trial-result.txt`에
종료 전 상태와 `status_exit`, `finish_exit`, `export_exit`를 따로 남깁니다.
`finish_exit`는 **현재 부팅**의 종료 확인이고 `export_exit`는 **보존된 모든
부팅 자료**의 회수 결과입니다. 재부팅 후에는 이전 시험의 완료 표식이 있어도
`finish_exit`가 0이 아닐 수 있습니다. 이를 현재 부팅의 정상 종료나 이전 시험의
실패로 바꾸어 해석하지 마십시오. `export_exit=0`이면 확보 가능한 파일의 회수는
성공한 것입니다. 완료되지 않은 끝부분·누락·계산 결과는 PC에서 별도로 분석합니다.
`export_exit`가 0이 아니면 회수 성공으로 간주하지 마십시오.
이 작은 결과 파일은 다음 회수 때 교체하며 CMU에 누적하지 않습니다.
새 archive에는 `/data_persist/mx5-aa-dr` 전체(로그·guard 표식·설정·백업·설치 파일),
실제 autostart와 두 SM 설정, 선택된 시험 설정 사본, 용량을 제한한 현재 부팅의
`/proc`·명령 출력·재부팅 요청 기록을 함께 담습니다. 현재 부팅의 진단은 이전
주행 시점의 상태를 증명하지 않습니다. 진단 일부가 없거나 잘려

함께 보존하십시오. 로그 archive, `.sha256`, `trial-result.txt`,
`startup-result.txt`, `reboot-request.txt` 등 USB 결과를 함께 가져오십시오.
PC에서 archive의 `.sha256`을 확인하십시오. 회수 후 차량 원본은
남으며 센서 로그는 위 상한에서 관리됩니다. archive와 진단 임시 파일은 USB에
만들며 차량 내부에 누적하지 않습니다. 원본 파일과 차량 정보가 포함되므로 비공개로 보관하십시오.

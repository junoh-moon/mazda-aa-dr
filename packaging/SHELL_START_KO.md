# 승인된 셸에서 설치·CMU 재부팅·회수

이 안내는 **이미 승인된 OEM·정비 셸에 접근할 수 있고, CMU를 재부팅한
뒤에도 그 셸에 다시 접속할 수 있는 사용자**를 위한 것입니다. 이 설치
묶음은 셸 접근 수단을 제공하지 않습니다. 별도로 정한 시험에 적용하는
절차이며, 지금 새 차량 방문이나 주행을 요청하지 않습니다.

대상은 **2019 MX-5 ND2 6MT / 1세대 Mazda Connect NA 74.00.324A**입니다.
**이번 공개 shell-only ZIP의 기본 모드는 SHADOW이며 live ASSIST는
비활성입니다.** SHADOW 계산은 로그에 남기고 자체 계산 위치로 원본 AA
위치를 대체하지 않습니다. 실제 차량 자동 기동·센서·물리 복구·폰/지도
수용과 v1.0의 관성항법 적용은 아직 검증·완료되지 않았습니다.

직접 만든 shell-only 묶음은 OBSERVE를 선택할 수도 있습니다. 실제 설치
기본값은 동봉된 `bundle-default-mode`이며, 설치 뒤 메뉴 `2`의
`config_mode`로 현재 설정을 확인합니다. **아래 절차와 기동 확인값은
SHADOW로 발행된 이번 ZIP 기준**입니다.

## 준비와 전원 상태

PC에서 설치 ZIP의 SHA-256을 함께 발행된 체크섬과 확인한 뒤, **내용물
전체**를 깨끗한 FAT32 USB 최상위에 복사하십시오. `trial`, `install.sh`,
`INSTALL_KO.md`가 USB를 열었을 때 바로 보여야 합니다. GitHub의 자동
`Source code (zip)`은 설치 묶음이 아닙니다. 기존 USB 결과는 먼저 PC에
보관하십시오.

차량 USB 포트는 하나이며 허브를 사용할 수 없습니다. 설치·회수용 USB와
무선 AA 동글을 **주차 중에 번갈아 연결**하십시오. AA를 사용하는 동안
셸 접속이나 USB 동시 연결을 요구하지 않습니다.

ACC와 엔진이 꺼진 ON은 실제 엔진 가동과 다릅니다.

| 전원 상태 | 엔진 | 시동 버튼의 주황 표시등 | 이 설치 절차 |
| --- | --- | --- | --- |
| ACC | 꺼짐 | 켜짐 | 사용하지 않음 |
| ON, 엔진 꺼짐 | 꺼짐 | 켜짐 | 사용하지 않음 |
| ON, 실제 엔진 가동 | 가동 | 꺼짐 | 타코미터가 0보다 높은지 확인하고 유지 |

표시등과 전원 상태는 [Mazda 2019 MX-5 공식 설명서](https://www.mazdausa.com/static/manuals/2019/mx5/contents/05010101.html)를
따릅니다. 작업 동안 실제 엔진 가동을 유지하는 것은 전원을 일정하게
두기 위한 이 프로젝트의 절차이며, Mazda의 패키지 승인을 뜻하지 않습니다.

배기가스가 쌓이지 않는 환기되는 장소에 주차하고 주차브레이크를 채우십시오.
**6MT 기어를 중립 N에 두고, 브레이크와 클러치를 끝까지 밟은 상태에서
시동 버튼을 눌러 엔진을 켜십시오. 시동이 완전히 걸릴 때까지 페달을
밟고 계십시오.** 타코미터가 0보다 높은지 확인하고 설치·CMU 재부팅·기동
확인까지 중립·주차브레이크·공회전 상태를 유지하십시오.
[공식 엔진 시동 설명](https://www.mazdausa.com/static/manuals/2019/mx5/contents/05010200.html)을 참고하십시오.

## 설치 `1` → CMU 재부팅 `5` → 확인 `2`

설치 USB를 연결한 뒤 준비된 승인 셸에서 다음 한 줄을 입력하십시오.
소문자·숫자·공백·슬래시만 사용하므로 Shift가 필요하지 않습니다.

```sh
sh /tmp/mnt/sda1/trial
```

USB가 `sdb1`, `sdc1`, `sdd1`로 잡히면 경로의 해당 글자만 바꾸십시오.
차량에서 별도 해시·권한·마운트 명령을 입력할 필요는 없습니다. 메뉴
`1`·`2`는 같은 메뉴로 돌아오고, `3`·`4`·`5`는 실행 뒤 메뉴가 끝납니다.
다음 번호가 필요하면 같은 한 줄로 다시 여십시오.

1. **최초 설치인 경우에만 `1`과 Enter**를 누르십시오. 설치 오류로
   메뉴가 종료되면 `5`로 진행하지 말고 오류 출력을 보존하십시오.
   설치기를 이미 직접 실행하여 성공했다면 `1`을 반복하지 마십시오.
2. `Installation finished` 안내 뒤 같은 메뉴에서 **`5`와 Enter**를
   누르십시오. USB에 요청 기록을 저장·동기화한 뒤 순정 명령으로 CMU
   재부팅을 요청합니다. **시동 버튼을 누르지 말고 엔진과 USB 연결을
   유지하십시오. 차량 시동 OFF/ON으로 이 단계를 대신하지 마십시오.**
3. CMU 화면이 돌아오면 준비된 승인 셸에 다시 접속하십시오. 같은 한 줄로
   메뉴를 열어 **`2`와 Enter**를 누르십시오. 재부팅 요청의 성공이나
   화면 복귀만으로 새 Linux 부팅과 수집 시작이 확인된 것은 아닙니다.

메뉴 `2`에서 다음 일곱 근거를 각각 확인하십시오. 아래 진단값은 읽어서
확인하는 값이며 셸에 입력하는 명령이 아닙니다.

- `reboot_check=new_boot_observed`
- `startup_state=guard_committed_after_new_boot`
- `one_boot=consumed_this_boot`
- `config_mode=SHADOW`
- `runtime_disable_next_start=absent`
- `retained_bytes`가 0보다 큼
- `collector_poll_recent=observed`

양성 `startup_state`는 guard가 소비한 설정과 현재 설정의 해시가 일치한
`guard_config_binding=matched`일 때만 출력됩니다. 이 표식만으로 원본
서비스 전체의 기동이나 AA 런타임 실행까지 증명하지 않습니다.

AA 동글이 없어도 collector는 기동할 수 있습니다. 정차·AA 분리 상태에서
전체 `status_exit`가 1일 수 있으므로 모든 센서 수신이나 `status_exit=0`을
이 단계의 조건으로 요구하지 않습니다. 화면 복귀 직후
`startup_state=new_linux_boot_arm_unconsumed`이거나 collector poll만 아직
없으면 주차 상태에서 60초 기다린 뒤 `2`를 한 번 더 확인하십시오.

**그래도 일곱 근거 중 하나라도 없으면 시험 주행을 시작하지 마십시오.**
`3`으로 가능한 자료를 회수하고, 메뉴가 끝나면 같은 한 줄로 다시 열어
`4`로 예약을 해제하십시오. 부팅 표식이 `invalid`이면 설치·재무장이나
수동 표식 수정을 반복하지 말고 원본과 진단을 보존하십시오.

근거가 확인되면 **`0`으로 메뉴를 종료한 뒤 설치 USB를 빼고 무선 AA
동글을 연결하십시오.** 기존 AA·터치 동작을 주차 중 확인하십시오. 전환
중에 시동을 껐다 켜거나 CMU를 다시 재부팅하지 마십시오.

메뉴 `2`는 조회·보고만 하며 수집을 시작하거나 모드를 바꾸지 않습니다.
관측과 SHADOW 계산은 선택된 부팅에 자동으로 실행되도록 구성됩니다.
기동 확인은 원시 센서 수신·계산 성공·물리 자격이나 시험 승인을 뜻하지
않습니다. 정차 중 기준점을 기다릴 수 있으며, 계산이 불가능한 이유도
회수 자료와 함께 확인하십시오.

## 주차 후 `3`으로 회수

**운전 중에는 명령을 입력하거나 USB를 바꾸지 마십시오.** 별도로 정한
시험이 끝나면 주차한 뒤 AA 동글을 분리하고 같은 설치 USB를 연결하십시오.
준비된 승인 셸에서 위 한 줄로 메뉴를 열어 **바로 `3`과 Enter**를
누르십시오. `2`를 먼저 누르거나 목적지 경로를 입력할 필요는 없습니다.
저장이 끝날 때까지 USB를 연결해 두십시오.

기존 자료의 회수만 필요한 경우에도 바로 `3`을 사용하십시오. 이미
제거했어도 남은 파일을 회수하며 재설치·재무장·재주행은 필요하지 않습니다.
가능하면 같은 부팅에서 회수하십시오. 승인 셸로 돌아오기 위해 정상 CMU
재부팅이 필요했다면 이전 부팅의 남은 자료도 회수하지만, 다시 `1`을
누르지는 마십시오.

종료 확인이 실패해도 남은 파일의 회수를 시도합니다. USB의
`trial-result.txt`에서 `status_exit`, `finish_exit`, `export_exit`를
구분하십시오. `finish_exit`는 **현재 부팅**의 종료 확인이며,
`export_exit=0`은 **확보 가능한 보존 자료**의 회수 성공입니다. 빈 자료의
회수 성공을 정상 수집·계산 성공으로 해석하지 마십시오. `export_exit`가
0이 아니면 회수 성공으로 간주하지 마십시오.

회수 archive에는 전체 설치 폴더의 로그·설정·guard 표식·백업과 실제
autostart·SM 설정, 크기를 제한한 현재 부팅 진단을 함께 담습니다.
현재 부팅의 진단으로 이전 시험의 상태를 추정하지 마십시오. 진단 일부가
없거나 잘린 경우도 기록하며, 이미 회전으로 사라진 자료나 재부팅 직전의
마지막 기록까지 복원하지는 못합니다.

archive와 `.sha256`, `trial-result.txt`, `startup-result.txt`,
`reboot-request.txt`를 함께 PC로 가져오십시오. tar 실패로 남은 `.partial`과
USB 진단 폴더도 보존하십시오. PC에서 archive의 체크섬을 확인하고,
원본 파일과 차량 정보가 포함된 결과는 비공개로 보관하십시오.

설치기는 저장 공간을 먼저 확인합니다. 실행 중 공간이 부족하면 기록을
중단하고 사유를 남기며 기존 로그를 지워 계속 수집하지 않습니다. 로그는
최대 26MiB이고 설치 파일·설정 백업은 별도입니다. archive와 진단 임시
파일은 USB에 만들며 차량에는 원래 로그를 보존합니다.

## 기본 설정 복귀 `4` → `5` → `2`

회수 뒤에도 주차 상태에서 작업하십시오. `3`이 끝나면 같은 한 줄로
메뉴를 다시 열어 **`4`와 Enter**로 제거하십시오. 기존 수집 로그는
보존합니다. `4`가 끝나면 다시 메뉴를 열어 **`5`**로 새 CMU Linux 부팅을
요청하십시오. 화면이 돌아오면 준비된 승인 셸로 다시 접속해 같은 한 줄
뒤 **`2`**에서 다음 값을 확인하십시오.

- `reboot_check=new_boot_observed`
- `config_mode=OFF`
- `guard_arm=absent`

이 확인까지 엔진과 USB 연결을 유지하십시오. `5`·`2`는 USB의 현재
요청·상태 파일을 바꾸지만 앞선 `3`은 당시의 해당 파일도 회수합니다.
`3`으로 수집을 끝낸 것만으로 이미 실행 중인 프로세스가 기본 설정으로
돌아왔다고 판단하지 마십시오. 제거 실패나 arm 잔존 시 복귀를 완료했다고
기록하지 마십시오. 기존 AA·터치 동작은 주차 중 확인하십시오.
